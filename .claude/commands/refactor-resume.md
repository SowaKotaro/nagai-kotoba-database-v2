大規模リファクタリングを、台帳に従って再開してください。
**進捗はメモリや会話の記憶ではなく、`docs/refactoring/LEDGER.md` だけを根拠にする**こと。

- 引数（いまの effort）: $ARGUMENTS （空なら `high` とみなす）

## 1. 読む

1. `docs/refactoring/STRATEGY.md`（進め方の決まり）を読む。
2. `docs/refactoring/LEDGER.md`（台帳）を読む。§1「現在地」が出発点になる。
3. 計画書 `docs/refactoring/ai-legibility-plan.md` は、いまの単位に関わる節だけを読む。全部を読み直さない。

## 2. 安全確認

1. `git branch --show-current` を確かめる。
   - `main` にいたら、`feature/refactoring` があれば `git switch` し、無ければ最新の main から切る。
   - **main にはコミットしない。push・PR・merge はオーナーの指示が無い限りしない**
     （main への push はそのまま本番デプロイになる）。
2. `git status` を確かめる。
   - 未コミットの変更があれば、前のセッションが単位の途中で止まったということ。
     差分を読んで台帳のどの単位のものかを特定し、オーナーに報告して「続けて仕上げる / 捨ててやり直す」を確認する。
     **確認なしに捨てない。**
3. 台帳 §7 の最終行と `git log --oneline -5` を見比べて、台帳とコミットが食い違っていないかを確かめる。
   食い違っていたら、作業に入らずにオーナーへ報告する。

## 3. 次の単位を決める

台帳 §1「次の一手」と、その段階の表で最初の `未着手` の行を取る。次の場合は、作業に入らずに止まる。

- **オーナーの判断が要る**（段階 1 の目的の確定・P-04 の承認・`保留` の行）:
  判断に要る材料を短くまとめて質問し、止まる。回答をもらったら台帳に書いてコミットし、先へ進む。
- **推奨 effort が max で、いまの effort が high**: 「この単位は max 推奨です。`/effort max` にしてから
  `/refactor-resume max` を打ってください」と伝えて止まる。
  逆に、いまが max で推奨が high の単位に来たら、続けてよいが、high に戻すと消費が減ることを一言添える。

## 4. 1 単位を進める

1. 台帳の手順と計画書の該当項目に従って作業する。**単位の範囲の外には手を広げない。**
   範囲外で見つけたものは、台帳 §6「受付箱」に書く。
2. 指摘や確認結果には `path:line`・シンボル名・いまの HEAD のハッシュを添える。
3. サブエージェントを使うときは、同時に 2〜3 体までにする。各体に書き込んでよいファイルを 1 つだけ渡し、
   台帳と計画書には触らせない。
4. 検証する。
   - アプリ・テスト・設定を変えたら、計画書 §0.3 の合格判定をすべて通す
     （システムテストの WSL での実行方法はメモリ `system-tests-wsl-chrome` を参照する）。
   - `docs/refactoring/` だけを変えたなら、合格判定は省いてよい。
5. 台帳を更新する。
   - 該当行の状態を `済`（または `見送り` / `保留` と理由）にし、コミット欄は「このコミット」と書く。
   - §1「現在地」を、次の単位に合わせて書き換える。
6. 成果物と台帳を**同じコミット**に入れる。`git add` は変えたパスを明示する。
   - メッセージは日本語で書き、接頭辞は `docs:` / `test:` / `refactor:` / `chore:` を使う。
   - 末尾に `Co-Authored-By` の行を付ける。
   - 前のコミットのコミット欄に「このコミット」が残っていたら、ハッシュに直して、このコミットに含める。

## 5. 続けるか止まるか

1 単位をコミットしたら、§3 に戻って次の単位を取る。次のどれかに当たったら止まる。

- オーナーの判断が要る単位に来た。
- 推奨 effort が、いまの effort より高い単位に来た。
- 段階の終わりの条件を満たした。段階の切れ目では、受付箱の整理をオーナーに相談する。
- 合格判定がどうしても通らない。原因を台帳の備考に書き、オーナーに報告する。

止まるときは、台帳 §7「作業ログ」に 1 行を足してコミットし、次のことを短く報告する。

- やった単位
- 次の一手
- 次に打つコマンド（必要なら `/effort` の切り替えも）

## してはいけないこと

- メモリや会話の記憶だけを根拠にして、「終わっている」と判断する。
- 変わっていないファイルを調べ直す。差分は `git diff <基準>..HEAD --stat` で確かめる。
- 台帳を更新しないままコミットする。
- 計画書に無い変更を混ぜる。
- auto-memory に進捗を書く。
