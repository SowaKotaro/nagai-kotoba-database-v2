## 0. ポジショニング

goo辞書・Weblio・コトバンク等の総合辞書と正面から戦わず、
**「読みの長さ・リズム・文字種で引ける、長い言葉に特化したデータベース」** という独自の切り口を核にする。
これがブランド・キャッチコピー・SEO の狙いクエリ(「◯文字の言葉」「◯◯なリズムの言葉」)すべての土台。

- ◎ 独自の検索軸(読み文字数・モーラ・先頭/末尾文字・文字種パターン・リズムパターン)は実装済み
- ◎ 明文化済み: 見出し「長い言葉を探す。」/ タグライン「日本語の長い言葉を読み・韻・ジャンルから探す」/
  説明文(`ja.yml` の `home.index.*`)。About・llms.txt・共有カードの文言もここから派生させている

## 1. コンテンツ戦略(現フェーズの最重要項目)

データベースサイトは**コンテンツそのものがプロダクト**。技術と同列以上に戦略が要る。

- ◎ 収録基準の文書化: [`docs/annotation-guidelines.md`](annotation-guidelines.md)(収録4原則・立項スコア・表記/読みの基準)
- ◎ 増産体制: 一括登録3ステップ + アノテーション・コンソール + Claude Code 連携(Issue 38)で半自動化済み
- ◎ ページ品質の底上げ: 自動リード文(Issue 18)で「散文ゼロのページ」は根絶済み。用例フィールド(Issue 33)は未着手(着手前に運用方針を相談)
- ◎ 「生きているサイト」の見せ方: 新着5件表示・Atom フィード・今日の一語に加え、収録数の**推移**は統計ページ §4(株価チャート式)で見せている(Issue 34 完了)
- **数値目標(宿題)**: インデックス解禁目安 = 注釈済み 300〜500 語(確定事項)。月あたりの注釈スループットを計測し、解禁予定日を逆算する

## 2. ユーザー理解とペルソナ

- ✗ ペルソナ・ユースケースの文書化は未着手
- **宿題(コード変更ではないため Issue 化しない)**: 誰が何のために長い言葉を引くのかを書き出す。
  候補: 作詞・ラップ(リズム/母音検索)、言葉遊び・大喜利、クロスワード/パズル作成(文字数/先頭末尾)、

## 3. 計測基盤と KPI(早いほど良い — 過去データは後から取れない)

- ◎ GA4 実装済み(Issue 19。Turbo 対応の page_view 送信、ENV `GA4_MEASUREMENT_ID`)
- ◎ Search Console / Bing の所有権確認メタタグは ENV 対応済み
- △ 本番での測定 ID 設定・所有権確認・sitemap 送信: 手順は [`launch-checklist.md`](launch-checklist.md)(Issue 44)。
  **インデックス解禁は 2026-07-19 に実施済み**(注釈済み 294 語の時点)で、Search Console への
  sitemap 送信も完了。**残っているのは Bing Webmaster Tools の所有権確認と sitemap 送信、
  および解禁後の観測(§3 の KPI)の定常運用**
- ◎ KPI の定義(Issue 44。以下のツリー)

### KPI ツリー

北極星: **週あたりの「語を見た訪問」数**(単語詳細を1語以上見たセッション)。
量・質・資産の3系統で観測し、数だけでなく**健康さ**を測る。

- **成長(量)**
  - PV・AU(週次/月次。GA4)
  - 流入チャネル別セッション(検索・SNS・直接・参照。GA4)
  - インデックス済みページ数・検索表示回数・クリック数(Search Console)
- **健康さ(質)**
  - 新規/再訪比率(GA4)
  - 検索・ファセット利用率 = /search または絞り込み付き /words を見たセッションの割合(GA4 の page_view URL で判別)
  - 1訪問あたり閲覧語数(単語詳細 PV ÷ セッション)
- **資産(将来の流入源)**
  - Atom 購読・JSON API 利用(サーバログ)
  - 被リンク(Search Console)

計測手段は当面 **page_view のみ**で賄う。GA4 カスタムイベント(検索実行・ファセットクリック・
シェアクリック)は URL パラメータでおおむね代替できるため導入しない。解禁後の観測で不足が
明確になったら小さな別 PR で導入する(Issue 44 の検討結果)。

## 4. リテンション(再訪)設計

公開側にアカウント機能を作らない方針のため、**ログインなしで再訪させる仕掛け**が課題。

- ◎ 「今日の一語」(日替わり・決定的)、Atom フィード(新着20件)、共有しやすいパーマリンク(1語1URL)
- ✗ SNS 定期投稿(今日の一語の X 自動投稿 → Issue 47)
- △ ブックマークしたくなる検索 URL: ファセット URL は共有可能だが、狙いクエリ別のランディング(索引 /browse・ジャンル /genres)はあるので当面十分

## 5. 流入チャネルの多様化(SEO・LLMO 以外)

- ◎ SEO 基盤: sitemap / robots / meta・canonical / JSON-LD / ファセットのインデックス方針(Issue 13〜18)
- ◎ LLMO: llms.txt / 公開 JSON API(CC BY 4.0 表記つき) / 自己完結リード文(Issue 24・25・18)
- ◎ シェア導線(X 共有・URL コピー、Issue 30)・静的 OGP 画像(Issue 14)
- ◎ 単語ごとの共有カード(og:image。Issue 29)
- ◎ 「引用したくなるページ」= 統計ページ `/stats`(Issue 34・78 完了。数字の壁 + 8章。被リンク獲得の種)
- △ データ引用チャネル: CC BY 4.0 + API + llms.txt の布石は完了。研究・アプリでの利用実績づくりはこれから

## 6. 信頼性・運用(グロースの土台)

- ◎ CI・セキュリティスキャン(rubocop / brakeman / bundler-audit / importmap audit)・テスト基盤
- ◎ HTTP キャッシュ(ETag・expires_in・Rails.cache。Issue 26)— 1万語規模なら現構成で耐える
- ✗ 死活監視・エラー通知が無い(障害に気づく手段がゼロ → Issue 45)
- ✗ DB バックアップが手動(`~/db_backups` → 日次自動化 Issue 46)
- ◎ fragment cache は `PublishedSenseCounts` に集約済み(Issue 48 完了)。速度の実測と残課題は [`performance-report.md`](performance-report.md)
- **コスト見通し(宿題)**: PV 10倍時のサーバ費用モデルは、計測(§3)でトラフィック実測が取れてから

## 7. 法務・ポリシー

- ◎ データライセンス CC BY 4.0(クレジット = サイト名 + URL)を About・llms.txt・JSON API に明示済み
- ◎ 連絡先メールの公開(About)
- ◎ プライバシーポリシー `/privacy`(Issue 42): GA4 の外部送信情報(送信先・情報・目的)・Cookie・
  アクセスログの取り扱いを公表。フッター・About・llms.txt・sitemap から参照
- △ API・スクレイピングの利用ポリシー: About の記載で最低限はあるが、アクセス急増時のレート方針は未定(必要になってから)

## 8. 持続可能性(運営体制・収益)

- △ 一人運営の律速 = アノテーション作業。Claude Code 連携(Issue 38・39)で「調査しながら全項目入力」から
  「下書きを承認」へ転換済み。**運営キャパ(月あたり注釈語数)の数値化は宿題**(§1 の解禁逆算と同じ計測)
- ✗ 収益方針(広告・寄付・スポンサー)は未定。入れる場合はデザインシステム([`design.md`](design.md)「しずか」)との両立を先に設計する
  —— アクセントカラーを持たず太字も使わない設計なので、既成の広告枠はそのままでは載らない。
  当面は判断不要 — トラフィックが立ってから

## 現フェーズ(解禁後・コンテンツ拡充期)の優先順位

**2026-07-19 にインデックスを解禁済み**(注釈済み 294 語の時点)。「解禁の前提を揃える」フェーズは
終わり、いまは**収録を増やしながら、観測と運用土台を固める**段階。

1. **コンテンツ**: アノテーションを進める — 全施策の前提。律速は依然としてアノテーション作業(§8)
2. **データの厚み**: 言語的特徴の遡及付与(Issue 76)— 公開語の 86% で空のまま公開されている検索軸
3. **運用土台**: バックアップ自動化(Issue 46・技術監査で Critical)と監視(Issue 45)
   — どちらも本番サーバでの作業が要るため着手が止まっている(確定事項 23)
4. **観測**: Search Console の流入クエリを狙いクエリ(「◯文字の言葉」等)と突き合わせ、§1 の収録方針に反映する
5. **スケール系**(コスト最適化・レート制御・収益)は兆しが見えてからで間に合う

旧ドメイン `.com` との関係(ブランドクエリを旧システムに取られている件)は、収録語数が追いつくまで
動かさない方針(Issue 27・確定事項 22)。
