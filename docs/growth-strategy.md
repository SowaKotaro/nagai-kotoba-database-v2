## 0. ポジショニング

goo辞書・Weblio・コトバンク等の総合辞書と正面から戦わず、
**「読みの長さ・リズム・文字種で引ける、長い言葉に特化したデータベース」** という独自の切り口を核にする。
これがブランド・キャッチコピー・SEO の狙いクエリ(「◯文字の言葉」「◯◯なリズムの言葉」)すべての土台。

- 独自の検索軸(読み文字数・モーラ・先頭/末尾文字・文字種パターン・リズムパターン)は実装済み
- 明文化済み: 見出し「長い言葉を探す。」/ タグライン「日本語の長い言葉を読み・韻・ジャンルから探す」/
  説明文(`ja.yml` の `home.index.*`)。About と llms.txt の文言は `ja.yml` の `pages.about.*`、
  既定の共有カードの文言は `script/og_default.py` の `LEAD` に直書きしていて、`home.index.*` からは派生していない

## 2. ユーザー理解とペルソナ

- **宿題(コード変更ではないため Issue 化しない)**: 誰が何のために長い言葉を引くのかを書き出す。
  候補: 作詞・ラップ(リズム/母音検索)、言葉遊び・大喜利、クロスワード/パズル作成(文字数/先頭末尾)、
  創作(ネーミング)、日本語学習者・言語学好き(特徴タグ)。
  ユースケースごとに刺さる機能・狙う検索クエリ・SNS での見せ方が変わるため、§1 の収録方針にも反映する

## 3. 計測基盤と KPI(早いほど良い — 過去データは後から取れない)

計測の現状(GA4・Search Console・インデックス解禁)は history の §3。手順は [`launch-checklist.md`](launch-checklist.md)。

### KPI ツリー

北極星: **週あたりの「語を見た訪問」数**(単語詳細を1語以上見たセッション)。
量・質・資産の3系統で観測し、数だけでなく**健康さ**を測る。

- **成長(量)**
  - PV・AU(週次/月次。GA4)
  - 流入チャネル別セッション(検索・SNS・直接・参照。GA4)
  - インデックス済みページ数・検索表示回数・クリック数(Search Console)
- **健康さ(質)**
  - 新規/再訪比率(GA4)
  - 検索・ファセット利用率 = /search または絞り込み付き /words を見たセッションの割合(GA4 の page_view URL で判別)
  - 1訪問あたり閲覧語数(単語詳細 PV ÷ セッション)
- **資産(将来の流入源)**
  - Atom 購読・JSON API 利用(サーバログ)
  - 被リンク(Search Console)

計測手段は当面 **page_view のみ**で賄う。GA4 カスタムイベント(検索実行・ファセットクリック・
シェアクリック)は URL パラメータでおおむね代替できるため導入しない。解禁後の観測で不足が
明確になったら小さな別 PR で導入する(Issue 44 の検討結果)。
