## 技術監査対応(Issue 49〜56、2026-07-12 の監査より)

- **Issue 49: deploy:seed × マスタリネームの重複再発防止** [bug] — 完了(PR #73)。対策方式は「案a+b(リネーム追従マップ + UI警告)」をオーナー決定。マスタの名前リストを `app/models/seed_catalog.rb`(単一の正)に集約し、seed 実行時に RENAMES(旧名→新名)で全環境が改名に追従。移行先が既存の場合は改名せず警告(統合は /admin/tags に委ねる)。タグ統括管理には seed 収載タグの「seed」印(一覧)と更新手順の警告(編集画面)を表示。旧 `db/seeds/*.rb` 4本は削除。
- **Issue 50: 管理者セッションの有効期限** [improvement] — 完了(PR #71)。永続 Cookie(約20年)を2週間の `expires` に変更。サーバ側も `updated_at` ベースのスライディング失効(`Session::LIFETIME`)を導入し、期限切れはアクセス時に破棄・ログイン時に掃除。DB 書き込みと Set-Cookie は1時間間隔に間引き。
- **Issue 51: backfill タスクの last_char 再計算漏れ** [bug] — 完了(PR #72)。`backfill:reading_metrics` に `last_char` の再計算を追加。全派生カラム(words.char_type_pattern 含む)の現在値と再計算値の差分を報告する読み取り専用タスク `backfill:verify` を新設。verify がフィクスチャの実バグ(涼宮ハルヒの憂鬱の char_type_pattern で「の」が文字クラス化されていない)を検出したため同時修正。
- **Issue 52: 一括登録の類似チェック(Levenshtein 総当たり)の負荷軽減** [improvement] — 完了(PR #123)。Issue 75 で同じ総当たりが公開側から叩けるようになったため前倒しした。計測は 10,000語で 2,250ms → 676ms(3.3倍)。**当初の対処案(`reading_length` による DB 側の長さ絞り込み)は採用していない**。それは `far_apart?` が Ruby 側で既にやっている枝刈りと同じもので、距離計算が1件も減らないため。収録基準が「読み10文字以上」で読みの長さが一箇所に固まっており、長さによる枝刈りは原理的に効かない(帯に読み12字で 97.4% が残る)。実際の対処は帯状化+早期打ち切り(Ukkonen)・`String#chars` のループ外への追い出し・DP 行配列の使い回し。あわせて `far_apart?` の浮動小数バグ(`(1-0.8)` が `0.19999999999999996` になり、類似度ちょうど 0.8 の組を誤って弾いていた)を修正した。詳細は [`performance-report.md`](performance-report.md) §7.5。
- **Issue 54: Atom フィードのジャンル祖先 N+1 解消** [bug] — 完了(PR #95)。
- **Issue 55: config.load_defaults を 8.1 へ引き上げ** [improvement] — 完了(PR #125)。7.1 のままで 7.2/8.0/8.1 の新既定が一切効いていなかったのを解消。実際に影響があったのは4つで、いずれも動作確認済み: `strict_freshness`(8.0。sitemap/llms-full の条件付き GET が 304 を返すことを確認)・`Regexp.timeout = 1`(8.0。公開検索の正規表現は MySQL 側評価なので影響なし)・`render_tracker = :ruby`(8.1。`/search` のフラグメントキャッシュが `_genre_chip` の変更を拾えることを確認)・`yjit`(8.1。本番のみ。Rails 側が `defined?` でガードしており YJIT 無しビルドでも起動する)。feed の preload を `words#show` と同じ深さ(`genre: { parent: :parent }`)に揃え、リード文の `self_and_ancestors` による遅延ロード(最大 20語×2階層 ≒ 40 クエリ)を解消。あわせて条件付き GET(`fresh_when`。ETag はジャンル祖先を含む = touch されないマスタの改名も検知)を追加。

## クロール予算の是正(Issue 80、2026-08-20)

- **Issue 80: シャッフルの無限クロールトラップと、面の棚卸し** [bug] — 完了(2026-08-20)。2026-08-20 の Search Console レポート(**noindex 除外 3,186** ・robots.txt ブロック 102・検出未登録 96・クロール済み未登録 13)と、7月末から約半減した表示回数(約250/日 → 約110/日)の原因調査。**Issue 74 の対応(2026-07-28 時点で noindex 309)から3週間で 10 倍に増えていた**。
  - **原因はシャッフルのリンク**。`shuffle_words_path` が `SecureRandom.hex(4)` を href に埋めていたため、**一覧を描画するたびに未知の URL が生まれる**。しかもこのボタンは素の一覧・全ファセット面・全ページ送りに置かれ、`rel="nofollow"` も robots.txt のブロックも無く、**辿った先でもまた新しい URL が生まれる**。事実上の無限 URL 空間で、クローラが延々と noindex ページを取りに来ていた。導入は 2026-07-21(`58cbe66`)で、GSC の未登録数が 7/24 の 449 → 7/25 に 1,910 へ急増し以降**単調増加**(2,620 → 2,919 → 2,961 → 3,423)している推移と一致する。本物のページのクロールが後回しになり(「検出 - インデックス未登録」96)、表示回数の低下につながっていた。
  - **対応(1) 生成元を絶つ**: シードを **href から外してサーバ側(`WordSort`)で振る**。URL に無ければリクエストごとに新しいシードを引くので「押すたび・開くたびに引き直す」挙動はそのまま、**絞り込み1つにつきシャッフルの URL はちょうど1本**に収まる。ページ送りは実際に使ったシードを引き継ぐが、そのリンクには `rel="nofollow"` を付ける。ボタン自体にも `nofollow`(結果は必ず並び違いの重複 = noindex なのでクロールの価値が無い)。
  - **対応(2) 既知の分も止める**: robots.txt に `Disallow: /*seed=`。`/search` と違い**元から実在しないページ**なので noindex を読ませる必要がなく、再クロールごと遮断してよい(Issue 74 で `/search` をブロックしなかった判断とは前提が異なる)。
  - **対応(3) 面の棚卸し**: 統計・索引から常時リンクしているのに noindex のままクロールだけさせていた軸を **インデックス許可に格上げ**(`reading_length` / `mora_count` / `linguistic_feature_id`、実測で計約 56 URL)。いずれも値域が有限で、「読みが15文字の長い言葉」「回文の長い言葉」のように**本サイトの検索需要そのもの**になる面。見出しは `words.index.facet_heading.reading_length` / `.mora_count` を追加。
  - **対応(4) 残る noindex 行きに `nofollow`**: ワードクラウドの形態素チップ(キーワード検索 `q=`。実測 60 URL → 2026-09-10 に 100 URL)、頭子音の**複数文字**をまとめて渡す棒(1文字だけの群はスカラ形 = 単一ファセットなので**辿らせたまま**)、波形バーの「◯以上」(範囲指定 `reading_length_min`)、`/words/random`(毎回別の語へ 302 する導線)。
  - **効果の見込み**: 内部リンクから辿れる noindex URL が有限(素の一覧 + 各面 1 本)になり、クロール予算が単語詳細と単一ファセットへ回る。既存の 3,186 件は robots.txt で再クロールが止まり、GSC 上は「robots.txt によりブロックされました」へ移ってから漸減する。**(この最後の見込みは Issue 81 で撤回。ブロックすると canonical の訂正を読ませられないため `Disallow: /*seed=` は外した)**

## ファセット面の是正(Issue 81、2026-08-25)

- **Issue 81: ファセットの canonical 破れと、実在しない面** [bug] — 完了(2026-08-25)。Issue 80 の対応後も残っていた、面まわりの取りこぼし5点。
  - **canonical の二重エスケープ**: `content_for(:canonical_path)` は値を HTML エスケープして貯めるため、クエリの `&` が `&amp;` になり、レイアウトの `<%= %>` でもう一度エスケープされて `?a=1&amp;amp;b=2` になっていた。クローラから見ると「amp;b」という実在しないパラメータ名の URL を canonical に指名している状態。`canonical_path(...)` ヘルパー(インスタンス変数)に替えて経路からエスケープを外した。
  - **noindex の伝播**: `/words?sort=…` は必ず noindex だが、canonical には sort を含めず `/words` を指していた。**noindex のページが他の URL を canonical に指名すると、その指し先へ noindex が伝播しうる**(Google 公式ガイダンス)ため、サイトのハブである `/words` を巻き添えにする恐れがあった。canonical に sort を含め、自身を指させて断つ。シャッフルの seed は URL に載せない値なので canonical も seed 抜きの1本に寄せる。
  - **実在しないマスタ id で面が無限に湧く**: `genre_id=99999` のような値は絞り込みごと落ちるため **`/words` の完全な複製**が任意の数値ぶん作れ(しかも index 可能・自己 canonical)、他の軸は 0 件の面が同じく無限に作れた。`WordSenseSearch#unknown_master_ids?` を追加し、コントローラで 404 にして URL 空間を閉じる。判定に使う対応表(`MASTER_FACETS`)は見出しの解決(`WordsHelper::FACET_MASTERS`)と共有し、片方だけ軸が増えるのを防ぐ。
  - **0 件のファセット面を noindex**: 実在する軸でも公開語が 0 のもの(連声・音韻添加など。Issue 77)や `reading_length=99` のように値だけ無いものがあり、中身の無い面をクロールさせても「クロール済み - インデックス未登録」が増えるだけのため。
  - **`Disallow: /*seed=` を撤去**: Issue 80 の対応(2)を**取り消した**。既知の 3,186 件は当時「noindex + canonical は `/words`」を宣言済みで、ブロックすると Google がその訂正(canonical を自身へ向けた上記の修正)を読めず、宣言が凍結されて `/words` へ noindex が伝播したままになる。生成元は既に絶ってあるので新しい `?seed=` は増えず、既知の分は再クロールで noindex に落ちる。あわせてランキングの「すべて見る」(必ず noindex の並び違いへ行く導線)に `rel="nofollow"`。

## 番号を持たない改善(PR 単位)

Issue 番号を取らずに PR だけで進めた、オーナー指示由来の機能追加・磨き込み。
経緯の詳細は git 履歴、仕様の正はそれぞれのリンク先。**ここには「何が入ったか」だけを 1 行で残す。**

### 機能

- **一括登録の3ステップ化と読みの自動取得**(PR #30、2026-07-05) — 入力(箇条書き) → 読み(MeCab) → 重複チェック → 登録。`ReadingExtractor` が `mecab -Oyomi` を Open3 で呼ぶ。**mecab が無い環境では読みが空欄になるだけで機能は止まらない**。PR #108 で自動読みをカタカナのみに正規化。
- **タグ統括管理 `/admin/tags`**(2026-07-09) — ジャンル・エンティティ・品詞・語種・特徴の一覧/リネーム/削除/統合。`:kind` は `TagKind` のホワイトリストで解決する。PR #92 で管理一覧のタグ絞り込み、PR #93 でタグ管理からの特徴追加。
- **注釈状態の3値化**(PR #85、2026-07-15) — 未対応 / 保留 / 完了(`words.annotation_status`)。保留はコンソールのキューから外れ、一覧の絞り込みから見直せる。
- **正規表現検索**(PR #94、2026-07-16) — `/search` の `regexp`。値オブジェクト `SearchRegexp`。読みに当てるパターンだけカタカナへ畳み、不正な式は検索前に弾き、照合の打ち切りは空結果＋警告にフォールバックする。
- **ランキングページ `/rankings`**(PR #103、2026-07-21) — 11 種の順位表を束ねるハブ。カタログは `WordRanking`、並びは `WordSort::RANKING_ORDERS` と共有し、各枠の「もっと見る」は同じキーの一覧へ渡す。
- **五十音円環と円環交差数**(PR #105・#106、2026-07-21) — `KanaRing`。読みを 50 音の円環上で一筆書きにした線画と、その弦が交わった回数(`word_senses.ring_crossing_count`)。**統計の看板としては不採用だった案(Issue 62)が、単語詳細の図として復活したもの**。のちにサイトのロゴ・favicon・共有カードもこの図になった。
- **ダークモード**(PR #111、2026-07-24) — OS 設定に追従し、ヘッダーのトグルで上書きして `localStorage` に残す。公開側・管理画面・コンソールのすべてに適用。設計は [`design.md`](design.md) §9。
- **オフライン調査コマンドの拡充** — `/expand`(PR #79)・`/harvest`(PR #84)・`/reannotation`(PR #117、PR #141 で claude.ai 用バンドルの生成手順)。入出力の約束は [`../research/README.md`](../research/README.md)。
