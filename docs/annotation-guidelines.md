# アノテーション・ガイドライン（収録基準と調査補助）

単語の立項（収録）とアノテーションの**客観的な基準**。次の2つの目的を持つ（Issue 39）。

1. **Claude Code の基準点**: `word-notation-research`（登録前の表記確定・立項判定）、
   `word-reading-research`（読み調査）、`word-annotation-research`（アノテーション提案）の各スキルは、
   この文書を判断の拠り所にする。
2. **オーナーのバイアス防止**: 収録可否・表記・読みの判断が個人の感覚に流れないよう、
   誰が判定しても同じ結論になる基準を明文化する。内輪語の混入や曖昧な表記選定から DB を守る。

---

## 0. 前提: 収録範囲

- **読みが10文字以上**の日本語の単語を収録対象とする（2026-07-06 オーナー確定。`docs/issues.md` 参照）。
- 読みが10文字未満の語は、以降の原則を満たしても収録しない。

---

## 1. 収録の4原則

立項に値するかは、以下の**4原則すべて**で判定する。各原則は独立しているが相互に補完し合う。
例えば「公然性」を満たしても「慣用性」を欠く語（公開はされているが誰も使っていない語）や、
「慣用性」を満たしても「同定可能性」を欠く語（広く使われるが指す対象が曖昧な語）は立項できない。

| 原則 | 判定質問（1行） | 防ぎたい問題 |
|---|---|---|
| 公然性 | 第三者が公開媒体でその語の存在を確認できるか？ | 内輪ネタ・検証不能な語の混入 |
| 妥当性 | 辞書や索引の見出し語になり得る、過不足のない1語か？ | 説明文・不要な修飾による水増し |
| 慣用性 | ある共同体で実際に使われ続けているか？ | 即興の造語・一時的な表現の混入 |
| 同定可能性 | 聞いた第三者が、指す対象を一意に特定できるか？ | 何を指すか分からない曖昧な名称 |

### 1.1 公然性（Publicity）

**誰でも客観的に存在を確認できる語であること。**

- 一般に公開されており、不特定多数が知り得る。
- 辞書・百科事典・書籍・新聞・公式サイト・ゲーム・漫画など、**第三者が確認できる媒体**に存在する。
- 当事者以外でも「その単語が存在する」ことを検証できる。

| 満たす例 | 満たさない例 |
|---|---|
| 天上天下唯我独尊（仏典・辞書に掲載） | 身内だけで使っているあだ名 |
| モンキー・D・ルフィ（公刊漫画の登場人物） | 友人の飼い猫の名前 |
| バミューダトライアングル（百科事典・多数の書籍） | Discord サーバー内だけの呼称 |
| リヴァイアサン（書名・神話上の存在） | 会話中にその場で決めた略称 |

### 1.2 妥当性（Validity）

**一つの語として過不足なく独立して成立していること。**

- 単独で一語として意味を持つ。
- 説明文や不要な修飾を含まない。**冠称・敬称・肩書きは取り除く**（→ §3 表記の選定基準）。
- 文の一部ではなく、辞書などで**見出し語になり得る単位**である。

| 満たす例 | 満たさない例 | 理由 |
|---|---|---|
| プロテスタンティズムの倫理と資本主義の精神 | ドナルド・トランプ大統領 | 冠称（肩書き）が付いている |
| ドナルド・トランプ | 東京にある長い名前の駅 | 語ではなく説明句 |
| 花は桜木人は武士（ことわざ＝1見出し） | とてつもなく大きな | 修飾句の断片 |
| インフォームド・コンセント | 〜のために | 文の一部 |

補足: 書名・曲名・ことわざ・慣用句は全体で1つの見出し語として扱う（「花は桜木人は武士」は
文の形をしているが、ことわざとして辞書の見出しになるため妥当性を満たす）。

#### 1.2.1 語の単位（過剰な連結をしない）

複数の概念が連なって見える語は、**その連結形そのものが一語として定着しているか**を必ず確認する。
定着していれば1語として立項し、定着していなければ**別々の語として立項する**。
読みを10文字以上にするために連結させる、という発想で語を作らない。

| 1語として扱う（連結が定着） | 分割する（便宜上まとめただけ） |
|---|---|
| 相加・相乗平均（両者の関係を述べる定理名として定着） | 経済・経営学部 → 経済学部／経営学部 |
| 費用対効果 | 損害保険・生命保険 → 損害保険／生命保険 |
| 加持祈祷 | 特急・急行料金 → 特急料金／急行料金 |
| インフォームド・コンセント | 衆議院・参議院 → 衆議院／参議院 |

判定手順:

1. 連結形そのもので検索し、**辞書・百科事典の見出し**になっているかを見る。あれば1語。
2. 見出しが無ければ、公式・専門媒体・教科書で**定型句として繰り返し使われている**かを見る。
   使われていれば1語（根拠を注記に残す）。
3. どちらも無ければ**分割する**。新聞見出し・目次・列挙での「A・B」は、紙面の都合で
   まとめただけであり語ではない。
4. 分割後の各語が収録範囲（§0）と4原則を満たすかは、**それぞれ独立に**判定する。
   分割した結果どちらも読み10文字未満なら、その候補は落ちる。

### 1.3 慣用性（Conventionality）

**社会において実際に用いられている語であること。**

- 継続的な使用実績がある（一過性のバズで消えた語は慎重に）。
- 一個人が即興で作っただけの造語ではない。
- 一定の共同体や社会で語として**定着**している。共同体は「日本社会全体」である必要はない
  （特定作品のファンダム・専門分野・地域でも、その共同体で定着していればよい）。

| 満たす例 | 満たさない例 |
|---|---|
| インフォームド・コンセント（定着した専門語） | その場で作った造語 |
| リボルビング払い（社会に定着した商用語） | 自分しか使っていない略語 |
| 広く普及したネットスラング・略称 | 投稿1件でしか確認できない表現 |

### 1.4 同定可能性（Identifiability）

**第三者が何を指している語か一意に理解できること。**

- 聞いた人が対象を特定できる。必要以上に曖昧ではない。
- 固有名詞であれば、**一般的な名称**として認識されている。
- 同名の対象が複数ある場合は、意味（語義）の記述で同定を担保する（同音異義語は語義を分ける）。
- **略称・通称は同定可能性が落ちやすい**（同じ略称が複数の対象を指す）。原則として正式名称を
  表層形に採ることで同定を担保する（→ §3.3）。

| 満たす例 | 満たさない例 |
|---|---|
| 東京スカイツリー | 駅前のラーメン屋 |
| バミューダトライアングル | うちの近所の大きな公園 |
| 中臣鎌足 | 田中さん／うちの先生 |

## 2. 立項スコア（5段階）

4原則への適合度を1〜5で評価する。`word-annotation-research` スキルは全語に `entry_score` を付け、
**3以下**には `entry_notes`（どの原則を・なぜ欠くか）を必ず添える。コンソールは3以下に朱バッジを出す。

| スコア | 定義 | 扱い |
|---|---|---|
| 5 | 4原則すべてを明確に満たす。辞書・百科事典・公式媒体で即確認できる | 登録可 |
| 4 | すべて満たすが、一部の裏取りが単一ソースなど確認が薄い | 登録可（根拠を notes に） |
| 3 | 1つの原則にグレーがある（慣用性が新しすぎる、同定に文脈が要る 等） | **オーナー判断** |
| 2 | 1つの原則を明確に欠く、または2つ以上がグレー | 原則見送り（削除候補） |
| 1 | 複数の原則を明確に欠く（内輪語・即興造語・検証不能） | 立項不可（削除候補） |

- スコアは「語の有名さ」ではなく「**基準への適合度**」。マイナーでも4原則を満たせば5になり得る。
- 既に登録済みの語に低スコアが付いたら、それは**削除候補の指摘**。削除の最終判断はオーナーが行う。

## 3. 表記の選定基準（一般的な表記か）

`surface`（表層形）には、**日本語の文脈でその語を書くときの標準形**を採る。
「よく見かける形」ではなく「**正規はどれか**」を確定する。3.1 から 3.5 まで順に適用する。

### 3.1 本体だけを採る

- **冠称・敬称・肩書きを含めない**: ドナルド・トランプ大統領 → ドナルド・トランプ。
- **法人格・組織形態の冠称を含めない**: 株式会社／有限会社／一般社団法人／独立行政法人 等は落とす
  （日本電信電話株式会社 → 日本電信電話）。ただし商号の一部として不可分な場合は残す。
- **説明的修飾を含めない**: 見出し語になる最小の単位に切り詰める。
- **中黒・句読点・スペース・記号**は、原典・辞書の見出しの表記に従う（勝手に足したり削ったりしない）。

### 3.2 異体字・旧字を正規化する

- **一般表記へ寄せる**: 廣島 → 広島、內藤 → 内藤。
- ただし**固有名詞が旧字・異体字を正式表記とする場合はそれに従う**（例: 髙島屋）。

### 3.3 正式名称を優先する（通称・略称は原則採らない）

固有名詞は**正式名称を第一候補**とする。通称・略称・愛称・俗称は別表記（variants）に回す。
略称は同定可能性（§1.4）も弱く、同じ略称が複数の対象を指しうる。

| 採る（正式名称） | 採らない（通称・略称） |
|---|---|
| 東京大学 | 東大 |
| ヤマト運輸 | クロネコヤマト |
| 東京ディズニーランド | ディズニーランド |
| 国立国会図書館 | 国会図書館 |

**通称を表層形に採ってよいのは、次を全て満たすときだけ**。満たす根拠を注記に残す。

1. 正式名称が法令・登記・公的文書以外ではほとんど使われない。
2. 通称が辞書・百科事典・公式媒体の**見出し**になっている。
3. その通称で対象が一意に定まる。

例外の例: ゆりかもめ（正式: 東京臨海新交通臨海線）／京浜東北線（運転系統の呼称）。

- 「正式名称は長い」「通称の方が有名」は、通称を採る理由に**ならない**。有名さは基準ではない（§2）。
- 正式名称が複数の時期で変わっている場合は、**現行の正式名称**を採る（旧称は variants）。

### 3.4 ラテン文字表記かカタカナ表記か

外来の語は「カタカナで書かれることもある」で止めず、**日本語の文脈での正規表記がどちらか**を確定する。
判断の軸は**日本の書記慣習**であって、原語の綴りが正しいという話ではない。

- **人名・地名など、日本語では慣習的にカナ転写されるもの → カタカナ**。
  日本の辞書・報道・教科書がカナ見出しを使う領域は、原綴りがあってもカナが正規。
  - ドナルド・トランプ（Donald Trump ではない）／サンクトペテルブルク／シュレーディンガー方程式
- **ブランド・製品・作品・企業・団体 → 権利者が日本語圏で使っている表記に従う**。
  日本語版の公式サイト本文・パッケージ・クレジットでの表記が正規。
  - ラテン文字が正規: Dead by Daylight ／ Nintendo Switch ／ PlayStation
  - カタカナが正規: マクドナルド ／ ポケットモンスター ／ ファイナルファンタジー

  公式が両方使う場合は、ロゴではなく**本文中の表記**（サイトのタイトル・法人の商号・報道での表記）を採る。
- **頭字語・略号 → 日本語でもラテン文字のまま使うものはラテン文字**: NHK／DNA／NATO／Wi-Fi。
  カナ表記が定着している語だけカナにする（ディーエヌエー とは書かない）。
- **一般名詞・学術用語 → 日本語（漢語・カナ）を採り、原語綴りは採らない**:
  compliance ではなく コンプライアンス、informed consent ではなく インフォームド・コンセント。
- **大文字小文字・記号・空白は公式表記どおり**: iPhone／eスポーツ／Yahoo! JAPAN。
- 表層形がラテン文字でも `reading` はカタカナで持つ（§4）。**表記の判断を読みに引きずられない**。

### 3.5 拮抗するときは典拠の優先順位で決める

複数の表記が競合したら、次の順で上位の典拠に従う。下位が多数でも上位を覆さない。

1. 権利者・本人・発行元の**日本語公式表記**（公式サイト本文、パッケージ、奥付、登記上の商号）
2. 国語辞典・百科事典の**見出し**（日本国語大辞典、コトバンク、ブリタニカ 等）
3. 全国紙・公共放送の表記（記者ハンドブック系の統一表記）
4. 日本語版 Wikipedia の**記事名**（改名議論があるため単独では根拠にしない）
5. 検索ヒット数（**最後の手段**。数字だけで決めない）

- 上位2つが一致すれば `confidence` は high にしてよい。
- 4・5 しか根拠が無い場合は medium 以下にし、**採らなかった表記を注記に残す**。

## 4. 読みの基準（正しい読みか）

`reading` は語の**最も一般的な読み**を採る。表記ルールは MeCab との突き合わせに合わせる
（`word-reading-research` スキルと同一のルール）。

- **カタカナ**で書く。長音は「ー」（例: プロテスタンティズム）。
- **助詞は表記どおりのかな**: は→ハ、へ→ヘ、を→ヲ（例: 花は桜木人は武士 → ハナハサクラギヒトハブシ）。
- 促音「ッ」・拗音「ャュョ」は小書き。記号・空白・中黒は読みに含めない。
- 数字は文脈上の一般的な読み（例: 四十七士 → シジュウシチシ）。
- 読みが複数あるときは最も一般的なものを採り、他は候補（alternatives）として残す。
- **でっち上げない**: 確信が持てない読みは Web 検索で裏取りし、独立した2ソースの一致を確認する。
  一致しなければ confidence を下げて候補を併記する。

## 5. 知名度・一般性の判定目安（一般に知られている語か）

「知られているか」は主観に流れやすいため、以下の**客観的な手掛かり**で判定する。

- 国語辞典・百科事典（コトバンク、Wikipedia 等）に見出しがある → 強い根拠。
- **互いに独立した複数の情報源**（公式サイト＋報道、書籍＋辞書 等）で確認できる → 十分な根拠。
- 単一の投稿・単一のファンサイトでしか確認できない → 慣用性・公然性のグレー（スコア3以下）。
- 判定に迷う場合は、でっち上げずに confidence を `low` にし、notes に「何を確認してほしいか」を書く。

## 6. 人物語の分類（ジャンルとエンティティ）

人物（実在の個人）を立項するとき、「数学者」「作曲家」のような**職業はジャンルではなくエンティティ側**の情報。
語義はジャンル1つ・エンティティ1つしか持てないため、職業名を小分類に作ると、各中分類の下に
「物理学者」「化学者」…が増殖し、**分野の棚が職業の棚に侵食される**。職業は `人名` エンティティに畳む。

ジャンルは業績の要約ではなく、**探す人がどの棚を見るかという検索の導線**。したがって人物は
**その人物が最も強く想起される一分野**の小分類に置き、全業績の網羅は諦める。

- 複数分野にまたがる人物（オイラー、フォン・ノイマン等）でも、代表分野を一つ選ぶ。
  承認済み実例: `レオンハルト・オイラー` = `自然科学 > 数学 > 解析学`（`entity_type` は `人名`）。
- 分野の小分類は**人物専用の棚にしない**。同じ小分類が業績語・概念語にも再利用できる分野名を選ぶ
  （`解析学` は微分積分・フーリエ級数にも使える。`数学者` は人物にしか使えない）。
- 代表分野が割れて決められないときは、新設せず notes に迷いを書いてオーナーの承認に回す。
- 網羅性は将来的に関連語で表現する事柄であり、**ジャンルや小分類を増やす理由にはしない**。

## 7. 言語学的特徴の用語集

連濁・音韻添加・重箱読みなどの定義と具体例は、**`config/linguistic_features_glossary.yml`** が
単一ソース（seed のマスタ名と1対1）。アノテーション・コンソールの特徴選択欄にある
「用語解説」パネルから同じ内容を参照できる。

## 運用（どこで使われるか）

- **候補収集時**: `word-expansion-research` スキルが、登録済みの語を種に同系統の語をまとめて集める。
  §1（収録4原則）・§5（知名度）で候補を絞り、基準を欠く語は候補に入れない。
- **登録前**: `word-notation-research` スキルが §3（表記）に従って表層形を確定し、
  §1（4原則）・§1.2.1（語の単位）・§2 で立項スコアを付けて足切りする。
- **登録時**: `word-reading-research` スキルが §3（表記）・§4（読み）に従って調査 JSON を作る。
- **アノテーション時**: `word-annotation-research` スキルが §1〜§6 に従い、`entry_score` 付きの
  提案 JSON を作る。コンソールの提案パネルがスコアを表示し、3以下に朱バッジと理由を出す。
- **迷ったら**: 原則に照らして notes に理由を書き、最終判断はオーナー（人間）が行う。
  基準そのものに不備を見つけたら、この文書を更新してからスキルの挙動を変える。
