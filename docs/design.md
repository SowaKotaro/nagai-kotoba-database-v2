## 0. 思想（1行）

**「読むための、しずかな場所」**。主張しないこと自体が仕様。目に入るのは言葉とデータだけにする。

- 手本は **しずかなインターネット**。狭いカラム・大きな余白・太字を使わない文字組み・彩度をほぼ持たない配色。
- **情報は疎でよい。** 1画面に詰め込まず、見せる要素を減らして余白で離す。
- **禁止**: 書体で情緒を出すこと（明朝体は使わない）／和色（朱・臙脂）や紙色の地／彩度の高いアクセント色を UI に置くこと／
  ゼロ埋め番号（`01`）／太字による強調／大文字＋広い字間の英字ラベル／巨大見出し×極小ラベルの級数対比／
  グラデーション・ガラスモーフィズム・**ドロップシャドウで押し出す“カード風”**・**ニューモーフィズム**・派手なアニメーション・絵文字。
  （区画は §3 のとおり「面の色 ＋ 細罫 ＋ 余白」だけで示す）
- **動きはサイト全体でホーム最上部の印だけ**（§5.9）。一筆書きで描く 3.1 秒は**1 度だけで止まり**、外周の英字だけが**80 秒で 1 周**し続ける。
  ほかは hover の色/面の変化（160ms）に限る。**スクロール連動・視差・フェードインの一斉発火は入れない**。
- 迷ったら **実サイトを開いて見比べる**。手本は役割で分けている:
  **静けさ・余白・文字組み = sizu.me**／**標識と図としての数字 = ただ、そこ**／**線画 = mud Inc.**／**全幅の帯 = TOFT**。
- 装飾を足す方向には倒さない。**新しい要素を1つ足すなら、既にあるものを1つ削る。**

## 1. カラートークン（これ以外の色は使用禁止）

`app/assets/stylesheets/tokens.css` の `:root` に定義。必ず `var(--token)` で参照。
**色は「無彩色＋ごく淡い青み」だけ。アクセントカラーを持たない。**

| トークン | ライト | 用途 |
|---|---|---|
| `--bg` | `#EFF2F6` | 地。**すべての立体の基準面**（真っ白にしない） |
| `--surface` | `#FFFFFF` | **コンテンツの面**（カード・一覧・ボタン・タグ・入力）。地との差をはっきり出す |
| `--bg-soft` | `#E6EBF2` | 一段沈めた面（フッター・行の hover・画像帯・コード面） |
| `--bg-tint` | `#E4ECF6` | さらに淡い青の面（選択中・ハイライト） |
| `--text` | `#232A31` | 本文・見出し（手本の `rgba(3,10,18,.87)` 相当。真っ黒にしない） |
| `--text-muted` | `#5F6568` | 補足・メタ（白地 5.9:1） |
| `--text-subtle` | `#63686C` | 最も弱い文字の**下限**（地 5.0:1／沈んだ面の上でも 4.7:1。これ以上薄くしない） |
| `--border` | `#DFE4EC` | 仕切り（表の行・区画の中の細罫） |
| `--border-strong` | `#C6CCD5` | 本文リンクの下線・図の補助線 |
| `--danger` | `#B4453F` | エラー・重複警告・削除 |
| `--success` | `#3F7D5A` | 一致・完了・達成 |
| `--chart` | `#6F8EA8` | **チャートの塗りだけ**に使う青灰。UI には使わない |

書体のトークンは 3 本: `--font-sans`（本文・見出し・**サイトタイトルを含むすべての和文**）／`--font-mono`（機械が読む値・§5.8 の標識・ブランド名の右の英字）／`--font-display`（§5.9 の「図としての英数字」だけ）。

**原則**:
- **UI に色を置かない**。リンクも現在地も選択状態も、**文字色の濃さ・淡い面・塗りの反転**で表す。
- **淡さには下限がある**（2026-09-03 の実測で判明）。静けさを狙って薄くしすぎると、文字は WCAG AA を割り、
  面と罫は「稜線」にならず、ページ全体が白飛びして目が滑る。**文字は最も弱い `--text-subtle` でも 4.5:1、
  面・罫は白との差を ΔRGB 19 以上**確保する。これは意匠ではなく下限値なので、静けさを理由に下回らない。
- 赤と緑は「意味を持つとき」だけ（エラー / 達成）。文字と細枠にとどめ、面には塗らない。
- 濃さの表現（ヒートマップ等）は `color-mix(in srgb, var(--chart) N%, transparent)`。**N の上限は 45%**
  （それ以上濃くすると、ライト/ダークどちらかで上に載る文字が読めなくなる）。

## 2. タイポグラフィ

**本文と UI の書体は 1 本**（`--font-sans`）。手本と同じ `-apple-system, BlinkMacSystemFont, Inter, "Hiragino Kaku Gothic Pro", "Noto Sans JP", …` の並び。

**書体はサイト全体で 1 本**（`--font-sans`）。**例外は無い**。
サイトタイトルに専用の書体（手本「ただ、そこ」から採寸した `--font-brand`）を当てていた時期があるが、
「イメージと違う」として本文と同じ `--font-sans` に戻し、トークンごと削除した（2026-09-04 → 05 オーナー判断）。
サイトタイトルは **19px・`font-weight` 400**（級数だけ上げて段を作る）。

- **太字を使わない。`font-weight` は 400 に統一**（`b`/`strong` だけ 500 まで）。段は**大きさと文字の濃さ**で作る。**例外は無い**（サイトタイトルを 700 にしていた時期があるが 2026-09-05 に 400 へ戻した）。
- **字間 `--tracking`（0.03em）を本文・見出しに一律で効かせる**。この僅かな空きが手本の空気感の要。
- **行間は広い**: 本文 1.9〜2.0、見出し 1.7。
- 級数（実測に合わせた最大値）:

| 役割 | サイズ |
|---|---|
| 単語詳細の h1 | 24px |
| ホームのヒーロー見出し | 24px |
| ページ見出し | 21px |
| セクション見出し | 15–17px（色は `--text-muted`） |
| 一覧の語 | 17px |
| ヘッダーのサイトタイトル | 16px（太さは本文と同じ 400） |
| 本文 | 15–16px |
| 補足・ラベル・メタ | 12–13px（**11px 未満にしない**） |

- **等幅（`--font-mono`）の用途は 2 つだけ**: ①「機械が読む値」（ローマ字・母音/文字種パターン・JSON・IP・桁揃えの数値）、②**§5.8 の英字ラベル（標識）**。日本語のラベルには使わない。
- **「図」として置く英数字**（線だけの巨大な数字）だけ `--font-display` + `font-weight: 700` + 負の字送り（-0.05em）を使う。**本文の書体・太さには一切影響させない**。
- ふりがな（`rt`）は `--text-subtle` の 12px。色を付けない。
- 数値は `font-variant-numeric: tabular-nums`。**ゼロ埋め（`01`）はしない**。

## 3. 面・罫線・角丸・余白

| 要素 | 表現 |
|---|---|
| 囲い | **罫より「淡い面（`--bg-soft`）＋大きな角丸」を優先**する。ただし**縦に積むときは面を閉じず、全幅の帯にする**（下記） |
| 細罫 | `1px var(--border)`。表・行の仕切り・セクション見出しの下 |
| **章の罫** | `1px var(--text-muted)`（濃い罫）。**サイト全体で下記の場所だけ** |
| セクション間 | `--space-7`(64px) 〜 `--space-8`(96px) |
| ページ最大幅 | `--content-width` = **800px**。読み物（About・本文）は `--reading-width` = **640px** |
| ヘッダー | 罫も影も持たず、**追従（sticky）もしない**。幅だけ 1040px まで許す |
| ヘッダー / フッター | `--bg-soft` の帯。白い本文を上下から挟んで境目を作る |
| 地 | **白（`--surface`）。方眼・テクスチャ・画像は敷かない** |

- **角丸のスケールは 4 段**: `--radius-sm`(6px) / `--radius`(12px) / `--radius-lg`(20px) / `--radius-pill`。
  カードは 20px、ボタン・タグ・バッジは**全丸（ピル）**。
- **2px 以上の罫は引かない。** 現在地の下線も使わない（色の濃さで示す）。
- **面は 3 段だけ**（2026-09-03。地をわずかに沈ませ、区画の色を分けるための構成）。

  | 面 | 値 | 役割 |
  |---|---|---|
  | `--surface` | `#FFFFFF` | **地 ＝ コンテンツの面**。`body` の背景そのもの |
  | `--bg-soft` | `#E6EBF2` | **ヘッダーとフッターの帯**、行の hover、囲い（`.word-flavor` など）、コード面 |
  | `--bg` | `#EFF2F6` | ボタン・タグの塗り、`--text` で塗った面の上の反転文字色 |

  **色を持つのはヘッダーとフッターだけで、そのあいだは白 1 枚**（2026-09-04 オーナー指示「ヘッダーとフッター以外は背景を白色に。ヘッダーとの境目が現在だとわからない」）。
  上下から `--bg-soft` の帯で挟むことで、**罫も影も引かずに境目が出る**。

  **本文に面を敷く案は 2 通り試したうえで、どちらも取りやめた**（2026-09-04。①区画ごとに白と地を交互 ②一覧の棚だけ `--bg`）。
  オーナーの困りごとは色の不足ではなく **「区画の境目が分かりにくい」「中身が宙に浮いて見える」** ことだったため、**色ではなく罫で解いた**（§5.2）。
  面を足すと平坦になるという §3 の元の懸念もそのまま生きている。

  手本「ただ、そこ」を CSS から採寸したところ、
  **手本は背景色をほとんど使っていない**ことが分かったため。`background` を持つのは `body`（白）／`.piece-grid`（`#cdd0cd`）／`.site-footer`（`#0a0a0a` のベタ）**の 3 つだけ**で、
  構造は面ではなく **ほぼ真っ黒な 1px の罫**（`--rule: #0a0a0ae0`）が作っている。色相も無彩色ではなく**わずかに緑み**（`#f1f2f0` / `#cdd0cd` / `#6e726e`）で、
  うちの青み（sizu.me 由来）とは別系統。**移すのは「白のヒーロー → 色のついた一覧の棚」という縦の構えだけ**にして、黒罫と緑みは移さない。ヘッダーに `--bg` を使うと白との差が ΔRGB 16 で下限 19 に届かないため、フッターと同じ `--bg-soft`(Δ25) に揃えてある（実測）。
  地が白になったぶん、**白い面（`--surface`）で囲っていた区画は輪郭を失う**。小さいものは `--bg-soft` の面に、面積の大きいものは 1px `--border` の囲いに置き換える（`.word-flavor` / `.sense-card` / `.rank-board` がこれに当たる）。

  **段を 3 つより増やさない。** 増やすと「どの面が何を意味するか」が読めなくなる。

- **並んだ要素どうしの罫は `border` で作らない**（2026-09-06 オーナー指示）。**親を罫の色で塗り、各要素を面の色で塗って、`gap: 1px` の隙間を境界線として見せる**。
  ```css
  .list { display: grid; gap: 1px; background: var(--border); }
  .row  { background: var(--surface); }   /* 面の上に載るなら --bg-soft */
  ```
  見た目は `border-top` と同じだが、**先頭/末尾だけ線を消す `:first-child` / `:last-child` / `+` セレクタも、狭幅での打ち消しも要らない**。
  - **角丸を持たせない**。隙間が 1px しかないので、角が丸いと四隅で親の罫色が余計に覗き、線が途切れて見える。
  - hover は面の色が変わるだけで、隙間の線はそのまま残る。
  - **各行の背景は「その要素が載っている面の色」に合わせる**（白地なら `--surface`、`--bg-soft` の面の上ならその色）。
  - 適用済み: `.entry-list`（単語一覧）/ `.rank-list`（ランキング）/ `.stats-bars`・`.feature-rank`・`.stats-wall__list`（統計）/ `.sense-attrs`（単語詳細の関連データ）/ `.sheet`（ホームの区画）。
  - **この手が使えないもの**（`border` のまま残す）:
    - **単独の区切り線**（`.sheet` の章の罫、`.entry-toolbar` の上下罫、`.site-footer__bottom`、`.page-header` の下罫）。要素と要素のあいだではなく、ひとつの要素の縁に引く線なので `gap` では作れない。
    - **`<table>`**（`.data-table` / `.bulk-review__table` / `.request-table`）。`gap` が効かない。
    - **`.search-form`**。直下に `fieldset` / `.field` / `.search-actions` が混在し、送信ボタンの上だけ章の罫（`--text-muted`）で締める規則（§5.6）があるため、`gap` にすると罫が二重になる。

- **ただし、面は「囲い」ではなく「地層」にする**（2026-09-03 オーナー指摘「面に乗せるとコンテンツが浮いて一体感がなくなる」）。
  同じ `--surface` でも、**角丸で四辺を閉じた面を縦に並べると閉じた図形が島のように散らばり**、ページが 1 つのものに見えなくなる。
  面が要るなら**画面端まで届く帯（`.sheet` / `.band`）として敷く**。帯は左右に輪郭を持てないので、原理的に島にならない。
  - 区画どうしは**面の色を変えずに全幅の細罫だけで割る**。余白で割ると、罫が無いぶん一体感は出るが区画の切れ目が読めなくなる。
  - **1 ページに敷く紙は 1 枚**。紙を 2 枚に割った時点で、それは大きなカードが 2 枚並んでいるのと同じ。
  - 現在この組み方をしているのは**ホームだけ**（`main.container--flush` ＋ `.band` / `.sheet`、§5.2）。
    他のページは従来どおり `--content-width` のコンテナに中身を置く。
- **立体（影）は使わない。** 区画は**面の色と 1px の細罫と余白**だけで示す。
  - **ドロップシャドウで押し出す“カード風”は禁止**。
  - **ニューモーフィズム（二方向の淡い影で膨らませる手法）は試作の結果、不採用**（2026-09-03 オーナー判断）。
    **配色（沈んだ地＋3 段の面）だけを残し、影・ベベル・「浮く/沈む」の作り分けはすべて撤去した。再提案しない。**
- **影を使ってよいのは「実際に浮くもの」だけ**（ナビのプルダウン、モバイルのドロワー）。`--shadow-soft` / `--shadow-pop`。
  カード・一覧・表・ボタン・入力には落とさない。
- 一覧やリストは**区切り線を引かない**。行の間は余白で離し、hover のときだけ `--bg-soft` の面が敷かれる。
- **額装（`.masthead` / `.page-header--word`）**: ひと区画を 1px `--border` で囲い、**内側を縦罫で「本文」と「数字」に割る**。
  使ってよいのは**ホームの看板と単語詳細のヘッダーだけ**。ページ全体を枠で囲まない。
- **罫は二層で持つ**（2026-09-03 の実測。手本「ただ、そこ」は淡い縦罫 1.31:1 と**濃い横罫 14.74:1** の二層を持っていた）。
  淡い罫（`--border` = 1.25:1）だけだと**引っかかる稜線がゼロ**になり、ページが白飛びして目が滑る。
  そこで**「章を分ける 1 本」にだけ `--text-muted`（白地 5.9:1）を罫の色として使う**。適用は次の場所だけで、
  増やすと途端に「囲みだらけ」になる:
  1. ページ見出しの下（`.page-header:not(.page-header--word)`。単語詳細はレールの縦罫が骨格なので引かない）
  2. 一覧のツールバーの上辺（`.entry-toolbar`）
  3. ランキングの切替タブの上辺（`.rank-tabs`）
  4. 検索の送信ボタンの上辺（`.search-actions`）
  **黒（14.74:1）までは濃くしない。** `--text-muted` で止めるのが「しずか」との折り合い。

## 4. インタラクション

- **transition は 160ms（`--transition`）**。動きで飾らない。
- **リンクは色を変えない**。`base.css` の `a` は `color: inherit` ＋ **細いグレーの下線**（`--border-strong`、offset 5px）で、hover で下線が濃くなる。
  ナビ・一覧の行・カードなど「下線を出したくない」リンクは各コンポーネントで `text-decoration: none` にし、**hover は面か文字色の濃さ**で示す。
- **色を反転する hover は、選択状態にだけ**使う（チップ・50音セル・タブ・主要ボタン = `--text` のベタ ＋ `--bg` の文字）。
- 現在地（グローバルナビ・管理サブナビ）は**文字色を `--text` に濃くするだけ**。下線も面も足さない。
- `::selection` は `--bg-tint`。`:focus-visible` は `--text-muted` の 2px アウトライン（消さない）。
- 入力の focus は枠が `--text-muted` に変わるだけ。リング（box-shadow）は付けない。

### 5.2 ホーム（1 枚の紙として組む）
**ホームだけは面で囲わず、画面端まで届く帯（`.band`）を縦に積んで組む。**
区画ごとに角丸の面を置いたところ「コンテンツが浮いて一体感がなくなる」（2026-09-03 オーナー指摘）ため、§3 の「地層」に組み直した。

- `main` に `container--flush`（幅と左右の余白を外す）を差し込み、中身は `.band > .band__inner`（**`--content-width` = 800px**・中央寄せ）で受ける。
  **ヘッダー（1040px）に合わせて 1040px まで広げた時期があったが、区画が横に伸びて中身が間延びしたため取りやめた**（2026-09-04 オーナー指示）。
  ヘッダー・フッターと本文カラムの左端は揃わないが、手本も揃えていない（sizu.me 290px・mud 763px ずれ。実測）。
- **面は白 1 枚のまま。区画は「罫の格子」で組む**（2026-09-04 オーナー指示「やっぱり背景を全部白色に戻しましょう。各コンテンツとその境界が分かりにくい／`band__body` の各コンテンツが浮いているのが気になる」）。
  罫は 3 本だけで、いずれも `--border` の 1px。**淡くて邪魔をしないが、組みの骨格は立つ**という配分にしてある。

  | 罫 | セレクタ | 役割 |
  |---|---|---|
  | 章の罫（`--text-muted`） | `.sheet` の `border-top` | 看板と本文の切れ目。ここだけ濃い（§3 の二層の罫） |
  | 区画の横罫 | `.sheet .band + .band` | 区画どうしの境目。**画面端まで通す**ので「地層」の重なりとして読める |
  | **袖の縦罫** | `.sheet .band__body` の `border-left` | 袖と本体を分け、**区画をまたいで同じ位置に立つ 1 本の柱**になる |
  | **区画の左右の縦罫** | `.sheet .band__inner` の `border-inline` | 標識の左と導線の右に立て、袖の柱と合わせて**縦罫 3 本で紙を額に収める**（2026-09-04 オーナー指示） |
  | 見出しの横罫 | `.band__head` の `border-bottom` | 見出しと中身を地続きにする（手本の `.archive-control` と同じ） |

  **縦罫がいちばん効く**（2026-09-04 オーナー指示「`band__body` の各コンテンツが浮いている」→「もうちょっと自由に伸び伸びと罫線を引いて」）。
  §5.2 は袖を「縦に長い 1 本の索引の背」と呼んでいたが、罫が無いあいだは背に見えず、中身が宙に置かれて見えていた。

  - **縦罫は区画の全高に通す**。そのため上下の余白は `.band__inner` ではなく `.band__gutter` / `.band__body` がそれぞれ持つ（`padding-block`）。
    宙で途切れると「切り株」に見えて、かえって浮く（§5.4 で単語詳細のレールについて確かめたのと同じ）。
  - 横罫と縦罫が交差して**格子**になる。手本「ただ、そこ」が作品グリッドを黒の 1px で格子に割っているのと同じ組みで、**色は使わずに罫だけで行う**。
  - **767px 以下では縦罫を 3 本とも外す**。1 カラムに畳んで袖が本体の上へ回るので袖の柱は意味を失い、
    左右の額もカラムが画面幅いっぱいになるぶん**画面の縁に貼り付いて見切れたように見える**。横罫だけで割る。上下の余白も `.band__inner` 側へ戻す。
  - この組み方をするのは**ホームだけ**。一覧・詳細の本文は白のままにする。
  - **罫をさらに「伸び伸び」引く案は試作のうえ戻した**（2026-09-04）。`main` に絶対配置して印から紙の下端まで縦罫 2 本を貫通させ、
    中身が罫をまたぐに任せる組み（手本の `.intro:before` と同じ手）だったが、オーナー判断で**区画ごとの縦罫に戻した**。
    **罫は区画の中で完結させる**（紙全体を貫く線は持たない）。
- **各区画は左に 132px の袖（`.band__gutter`）を持つ**。ここに英字の標識（§5.8）だけを置き、右の `.band__body` に見出しと中身を入れる。
  標識が本文の頭に割り込まなくなり、**縦に長い 1 本の索引の背**のように読める。狭幅（767px 以下）では袖が上に回り込んで 1 カラムになる。

置くものは 4 つだけ。

1. **印（`.band--mark`）**: ページの一番上に、**サイト名の読み「ナガイコトバノデータベース」を五十音の円環で一筆書きにした線画**（`.ring-art--mark`、172px、**中央**）を 1 つだけ置く。手本（しずかなインターネット）が最上部にロゴの図を置くのと同じ役割。円の外側を標識「NAGAI KOTOBA DATABASE」が回るので、**キャプションは付けない**（§5.9）。
2. **看板（`.band--hero` + `.masthead`）**: 面も枠も持たず、地の上に直接置く。**手本と同じく 1 列の中央揃え**で、上から順に積むだけ（2026-09-04 オーナー指示。それ以前は縦罫で左右に割る 2 カラムだった）。
   - **見出し「長い言葉を探す。」→ 一行の説明（`max-width: 30em`）→ 丸い検索バー（高さ 52px・`max-width: 560px`・ピル・細枠）→「詳細検索はこちら →」**
     標識はここには置かない（`NAGAI KOTOBA DATABASE` は印の外周へ、`EST. 2026 / JAPAN` はフッターだけに残した）。
   - 列の最後に **`.masthead__figures`** を置き、**ここだけ左右 2 列**にする（列の終わりを示すため）。検索からは `--space-8`(96px) 離して切る。
     - 左＝**収録語数を線だけの巨大な数字**（§5.9。ページ中でいちばん大きい `clamp(56px, 7vw, 88px)`）＋ `WORDS COLLECTED`
     - 右＝**そのほかの数**（`.stats-grid--rows`）。ラベル左・値右の等幅 11px の行を積み、**縦罫（`--border`）で左と分ける**。罫は区画の高さいっぱいに通す。
     - 出す数は **語義数 / ジャンル数 / 最長の読み / 今月の新収録数**。**「最長の読み」は下の「読みが長い言葉」の 1 位と必ず同じ値**にする（別々に数えると片方だけ古い値が出て食い違う。テストで縛ってある）。
     - 560px 以下では 2 列をやめて縦に積み、縦罫も外す。
   - 縦のリズム（1280px 実測）: 印 → 24 → h1 → 16 → 説明 → 40 → 検索 → 24 → 詳細検索 → 96 → 数 → 64 → 紙。
3. **今日の一語**: 紙の最初の区画。左に語・読み・意味、右に**その語の読みを五十音の円環で一筆書きにした線画**（§5.9）。
   - 意味の下に**その語の関連データ**を置く（2026-09-04 オーナー指示「情報が少ないので賑やかしが欲しい」）。
     **ジャンルのパンくず**（`shared/_genre_path`）と、**丸タグの行**（エンティティ / 品詞 / 語種 / 読みの文字数 / モーラ数 / 先頭文字 / 末尾文字）で、
     **どれも単語一覧の絞り込みへの実リンク**にする（§5.5）。数を並べるためではなく「ここから辿れる」ことを見せるための区画。
     先頭・末尾文字のタグは**「先頭 バ」のようにラベルを添える**（文字だけ置くと何の値か読めない）。
     マスタは `HomeController#featured_word` で先読みする（1 語ぶんとはいえ個別に引かない）。
   - 円環の**標識の 2 行目に弦の交差回数**（`9 CROSSINGS`）を置く。§5.9 の「数値は必ず併記し、長さだけで情報を伝えない」を線画側でも守るため
4. **2つのリスト**（最近追加 / 読みが長い）: 横に並べず**縦に積む**。行は hover で面が敷かれる

- 各区画の見出しは**日本語見出し（`.section-title__ja`）と、右端の「一覧へ →」だけ**（`.band__head`）。英字の標識は袖が持つ。
- **ホーム以外にこの組み方を広げない。** 帯は「入口だから許される」贅沢で、一覧や詳細でやると読む位置が定まらなくなる。

### 5.3 一覧・検索結果
- **一覧は面を持たず、行を 1px の罫で仕切るだけ**（`.entry-list`）。
  2026-09-03 に「白い面に載せる」方式へ変えたが、**本文の地が白になった今は白い面に載せても差が出ず**、
  罫の格子で組むトップとも雰囲気が食い違うため、面（枠・角丸・内側の余白）を外した（2026-09-06 オーナー指摘）。
- **行の罫は `border-top` で作らない**（2026-09-06 オーナー指示）。**親を罫の色で塗り、各行を面の色で塗って、`gap: 1px` の隙間を境界線として見せる**。
  ```css
  .entry-list { display: grid; gap: 1px; background: var(--border); }
  .entry-row  { background: var(--surface); }
  ```
  見た目は `border-top` と同じだが、**先頭行だけ線を消す `+` セレクタも、狭幅での打ち消しも要らない**。
  この組みでは**行に角丸を持たせない**（隙間が 1px しかないので、角が丸いと線が途切れて見える）。hover は面の色が変わるだけで、隙間の線はそのまま残る。
- **1件 = 2 段 2 列**（`.entry-row` は grid）。**左列に見出し語（17px）→ 読み（13px）、右列に分類・種別 → 文字数**。
  - 3 段（語 → 読み → 分類・種別・文字数）に積んでいたのを 2 段に畳んだ。
    実測: **1 行 109px → 65px、100 件のページ全長 12,244px → 7,765px（13.6 画面 → 7.8 画面）**、
    1 画面目に見える件数は 3〜4 件 → **7 件**（2026-09-06 オーナー指摘「縦に情報を積んでいるせいで一画面の情報量が落ち、最下部までのスクロール量が大きい」）。
  - 行送りは本文（1.9）より締める（見出し語 1.45 / 読み 1.5）。100 行が縦に並ぶ面では、行送りがそのまま総スクロール量になる。
  - **右列には上限（46%）を持たせる**。`auto` のままだと長い分類名が幅を食い尽くし、**左列が潰れて見出し語が 1 文字ずつ縦に折り返す**（2026-09-06 に狭幅で実測）。
  - **600px 以下では 2 列をやめて縦に積む**（見出し語 → 読み → 分類 → 文字数）。2 列に割る幅が無く、同じ潰れが起きるため。
- ページ頭のレール（`.page-header__rail`）は、左の見出しより背が高くなりやすく、余ったぶんがそのままヘッダー下の空白になる。
  一覧が始まる位置を上げるため、**数字と線画の間隔（`--space-5`）と線画の大きさ（104px）は詰めてある**。
- 行は `--radius` の当たり判定を持ち、hover で `--bg-soft` に沈む。**矢印などの装飾は置かない**。
- 一覧の頭のツールバー（`.entry-toolbar`）は**上下 1px の罫で挟んだ帯**にし、件数の右に `.entry-range`（等幅 11px）で **`001–100`** を出す。「いま何件目を見ているか」を数えられるようにするための目盛りで、手本「ただ、そこ」の `001–022 / 022` に当たる。
- ジャンルのパンくずは**常に「中 › 小」に畳む**（カラムが狭いため。大分類への導線はジャンル一覧と単語詳細が担う）。

### 5.4 単語詳細
1. パンくず → **2 カラムのヘッダー（`.page-header--word`）**。

### 5.5.1 ランキング
- 1 枠 = `--bg-soft` の角丸カード。**切替タブは上下 1px の罫で挟んだ帯**にし、タブ自身の枠線は持たせない（選択中だけ `--text` のベタ）。
- 見出し行の右に、**その板の 1 位の値を線だけの数字**（§5.9）＋ `MAX <単位>` を置き、`--border` の縦罫で仕切る。
  板は切替で**常に 1 枚しか出ない**ので、画面に出る巨大数字は 1 つだけ。
- **順位は面で塗らない**。等幅 12px で `--text-subtle`、上位 3 位は `--text-muted`、1 位は `--text` と、文字の濃さだけで段を作る。
  あわせて **1 位の「値」だけ `--text`** まで濃くする。（同率 1 位が複数あるとベタ塗りが連続して誤読を招くため、塗りは廃止した）
- 行は 1px `--border` で仕切る（最終行は引かない）。板は高さ 900px 級の面になるので、区切りが無いと10行が平坦に流れる。
- ゼロ埋めしない。

### 5.6 フォーム / ボタン / テーブル / ページネーション
- **入力は細枠の角丸ボックス**（`--border-strong` + 12px + 白地）。focus は枠の色が変わるだけ。
  モバイル（767px 以下）ではフォーム部品を 16px 以上にする（iOS の自動ズーム対策）。
- **ボタンは丸いピル**（白地 + 1px `--border-strong` + 高さ 40px。`.btn--sm` 32px、`.btn--icon` 30px）。hover は `--bg-soft`。
  塗りは主要 CTA（`.btn--primary` = `--text` のベタ + `--bg` の文字）だけ。
- **検索フォームは面を持たない**。13 の条件を `1px var(--border)` の細罫で上下に仕切り、送信ボタンの上だけ章の罫（`--text-muted`）で締める。
  （淡い面を全高の 7 割に敷くと、条件が平坦に流れて「どこを見ればいいか」が消える。面を足すのではなく**外す**のが正解だった）
- エラーは `--danger` の文字＋細枠（背景は塗らない）。
- テーブル = ヘッダ下と行に `1px var(--border)`。ページネーションはピルのボタン。

### 5.6.1 恒久ページ（About・プライバシー）の本文（`.prose`）
- **横幅は `--reading-width`（640px）**。読み物なので一覧より狭く組む。
- **章の見出し（h2）の下に 1px `--border` の細罫を引く**（§3 の「細罫＝セクション見出しの下」）。
  h2 が等間隔に並ぶだけだと、どこで話題が変わるのか読めない。**濃い章の罫（`--text-muted`）は §3 の 4 箇所だけなので、ここは淡い罫で止める**。
- **問いと答えの差は「大きさ」と「文字の濃さ」で作る**（太字は使わない）。FAQ は **質問（h3）＝ 16px の `--text` / 答え（p）＝ 15px の `--text-muted`**。
  問いの上は `--space-6` 空けて、問答のかたまりを見せる。
- **ページ内もくじ（`.page-toc`）は試したうえで不採用**（2026-09-09 オーナー判断）。`--bg-soft` の面に章題を 2 列で並べる形で作ったが、
  本文の頭に「もう一つの見出しの束」が挟まって、ページの入口が重くなる。**章が多くても、もくじは置かない。**
- **図・イラストも置かない**（§5.7）。恒久ページは**文章と余白と細罫だけ**で組む。

### 5.7 図版（写真は置かない / About には図を置かない）
- 手本（TOFT / mud / ただ、そこ）はいずれも**図版が雰囲気の大きな部分を占める**。ただし手本の図版は**すべて撮影ではなく作図**なので、
  こちらも**図版が要るなら線画で用意する**（§5.9）。線画なら素材待ちにならず、実データから描けば嘘もつかない。
- **写真プレースホルダ（`.image-slot`）は全廃した**（2026-09-09）。「○○の画像を挿入」の破線枠を置いておく方式は、
  ホームの写真 4 枚の帯（`.image-strip`）→ 撤去、About のリード直下の 1 枠 → **撤去**、で置き場所がゼロになったため、
  partial `shared/_image_slot` と `.image-slot` の CSS ごと削除した。
  - **再導入しない。** 永久に埋まらない破線枠はページの入口を占領するだけで、実素材が入る当てのないまま「未完成の枠」を見せ続けることになる。
  - どうしても写真でなければならない場所が出てきたら、枠ではなく `<img loading="lazy">` を直接入れる（先に枠だけ置かない）。
- **About（このサイトについて）に図・イラストは置かない**（2026-09-09 オーナー判断。**再提案しない**）。
  「サイトの成り立ちを表す線画」として**5 案を実データで試作し、すべて不採用**になった経緯があるので、同じ道を辿らないよう残す:

  | 案 | 中身 | 不採用の理由 |
  |---|---|---|
  | 渦（うず） | 収録語の読みを「・」で連ねて外へ向かう螺旋に載せる（`<textPath>`） | 図としては成立したが、About に図そのものが要らないという判断 |
  | 同心円 | 1 本の円が 1 語。分割数＝読みの文字数、半径＝長さ | 説明なしでは何の図か伝わらない |
  | 連なる円環 | サイト名の円環に収録語の円環が続く | ホームの印と絵柄が近く「同じものをもう一度」に見える |
  | 三工程の説明図 | 拾う → 読みを与える → 軸で引く の 3 円 | ラベル（英字＋日本語）を持つぶん装飾ではなく図解になり、静けさから外れる |
  | サイト名の読みの円環 | ホーム最上部の印と同じ図を 240px で | 一度は採用したが、**最終的に「このページに図は無し」**に落ち着いた |

  - **恒久ページは文章と余白と細罫だけで組む**（§5.6.1）。図を足すのではなく、章の切れ目と問答の段で読ませる。

### 5.8 標識（`.label-en`）
- 区画の頭に置く**等幅・大文字・12px の英字ラベル**（`--text-subtle` の塗り、字送り 0.04em）。「ただ、そこ」の `INDEPENDENT VISUAL ARCHIVE` と同じ役割。
  §2 の「補足・ラベルは 11px 未満にしない」を満たす最小。**袖もページ見出しも同じ組み**（横組み）。
  数字に添える単位（`.figure-caption`）も同じ 12px の塗り、図に添えるキャプション（`.ring-art__caption`）は一段小さい 10px。

- **標識を白抜き（アウトライン）にする案は試したうえで不採用**（2026-09-05 オーナー判断）。`.figure-number` と質感を揃え、
  ダークで白い線が浮くのをアクセントにする狙いだったが、**最終的に塗りへ戻した**。同じ道を辿らないよう、実測と経緯を残す。
  - **級数ごとに適正な線幅が違い、幅が狭い**。12px での実測（線の画素そのものを測ったもの）:
    0.5px=2.53 ✗ / 0.7px=3.34 ✗ / **0.85px=4.72 ✓** / 1px=5.80 だが**塗り潰れて白抜きに見えない**（太字に見え §2 に反する）。
    成立するのは 0.85px 付近だけで、**10px には使えない**（溶けるか潰れる）。
  - **大きくすると別の問題が次々に出る**: 16px 横組みは成立（5.80）。20px の 1 語 1 行の縦積みは袖では柱になるが、
    ページ見出しでは `PAGE 1 / 15` が「1 /」「15」に割れて**スラッシュが行末に残る**。
    30px ＋ `.figure-number` の書体では、級数を `clamp(44px, 5.5vw, 68px)` にできない
    （最長語 `RECENTLY`/`READINGS` が **332px** になり袖 152px を溢れて**本文に重なる**）。
  - **測り方の教訓**（白抜きを再検討するときは必ずこれで測ること）:
    - **白抜きは「線の画素そのもの」を測る**。背景から十分離れた画素だけを抜き出して平均する。細い線はアンチエイリアスで薄く溶けるので、
      指定した色（`--text` = 14.51:1）はまったく当てにならない。「暗い側 N%」で測ると**字面の大きさに結果が引きずられ**、級数を変えたときに比較できない。
    - **塗りは指定色で評価する**（WCAG の標準どおり）。塗りの文字を画素平均で測るとアンチエイリアスの縁を拾って不当に低く出る。
  - **白抜きを使うのは `.figure-number` だけ**に戻っている（§5.9）。
- **必ず日本語の見出しと対にする**（`.section-title` = 標識 ＋ `.section-title__ja`）。標識だけで意味を伝えない。
- 文言は `config/locales/ja.yml` の `labels.en.*` に集約。**翻訳ではなく「図」**なので日本語ロケールでも英字のまま。
- 使う場所: ページ見出しの上（`WORD INDEX` / `HEADWORD` / `SEARCH` / `KANA INDEX` / `GENRES` / `RANKINGS` / `STATISTICS` / `ABOUT` / `PRIVACY` / `REQUEST`）、ホームの各区画の袖、**ホーム最上部の印の外周**（§5.9）、フッター最下段の `EST. 2026 / JAPAN`。
  **ヘッダーには置かない**（ブランド名の右の `NAGAI KOTOBA` は撤去済み）。フッターの `NAGAI KOTOBA DATABASE` は標識ではなく**ワードマーク**（§5.1）。
- **これ以上増やさない。** 見出しのたびに英字を足すと、標識が背景化して効かなくなる。

### 5.9 図としての数字・線画
- **線だけの巨大な数字（`.figure-number`）**: `-webkit-text-stroke: 1px var(--text-muted)` ＋ `color: transparent`。
  `@supports` でフォールバック（未対応環境では `--border-strong` の塗り）を必ず用意する。
- 使ってよいのは**「そのページの性格を一言で表す数」だけ**: ホーム＝収録語数、単語詳細＝読みの文字数。
  順位や件数のような細かい数には使わない。
- **線画（`.ring-art`）**: 読みを五十音の円環で一筆書きにした図（`shared/_kana_ring_art`、`KanaRing` を再利用）。
  **実データから生まれる図**なので、装飾でありながら嘘がない。塗りを持たず、線は `--text-subtle` の 1px。
- **比べられる棒（`.genre-hub__bar`）**: 並んだ数値（ジャンルごとの公開語義数など）が比較できないときだけ、
  **72×2px の細い横棒**を数値の左に添える。トラックは `--border-strong`、塗りは `--text-subtle`。
- **ページ最上部の印（`.ring-art--mark`）**: ホームの一番上に、**サイト名の読み「ナガイコトバノデータベース」の円環**を 132px で 1 つだけ置く。
  手本（しずかなインターネット）が最上部に 81×101px のロゴの図を置くのと同じ役割（実測）。**キャプションは付けない**。
  - 描いているのは**サイト名そのもの**なので、ロゴでありながら他の円環（語の読み）とまったく同じ規則で生成される。**別途ロゴ画像を持たない**。
  - **中央に置く**（帯の左端に合わせない）。印だけは看板ではなく扉なので、ページの入口に据わって見えるほうを採る。
  - **印に描く読みは「ナガイコトバノデータベース」から変えない**（2026-09-04 オーナー判断）。
    交差が 9 本と少なく密度が物足りない件は検討済みで、**「いま収録している最長の読み」に差し替える案（交差 35〜47）／交点に実点を打つ案／
    収録語を重ね描きする案／全収録語の弦を集計する案**を実寸で試作したうえで、**すべて見送った**。印はサイト名から動かさないほうを採る。
    （重ね描き・弦の集計は 172px では網になって線が読めず、加えてローカルの開発語 1,683 件はダミーなので本番の実在語では絵が別物になる、という実測もある）
  - **「ナ」から「ス」へ一筆書きで描かれる**（円が浮かぶ 1.0s → 始点が点く 0.58s → 線を 2.2s で引く。合計 3.1s で止まり、繰り返さない）。
    **2026-09-04 に「線を引くところ」だけ速めた**（4.65s → 2.2s。オーナー指示）。**円が浮かぶ・始点が点くの 2 つと、外周の回転は元の速さのまま**にする（線を引く時間だけが長すぎたのであって、入りの間合いと永続する回転は変えない）。
    読みを 1 字ずつ辿る線なので**速度は変えず一定（`linear`）で引く**。ペンの動きに合わせるためで、`ease` を掛けると図形の演出になってしまう。
    - 実装は `stroke-dasharray` / `stroke-dashoffset` の CSS アニメーションだけ。**線の全長はサーバ側で出す**（`KanaRing.stroke_length` → `--ring-length`）ので、
      長さを測るためだけの JS（`getTotalLength()`）を持たない。Chromium と WebKit の双方で実測して確認した。
    - **`prefers-reduced-motion: reduce` では完成形をそのまま出す**（アニメーション定義ごと `no-preference` の中に置く）。
    - **ほかの円環（単語詳細・今日の一語）は動かさない**。動くのはページに 1 つだけ。
  - **外周を英字が回る（`.ring-art__arc` / `.ring-art__orbit`）**: 標識「NAGAI KOTOBA DATABASE」を、円の外側の弧（ベースライン半径 90）に沿わせて
    **80 秒で 1 周**させ続ける。`<textPath>` を「下から時計回りに 1 周するパス」の 50%（＝真上）に中央揃えで載せる。
    - **回転の中心は円環の中心**（`--ring-center` = `KanaRing::CENTER`）。`transform-box: fill-box` にすると、文字が弧の上側にあるぶん
      外形の重心が上へずれて回転が振れる（実測で 5 単位ずれた）。`transform-box: view-box` ＋ 中心指定にすること。
    - この標識は**看板から移したもの**で、`.masthead` 側には置かない（同じ英字を 2 箇所に出さない）。`EST. 2026 / JAPAN` は看板からは外し、フッター最下段だけに残す。
    - **弧のラベルは 1 ページに 1 つだけ**（`<textPath>` が参照する id を固定で持つため）。
  - **代わりに置いていた線画「折り返す帯」（`.ribbon-art`）は撤去した**（2026-09-04 オーナー判断）。1 本の帯が折り返し続けて枠外へ抜ける図で、
    「1 行に収まらない言葉」を直接表してはいたが、**サイト名の円環のほうが「実データから生まれた図」の原則に合う**。
- **線画は 1 ページに 1 枚 …… ただしホームの印だけは別枠**（ページの看板であって区画の図ではないため、「今日の一語」の円環と併存してよい）。
  図をこれ以上増やすと「実データから生まれた図」（`.ring-art` / `.genre-hub__bar`）の説得力まで飾りに見える。
- 線画に共通の作法: 実装は `viewBox` だけを持つ SVG。**色は `currentColor` か既定のクラスのみで、直書きしない**（ライト／ダークの反転が自動で付く）。
  濃さは **`--text-subtle`〜`--text-muted` まで**。`--text` まで濃くすると本文より濃い線になり、静けさの天井（太字を使わない方針）を破って絵だけが主張する。
  **正規化は最小値〜最大値を 20〜100% に写す**（最大値で割ると 143〜196 が 73〜97% に潰れて差が読めず、
  「情報を運ばない印」を足しただけになる。2026-09-03 の実測で判明）。**数値は必ず併記**し、長さだけで情報を伝えない。
- いずれも**色を持たせない**。図で目を引くのは形と余白だけにする。

## 6. アクセシビリティ & パフォーマンス

- **コントラストは WCAG AA 以上**（メタ文字の下限は `--text-subtle` = 白地 4.5:1）。`:focus-visible` を消さない。アイコンのみ操作要素に `aria-label`。タップ領域 ≥44px。
  この節は**自己申告ではなく実測で担保する**: 2026-09-03 に全ページを計測したところ、ライトのテキストの 88% が AA 未達（`--text-subtle` は 2.62:1）で、
  仕様書の記述に実装が追いついていなかった。**色を薄くする変更をしたら、必ず計測して確かめること。**
- 色だけで情報を区別しない（そもそも色をほとんど使わない）。ヒートマップは数値をホバー/直書きで補う。
- キーボードのみで一通り操作可能。ホバーでしか得られない情報を作らない。
- **web フォントを読まない**。重い CDN・JS を足さない。画像 `loading="lazy"`、importmap 維持。

## 7. レスポンシブ

- モバイルファースト。検証幅 375 / 390 / 768 / 1280px。横スクロール禁止（`main.container` の `overflow-x: clip` が backstop）。
- 2 カラム・定義グリッドは狭幅で縦積みに崩れてよい。幅の広い表・チャートは自身の `overflow-x: auto` の中でスクロールさせる。

## 9. ダークモード

**思想は「同じ静けさの明度反転」**。青みをわずかに残した無彩色の濃色。純黒にしない。**構造・余白・書体・角丸はライトと一切変えない**。

### 9.1 トークン（`tokens.css`）

値の定義は `:root` の `--dark-*` **1 箇所のみ**。適用は 2 つのセレクタが参照を差し替える。

| トークン | ライト | ダーク |
|---|---|---|
| `--bg` | `#EFF2F6` | `#191D22` |
| `--bg-soft` | `#E6EBF2` | `#12161A` |
| `--bg-tint` | `#E4ECF6` | `#1C2530` |
| `--surface` | `#FFFFFF` | `#232930` |
| `--text` | `#232A31` | `#E3E7EA` |
| `--text-muted` | `#5F6568` | `#98A0A5` |
| `--text-subtle` | `#63686C` | `#8F969B` |
| `--border` | `#DFE4EC` | `#2C3339` |
| `--border-strong` | `#C6CCD5` | `#454D55` |
| `--danger` / `--success` | `#B4453F` / `#3F7D5A` | `#D98079` / `#7FB79A` |
| `--chart` | `#6F8EA8` | `#7EA3BF` |
| `--shadow-soft` | ごく薄い影 | `none` |

- **色はトークン以外で直書きしない**。影・幕のような非色の視覚効果も、ダークで意味が変わるならトークンにする。
- **面の 3 段はダークでも同じ関係を保つ**（`--surface` が地より明るく、`--bg-soft` が地より暗い）。
- トークンを 1 つ足したら、`@media (prefers-color-scheme: dark)` 側と `:root[data-theme="dark"]` 側の**両ブロックに参照を追記する**。
- **`color-mix(..., transparent)` の塗りは両テーマで意味が変わる**（下に透ける地が反転するため）。濃さの上限を 45% に抑え、上に載る文字を `--text` にしておけば両方で読める。

### 9.2 切り替え

- **既定は OS 設定に追従**。ヘッダーのトグルを押したときだけ `html[data-theme="light"|"dark"]` が上書きし、`localStorage.theme` に残る。
- 初回描画のちらつきを防ぐため、**復元だけは `head` 内のインラインスクリプト**で行う。`theme-color` も CSS のトークンから読む。同期は `theme_controller.js`。
- **「自動に戻す」UI は置かない**（2 状態のトグルのみ）。JS 無効時は `noscript` でトグルを隠す。
- `color-scheme` を併せて切り替え、フォームコントロール・スクロールバーもブラウザ側で追従させる。
- **CSS だけで追従できない描画**（統計ページの Plotly など）は `theme:change` イベントを購読して色を差し替える。**その色も `getComputedStyle` で CSS トークンから読む**。

### 9.3 トグルの UI
- ヘッダー右端（狭幅ではドロワー内の最下部）。Phosphor の `moon` アイコン＋トグルスイッチだけ。
- トラックはピル、ツマミは円。ON は `--text` のベタ＋`--bg` のツマミ（**色は使わない**）。
- `role="switch"` ＋ `aria-checked` を同期し、`aria-label` は「ダークモード」。

### 9.4 適用範囲
- 公開側・管理画面・アノテーションコンソールの**すべてに適用**。

## 10. 管理画面（`/admin` 配下）

**公開側のトーンを引き継がない。**「しずか」は読み物のための設計だが、管理画面は**作業画面**であり、見る人はオーナー 1 人（2026-09-06 オーナー指示）。
**ページ構成・レイアウト・HTML は公開側と共有したまま、トークンの上書きだけで見え方を切り替える**（`app/assets/stylesheets/admin.css`）。
切り替えの起点は `<body class="is-admin">`（`request.path.start_with?("/admin")` で付ける）。個々のコンポーネント（`.btn` / `.tag` / `.admin-*`）には触らない。

狙いは 2 つだけ。

### 10.1 認知負荷を下げる

| 上書き | 公開側 | 管理画面 | なぜ |
|---|---|---|---|
| `--tracking` | 0.03em | **0** | 読ませる組みではなく、拾わせる組み |
| `line-height` | 1.9 | **1.5**（見出し 1.4） | 1 画面の情報量を上げる |
| `--text-muted` / `--text-subtle` | `#5f6568` / `#63686c` | **`#414850` / `#4a515a`** | 作業画面ではコントラストがそのまま速さになる |
| `--border` / `--border-strong` | `#dfe4ec` / `#c6ccd5` | **`#c4cad3` / `#98a1ad`** | 区切りを一目で取れる濃さまで上げる |
| `--radius` / `--radius-lg` / `--radius-pill` | 12 / 20 / 999px | **3 / 4 / 3px** | 角丸は輪郭を曖昧にし、形の判別に一手間かかる |

あわせて**画面に出す物を減らす**（描かない ＝ 認知負荷もレンダリング負荷も下がる）:
ヘッダーのブランドマーク（五十音円環の SVG）と 3 行の英字を消し、帯を低くする。本文の上下余白も詰める。
ログアウトとナビは残す（作業中に押すのはそれだけ）。

### 10.1.1 境界・アイコン・色（2026-09-07 オーナー指摘）

「グリッドの境界が見えない」「アイコンがあると分かりやすい」「色のメリハリがなく、各コンテンツや数字、文章を認識しにくい」への対応。

- **枠を持たせて区画を見せる**。`.admin-card` に 1px `--border`、hover で枠がアクセント色に変わる。
  カード下端の件数は `margin-top: auto` で押しつけ、細罫で本文と分ける（カードの高さが揃い、グリッドとして読める）。
- **表の見出し行は面で押さえる**（`.data-table thead th` に `--bg-soft`）。どこまでが見出しかを罫だけに頼らない。
- **ダッシュボードの各カードにアイコンを置く**（`pencil_simple` / `pen_nib` / `list_checks` / `books` / `bell_ringing` / `tag`）。
  文字を読まずに形で行き先を取れるようにするため。アイコンはアクセント色。
- **数字を主役にする**。統計はラベル（12px・`--text-subtle`）と数字（22px・`--text`）を上下に積んで対にし、上下の罫で挟む。
  ラベルと数字が同じ級数・同じ濃さだと、拾うのに一手間かかる。
- **色は 2 色だけ足す**。公開側は無彩色で通すが、管理画面では色が最短の手がかりになる。
  | トークン | 値 | 使い所 |
  |---|---|---|
  | `--admin-accent` | `#1d4ed8` | 押せるもの（リンク・アイコン・現在地のタブ） |
  | `--admin-warn` | `#b45309` | 未対応・要判断の件数 |
  状態色（`--danger` / `--success`）は公開側と共通のものをそのまま使い、**注釈の状態を 3 値で色分け**する
  （未対応＝`--admin-warn` / 保留＝`--text-muted` / 完了＝`--success`）。
  **破壊的な操作は色で分ける**（`data-turbo-confirm` を持つボタンを `--danger`）。行末の「annot.」と「del.」が同じ見た目だと押し間違える。
  **色を足すのは状態と操作だけで、装飾には使わない。**

### 10.2 レンダリング負荷を下げる

「高速アノテーション」が主題なので、**毎回の描画で払っているもの**を減らす。実測（`/admin/annotations`・637 要素）:

| | 公開側のトーン | 管理画面 |
|---|---|---|
| 角丸 16px 以上の要素 | **160** | **1** |
| 影のある要素 | 1 | **0** |

- **全称セレクタ（`.is-admin *`）で `transition` を潰す案は計測して取りやめた。**
  スタイル再計算のたびに全要素へマッチするぶん、**かえって重くなる**（強制レイアウト 30 回で 255.7ms / 撤去後 156.4ms を実測）。
  `transition` はそもそも hover したときだけ走るので、常時のコストではない。
- レイアウト時間そのものの比較は**ノイズが大きく有意差を出せなかった**（同条件で 162〜394ms とばらつく）。
  効いているかどうかは、上の「角丸・影の数」のような**描画物の量**で確かめること。
