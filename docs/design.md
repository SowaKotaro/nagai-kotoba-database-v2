## 0. 思想（1行）

**「読むための、しずかな場所」を、墨と白のメリハリで組む**。色は持たず、段は墨の濃さと太さで作る。目に入るのは言葉とデータだけにする。

- 手本は役割で分けている。迷ったら **実サイトを開いて見比べる**。
  - **地・墨・書体・太さ・字間・押せる部品と札の墨の枠・角・hover の動き = SANKOU!（sankoudesign.com）**。値の多くは実サイトから採寸した
    （2026-11-03 オーナー指示「背景色やフォント、フォントの重さなどを SANKOU! そのもののサイトを参考に」）。
  - **カラムの幅・余白・縦のリズム・最上部の印の役割 = しずかなインターネット（sizu.me）**。
  - **線画 = mud Inc.**／**標識（§5.8）と一覧の目盛り `001–100` = ただ、そこ**。
- **長時間の滞在と再訪で疲れないことが最優先で、情報は疎でよい。** 1画面に詰め込まず、見せる要素を減らして余白で離す。
- **禁止**: 書体で情緒を出すこと（明朝体は使わない）／和色（朱・臙脂）や紙色の地／彩度の高いアクセント色を UI に置くこと／
  ゼロ埋め番号（`01`。例外は一覧の目盛り `.entry-range` の `001–100` だけ。§2）／大文字＋広い字間の英字ラベル／巨大見出し×極小ラベルの級数対比／
  中間の太さ（500〜700。太さは 400 と 800 の 2 段だけ。§2）／
  グラデーション・ガラスモーフィズム・**ドロップシャドウで押し出す“カード風”**・**ニューモーフィズム**・派手なアニメーション・絵文字。
  （区画は §3 のとおり、地の上に置いた墨の枠の札と、細罫と余白で示す）
- **動くのは、マウスで触れたものだけ**。短く・小さく・1 度だけ動いて止まる（遊びの動き。型は §4 の 6 つと、ボタンの墨への反転だけ）。
  例外はヘッダーのサイト名で、触れている間だけ上限まで伸び続け、離すとゴムのように揺れて止まる（§4。2026-11-05 オーナー指示）。
  2026-11-04 オーナー指示「SANKOU! のように各所にアニメーションやマウスホバーでのアクションなど遊び心のある機能を付けましょう。
  ただし、アニメーションが多すぎて疲れてしまうような UI は駄目」。それまでは、hover は色と面の変化（160ms）に限っていた。
  **触れなくても動くのはホーム最上部の印だけ**（§5.9）。一筆書きは**1 度だけで止まり**、外周の英字だけが**80 秒で 1 周**し続ける。
  **スクロール連動・視差・フェードインの一斉発火・繰り返す動きは入れない**。
  例外は、タップで開閉する部品（ドロワー・「検索」のプルダウン・探し方のシート。§4）と、**上へ少し戻したときのヘッダーの出入り**（§5.1。
  スクロールの量に合わせて動くのではなく、向きが変わったときに 1 度だけ出入りする。2026-11-06 オーナー指示）。
- 装飾を足す方向には倒さない。**新しい要素を1つ足すなら、既にあるものを1つ削る。**

## 0.5 前提（技術・運用・パフォーマンス）

- **スタック**: Rails + ERB + Hotwire + importmap。**ビルドツールを入れない**。CSS は手書き（Sprockets、`tokens → base → layout → components → motion` の後に `annotate → candidates → admin`。**管理用の CSS も全ページで読まれる**。読み込み順と置き場所の実態の正は `app/assets/stylesheets/application.css` の冒頭）。JS は最小限。
- **権限/公開範囲**: 管理者（オーナー本人）だけが CRUD、他は閲覧のみ。**公開側にアカウント機能は作らない**。
- **パフォーマンス最優先**: **web フォントを一切読まない**（OS 標準のゴシックのみ）。外部 CDN・重い JS を足さない。
- デザイン案モック（`/admin/design_mocks`）は**削除した**（2026-09-07 オーナー判断。役目を終えたため。5 様式 × 3 ページの試作と専用 CSS・専用レイアウトを丸ごと撤去）。

## 1. カラートークン（これ以外の色は使用禁止）

`app/assets/stylesheets/tokens.css` の `:root` に定義。必ず `var(--token)` で参照。
**色は「地と墨」の 1 系統だけ**（SANKOU! の地 `#FAFAFA` と墨 `#2F2725`。面と罫の灰は、どれも墨と同じわずかに赤みのある色相）。**アクセントカラーを持たない。**
例外は 2 つだけ: 統計 §1 のワードクラウドの多色（`--cloud-*`）と、単語一覧で検索に当たった箇所の黄（`--highlight`。2026-11-10 オーナー指示「そっちの方がユーザーも見慣れてる」。§5.3）。

| トークン | ライト | 用途 |
|---|---|---|
| `--bg` | `#FAFAFA` | **地**（`body` の背景。SANKOU! と同じ）。`--text` で塗った面の上の反転文字、コンソールの操作バー（`.ann-actionbar`）、ホームの検索ボタン（`.hero-search__submit`）、`color-mix` の下地、モバイルのブラウザ UI の色（`theme-color`）も兼ねる |
| `--surface` | `#FFFFFF` | **札の白**（地より一段明るい。札 `.panel`・一覧の行・ボタン `.btn`・タグ `.tag`・チップ `.chip`・入力・プルダウン・狭幅のナビのドロワー） |
| `--bg-soft` | `#EBE9E7` | 一段沈めた面（行と押せる部品の hover・畳んだヘルプの中身・コード面。地との差 ΔRGB 19） |
| `--bg-tint` | `#E6E3E0` | 選択中・ハイライトの面（`::selection`・注釈の対象・タグの hover。地との差 ΔRGB 26） |
| `--highlight` | `#FFF3A0` | **単語一覧で検索に当たった箇所の面だけ**（`mark.search-hit`。蛍光ペンの黄。`--text-subtle` を載せて 5.4:1）。ダークは暗い黄土 `#3D320C`（同 5.3:1）。ここ以外で使わない |
| `--highlight-deep` | `#FBE36A` | 2 つ以上の条件が重なって当たった字（重ね塗り。`--text-subtle` で 4.7:1）。ダークは明るくすると淡い字が載らないので、明るさを保ったまま琥珀へ寄せた `#543800`（同 4.5:1） |
| `--text` | `#2F2725` | 本文・見出し・**墨の罫と枠**・墨のベタ（わずかに赤みのある黒。真っ黒にしない。地 14.0:1） |

| `--border` | `#E4E3E0` | 細罫（札の中の行・表・区画の仕切り。地との差 ΔRGB 26） |

| `--success` | `#3F7D5A` | 一致・完了・達成（札の白で 4.9:1。`--bg-soft` の上では 4.0:1 で届かないので、面の上に置かない） |
| `--chart` | `#8F8682` | チャートの塗りと、ホームの印の円（§5.9）。墨と同じ色相の中間の灰（地 3.4:1）。文字と UI の部品には使わない |
| `--scrim` | `rgba(47,39,37,.35)` | 狭幅のドロワーを開いている間、下のページを沈める幕（§5.1） |
| `--cloud-1`〜`8` | 下記 | **統計 §1 のワードクラウドの語別の色だけ**。ここ以外で使わない |

書体のトークンは 3 本: `--font-sans`（本文・見出し・**サイトタイトルを含むすべての和文**）／`--font-mono`（機械が読む値・§5.8 の標識）／`--font-display`（立てる数の欧文。§2）。

**原則**:
- **UI に色を置かない**。リンクは墨の下線、現在地と選択状態は墨のベタ（反転）、hover は面か墨への反転で表す（§4）。
- **淡さには下限がある**（2026-09-03 の実測で判明）。薄くしすぎると、文字は WCAG AA を割り、
  面と罫は「稜線」にならず、ページ全体が白飛びして目が滑る。**文字は最も弱い `--text-subtle` でも、載るどの面の上でも 4.5:1、
  それだけで境目を示す面・罫は地との差を ΔRGB 19 以上**確保する。これは意匠ではなく下限値なので、静けさを理由に下回らない。
  札の白は地との差が ΔRGB 5 しかなく、輪郭は墨の枠が持つ（§3）。下限は `test/assets/design_tokens_test.rb` が両テーマで測る。
  - **ΔRGB は、2 色の R・G・B それぞれの差の絶対値のうち最大のもの**（`max(|ΔR|, |ΔG|, |ΔB|)`。
    2026-10-03 オーナー判断）。本書とコードのコメントの ΔRGB は、すべてこの定義で数える。
    テスト（`test/assets/design_tokens_test.rb` の `delta_rgb`）も同じ式で測る（2026-10-08 に、差の合計から直した）。
- 赤と緑は「意味を持つとき」だけ（エラー / 達成）。文字と細枠にとどめ、面には塗らない。
- **多色を使うのは「統計 §1 のワードクラウド」だけ**（2026-09-10 オーナー指示。サイト唯一の例外）。
  色相は 8 つ（`--cloud-1`〜`8`）で、割り当ては**語そのもの**から決まる（`MorphemeCloud#palette_for`
  = CRC32。`String#hash` はプロセスごとに変わるので使わない）。収録が増えても同じ語は同じ色のまま。
  - **彩度はライト 30% / ダーク 34% に抑える**。これ以上上げると、墨と白の画面の中で語の色だけが光る。
  - **明度は「地に対して 4.6:1 以上」になるところまで落としてある**（実測値。`--chart` 自身は
    地 3.4:1 しかなく、文字色としては使えない）。ライト `#507694 #7E65AC #A4588D #A35F58
    #896D4A #5C7A42 #447D62 #437B79` ／ ダーク `#6C96B7 #9E87C4 #BF7DAB #BF847D #AE8A5B
    #739D4D #4FA17B #4D9D9B`。
  - **他の図には広げない**。ヒートマップ・ツリーマップ・遷移グラフは従来どおり無彩色 ＋ `--chart`。
- 濃さの表現（ヒートマップ等）は `color-mix(in srgb, var(--chart) N%, transparent)`。**N の上限は 45%**
  （それ以上濃くすると、ライト/ダークどちらかで上に載る文字が読めなくなる）。

## 2. タイポグラフィ

**本文と UI の書体は 1 本**（`--font-sans`）。SANKOU! と同じ並びで、欧文は Avenir Next、和文は Noto Sans JP → 游ゴシック Medium → ヒラギノ角ゴ
（`"Avenir Next", "Noto Sans JP", "Yu Gothic Medium", …`。web フォントは読まず、端末に入っているものを使う）。

**和文の書体はサイト全体で 1 本**（`--font-sans`）。ほかに持つのは、機械が読む値の等幅（`--font-mono`）と、立てる数の欧文（`--font-display`）だけ。
サイトタイトルに専用の書体（手本「ただ、そこ」から採寸した `--font-brand`）を当てていた時期があるが、
「イメージと違う」として本文と同じ `--font-sans` に戻し、トークンごと削除した（2026-09-04 → 05 オーナー判断）。
サイトタイトルは **20px**（2026-11-04 に 16px から上げた。太さと字間は §5.1。下の表と同じ値）。

- **太さは 2 段だけ: 本文の 400 と、見出し・強調・立てる数の 800**（SANKOU! と同じ。`h1`〜`h4` と `b`/`strong` は `base.css` で 800）。
  中間の太さ（500〜700）は使わない。段は、太さの 2 段に大きさと文字の濃さを重ねて作る。
- **和文を `palt` で詰めてから、字間 `--tracking`（0.08em）で一律に開ける**（`body`。SANKOU! と同じ組み方）。
  見出しは 0.06em、サイトタイトルは 0.04em に詰める。この広い空きが手本の空気感の要。
- **行間は広い**: 本文 1.9〜2.0、見出し 1.75（`base.css`）。
- 級数（実測に合わせた最大値）:

| 役割 | サイズ |
|---|---|
| ページ見出し（h1。単語詳細の見出し語・詳細検索・統計を含む公開側のすべてと、管理画面） | 28px |
| ホームのヒーロー見出し | 30px |
| 今日の一語の語 | 32px（767px 以下は 24px） |
| 語義の札の見出し語（`.sense-heading`） | 19px |
| 札の見出し（`.panel__title`） | 18px |
| 札の中の区画の見出し（統計の `.stats-subheading` など） | 15px（色は `--text-muted`） |
| 一覧の語 | 17px |
| ヘッダーのサイトタイトル | 20px（太さと字間は §5.1。管理画面も同じ） |
| 本文 | 15–16px（恒久ページの本文 `.prose` は 15px） |
| 補足・ラベル・メタ | 12–13px（**11px 未満にしない**。例外は 10px の `.vowel-graph__tick`） |

- **等幅（`--font-mono`）の用途は 2 つだけ**: ①「機械が読む値」（ローマ字・母音/文字種パターン・JSON・IP・桁揃えの数値）、②**§5.8 の英字ラベル（標識）**。日本語のラベルには使わない。
- **立てる数**（その面の主題になる数）は、欧文の `--font-display` の 800 で組み、単位を小さく添える。
  数だけのレール（単語一覧の件数・About の収録語数）56px／単語詳細のレールの読みの文字数 40px／ホームの数字の升 28px／統計の数字の壁 20px／順位表の値と、読みが長い言葉の文字数 18px／順位の角 14px。
  線だけの巨大な数字（`.figure-number`）は 2026-11-04 にやめた（§5.9）。
- ふりがな（`rt`）は `--text-subtle` の 12px。色を付けない。
- 数値は `font-variant-numeric: tabular-nums`。**ゼロ埋め（`01`）はしない**。
  例外は一覧の目盛り `.entry-range` の `001–100` だけ（§5.3）。順位・語義番号には使わない。
- **折り返しは語の切れ目に寄せる**（2026-11-04 オーナー指摘「説明文が変なところで折り返されている」）。字の切れ目で折ると、
  スマホで「データベ／ース」「公開語義の数で／す。」のように語の途中や最後の 1 字で割れる。組み方は文の種類で分ける。
  - **UI の説明文**（ページのリード・欄の補足・注意書き・奥付・統計の章の説明）と **About のよくある質問の問い**は、文ごとの文節の配列で `ja.yml` に持ち、
    `ApplicationHelper#phrased_sentences` が文ごとに行を分け、文の中は文節の切れ目でだけ折る（`.phrase-sentence`・`.phrase`）。
    meta description・llms.txt・構造化データ（FAQPage）はつないで使う（`.join`）。**新しい説明文もこの形で足す**。
  - **名前**（ジャンルの分類名・絞り込みの札の値・詳細検索の区画の見出し・恒久ページの章の見出し・ライセンス名とクレジット）は
    `ApplicationHelper#phrased_name` で、「・」の後ろ・「（」の前・空白でだけ折る。括弧書きの中（「(CC BY 4.0)」）の空白と「・」では切らない。
    切れ目の記号を持たない名前は、`ja.yml` に文節で分けた配列で持つ（プライバシーの章の見出し「収録リクエストで／受け取る情報」）。
    `word-break: keep-all` は使わない（WebKit が「（」の後ろで折った）。
  - **用語解説の例**は 1 つずつ塊にし（`ApplicationHelper#feature_examples`）、区切り（「　／　」）は前の例の塊に含める。
    1 つの例が収まらないときは、演算子（「 + 」「 → 」）の後ろ・「・」の後ろ・括弧書きの前と、括弧書きの中の句読点の後ろでだけ折る。
  - **データから組む文**（用語解説の定義・語義の意味・単語詳細のリード・About とプライバシーの本文）は文節を持たないので、
    `word-break: auto-phrase` と `text-wrap: pretty` に任せる。Chromium は語句の切れ目で折る。どちらも効かないブラウザ（Safari 18 など）は字の切れ目で折る（許容）。
  - 1 つの塊が幅に収まらないときだけ、塊の中で折れる。そのときも行の長さを揃え、行頭に「ー」や小書きのかなを置かない
    （`.phrase` の `text-wrap: balance` と `line-break: strict`。揃えないと 320px で「コンピュータアーキテクチ／ャ」と最後の 1 字が残った）。

## 3. 面・罫線・角丸・余白

**区画は、地の上に置いた札で組む**（2026-11-03 オーナー判断。SANKOU! にならった）。札（`.panel`）は白（`--surface`）の面を墨（`--text`）の 1px・角 8px で囲んだもので、
看板の検索バー・ボタンと同じ線で、ページの上から下までを組む（オーナー指示「しっかりしつつキャッチー」「検索窓周辺との雰囲気は統一して」）。

| 要素 | 表現 |
|---|---|
| 地 | `--bg`（`#FAFAFA`）。**方眼・テクスチャ・画像は敷かない**。ヘッダーとフッターも帯を持たず、同じ地に載る |
| **札** | 白（`--surface`）＋ 墨の 1px ＋ 角 8px（`--radius`）。札どうしの間は 24px（`--space-5`）。札の頭（`.panel__head`）は墨の罫 1px で中身と分ける |
| 細罫 | `1px var(--border)`。札の中の行・表・区画の仕切り |
| **章の罫** | `1px var(--text-muted)`。**レールの無いページ頭の下だけ**（下記） |
| **墨の罫** | `1px var(--text)`。輪郭を持たせる線（ヘッダーの下とフッターの上・札とその頭・押せる部品の枠・浮くもの。下記） |
| セクション間 | `--space-7`(64px) 〜 `--space-8`(96px) |
| ページ最大幅 | `--content-width` = **800px**。ページのリード（`.page-lead`）は `--reading-width` = **640px** で止める（恒久ページの本文は札の幅いっぱいに組む。§5.6.1） |
| ヘッダー / フッター | 帯も影も持たず、**追従（sticky）もしない**。ヘッダーの下とフッターの上に墨の罫を 1 本ずつ引き、本文を上下から挟む。幅だけ 1040px まで許す（§5.1） |

- **札の使い方**:
  - 公開側のページは、区画を札に収める（ホーム・単語一覧・単語詳細・収録リクエスト・ランキング・統計・探し方のページ・恒久ページ。§5.2〜§5.4・§5.5.1・§5.6・§5.6.1・§5.11〜§5.13）。
    札を積むか 1 枚にするかは中身で決める（1 本の並びは札で割らない。§5.2）。
  - 札の頭には日本語の見出し（18px）と、右端の小さいボタン（`.btn--sm`）だけを置く。英字の標識は置かない（§5.8）。
  - **札の中に枠を入れ子にしない**。札の中の行は細罫か `gap: 1px` の隙間で仕切り、区画は細罫で上下に分ける
    （墨で仕切るのは札の頭の下と、詳細検索の札の足の上だけ。§5.6）。行ごとに枠で囲むと、札の中に枠が入れ子になる（§5.12）。
    区画の中で部品を束ねるときは、墨ではなく淡い `--border` の枠にする（詳細検索のジャンル。§5.6）。
- **角丸のスケール**（SANKOU! の採寸値）: `--radius-sm` 4px（タグ・チップ・順位の角・ナビの項目・ホームの検索ボタン）／
  `--radius` 8px（札・ボタン・入力・検索バー・プルダウン）／`--radius-pill`（スイッチのトラックだけ。つまみの円と組になる形なので角を立てない）。
  `--radius-lg` は `--radius` と同じ 8px（管理画面も同じ。§10）。
- **2px 以上の罫は引かない。** 現在地の下線も使わない（墨のベタで示す。§4）。
- **面は 3 段だけ**（地・札の白・沈めた面）。選択の印の面（`--bg-tint`）は段に数えない。

  | 面 | 値 | 役割 |
  |---|---|---|
  | `--bg` | `#FAFAFA` | **地**。`body` の背景そのもの |
  | `--surface` | `#FFFFFF` | **札の白**。札・一覧の行・ボタン・タグ・入力・プルダウン・ドロワー |
  | `--bg-soft` | `#EBE9E7` | 一段沈めた面。行と押せる部品の hover、畳んだヘルプの中身（`.field-help__body`）、コード面 |

  札の白と地の差は ΔRGB 5 しかないので、**札の輪郭は面の差ではなく墨の枠が持つ**（ダークでは札の面と地が同じ色になる。§9.1）。
  **段を 3 つより増やさない。** 増やすと「どの面が何を意味するか」が読めなくなる。
  2026-11-03 までの「白 1 枚の地をヘッダーとフッターの帯で挟む」構えと、そのとき退けた案は [`history/design.md`](history/design.md) にある。

- **並んだ要素どうしの罫は `border` で作らない**（2026-09-06 オーナー指示）。**親を罫の色で塗り、各要素を面の色で塗って、`gap: 1px` の隙間を境界線として見せる**。
  ```css
  .list { display: grid; gap: 1px; background: var(--border); }
  .row  { background: var(--surface); }   /* 面の上に載るなら --bg-soft */
  ```
  見た目は `border-top` と同じだが、**先頭/末尾だけ線を消す `:first-child` / `:last-child` / `+` セレクタも、狭幅での打ち消しも要らない**。
  - **角丸を持たせない**。隙間が 1px しかないので、角が丸いと四隅で親の罫色が余計に覗き、線が途切れて見える。
  - hover は面の色が変わるだけで、隙間の線はそのまま残る。
  - **各行の背景は「その要素が載っている面の色」に合わせる**（札の上なら `--surface`、`--bg-soft` の面の上ならその色）。
  - 適用済み: `.entry-list`（単語一覧）/ `.rank-list`（ランキング）/ `.stats-bars`・`.feature-rank`・`.stats-wall__list`・`.stats-section__bodies`（統計。§5.13）/ `.sense-attrs`（単語詳細の関連データ）/ `.home-column__list`（ホームの 2 つのリスト）/ `.genre-hub`（ジャンルから探す）・`.feature-hub`（言語学的特徴から探す。どちらも §5.11）/ 詳細検索のジャンル（`.genre-filter`）と用語解説（`.field-help .feature-glossary`。どちらも §5.6）/ `.faq-list`（About の問答）・`.fact-list`（プライバシーの公表事項。どちらも §5.6.1）/ ナビの「検索」のプルダウン（`.nav-menu__panel`）と狭幅のドロワーのナビ（`.site-nav`。どちらも §5.1）。
  - **この手が使えないもの**（`border` のまま残す）:
    - **単独の区切り線**（札の頭 `.panel__head` の下罫。単語一覧では札の頭が `.entry-toolbar` を兼ねる。詳細検索の札の足 `.search-actions` の上罫。単語詳細では、語義の札の本文と関連データの行を分ける
      `.sense-attrs` の上罫と、しりとりの札の一言 `.related__lead` の下罫。プライバシーでは、本文の区画と公表事項の行を分ける `.fact-list` の上下の罫。
      狭幅のドロワーでは、頭 `.nav-drawer__head` の下罫・ナビの並びの終わりの罫・テーマの切り替えの行の上下の罫（§5.1）。
      ほかに `.site-footer__bottom`、`.page-header` の下罫）。要素と要素のあいだではなく、ひとつの要素の縁に引く線なので `gap` では作れない。
    - **`<table>`**（`.data-table` / `.bulk-review__table` / `.request-table`）。`gap` が効かない。
    - **`.search-form`**。直下に札の頭 / `.field` / 条件の区画 / `.search-actions` が混在し、送信の行の上だけ墨の罫で札の足を仕切る規則（§5.6）があるため、`gap` にすると罫が二重になる。

- **札は淡い面で浮かせず、墨の 1px の枠で輪郭を持たせる**。2026-09-03 には、角丸で四辺を閉じた淡い面を縦に並べると
  閉じた図形が島のように散らばり、ページが 1 つのものに見えなくなった（オーナー指摘「面に乗せるとコンテンツが浮いて一体感がなくなる」）。
  墨の枠は看板の検索バー・ボタンと同じ線なので、札を積んでもページの上から下までが同じ線でつながる。
  ホームは 2026-09-03〜11-03 のあいだ、面で囲わずに画面端まで届く帯（`.band` / `.sheet`）を 1 枚の紙として敷き、区画を細罫で割っていた
  （記録は [`history/design.md`](history/design.md)）。
- **立体（影）は使わない。** 区画は**札の墨の枠と、細罫と余白**だけで示す。
  - **ドロップシャドウで押し出す“カード風”は禁止**。
  - **ニューモーフィズム（二方向の淡い影で膨らませる手法）は試作の結果、不採用**（2026-09-03 オーナー判断）。
    **配色（沈んだ地＋3 段の面）だけを残し、影・ベベル・「浮く/沈む」の作り分けはすべて撤去した。再提案しない。**
- **浮くもの（ナビのプルダウン・モバイルのドロワー）も影を落とさず、墨の枠で輪郭を持たせる**（2026-11-04。
  この 2 つにだけ `--shadow-pop` を許していたが、ヘッダーとドロワーを札の組みに改めたときに外し、トークンも消した。§5.1）。
  ドロワーの下のページは、影ではなくスクリム（`--scrim`）で沈める。
  カード・一覧・表・ボタン・入力には落とさない。
- 一覧やリストの行の間の罫は **`border` で引かず、`gap: 1px` の隙間で見せる**（§5.3）。hover のときは `--bg-soft` の面が敷かれる。
- **レール付きのページ頭（`.page-header--rail`）**: ページの頭を縦罫（細罫）で「本文」と「数字・線画」に割る。
  レール付きの型を使うのは**単語詳細・単語一覧・About の 3 ページ**（2026-09-04 に単語詳細だけの
  `.page-header--word` から全ページ共通の型へ広げた。About は 2026-11-04 に収録語数を立てた。§5.6.1。
  ジャンル一覧のレールは 2026-11-05 に外した。§5.11）。**ページ全体を枠で囲まない**。
  単語詳細のレールは数と線画を積む（幅 160px。§5.4）。単語一覧と About のレールは数だけを大きく立て、列の幅を数の幅に合わせる
  （`.page-header--count`。§5.3）。
  この型のときは**下端に横罫を引かない**（縦罫が章の罫の代わりになる）。
- **罫は三層で持ち、濃さで役割を分ける**。淡い罫（`--border`）だけだと**引っかかる稜線がゼロ**になり、ページが白飛びして目が滑る
  （2026-09-03 の実測。手本「ただ、そこ」も淡い縦罫 1.31:1 と濃い横罫 14.74:1 の二層を持っていた）。
  1. **細罫**（`--border`）: 札の中の行・表・区画の仕切り、レールの縦罫。
  2. **章の罫**（`--text-muted`。地 7.6:1）: ページ見出しの下（`.page-header:not(.page-header--rail)`）だけ。
     レール付きの型はレールの縦罫が骨格なので引かない。一覧のツールバー・ランキングの切替・詳細検索の送信の行の上辺にも引いていたが、
     どれも札の頭と足（墨の罫）か墨の枠のボタンに移したので外した（2026-11-03〜04。§5.3・§5.5.1・§5.6）。
  3. **墨**（`--text`。地 14.0:1）: 輪郭を持たせる線（2026-11-03。SANKOU! にならった）。
     ヘッダーの下とフッターの上（§5.1）、札（`.panel`）と札の頭の下・詳細検索の札の足の上、
     押せる部品（`.btn`・`.tag`・`.chip`・ページ送り・ホームの検索バー・絞り込みの欄など）の枠、
     浮くもの（ナビの「検索」のプルダウンの枠・狭幅のドロワーの左端と頭の下。§5.1）。
  章の罫と、札の中を墨で仕切る罫は、上に挙げた場所から増やさない（増やすと途端に「囲みだらけ」になる）。

## 4. インタラクション

- **色と面の transition は 160ms（`--transition`）**。
  状態の変化を伝える短い動き: **タップで開閉する部品の動き**（2026-11-06 オーナー指示「ハンバーガーがバツになる時のアニメーション・検索の中のプルダウンの開閉・
  ドロワーそのものの動きも、少し工夫して入れてください」。2026-11-04 に外したハンバーガーの × への変形も、動きを付けて戻した）と、
  文字種トグルの状態ラベルのフェード（0.25s。ラベルは 3 秒で消える）、
  詳細検索の畳んだヘルプ（`.field-help`）の中身が見出しの下から伸びて出る動き（200ms・ease-out。**開くときだけ**で、閉じるときはすぐ畳む。§5.6）。
  `prefers-reduced-motion: reduce` で止めているのは、状態ラベルと畳んだヘルプの動きと、開閉の動き（下）と、下の遊びの動き（ほかも止めるかは、見た目が変わるので保留）。
  - **開閉の動きの型**（トークンは `tokens.css` の `--motion-open`・`--motion-close`・`--motion-pop`。開くときは出だしが速く着地がやわらかい 280ms、
    閉じるときは加速して抜ける 180ms。`--motion-pop` は終わりに少し行き過ぎて戻る 260ms）:

    | 部品 | 開くとき | 閉じるとき |
    |---|---|---|
    | ハンバーガー（900px 以下） | 上と下の線が真ん中へ寄って ±45° に倒れ、真ん中の線が消えて × になる（`--motion-pop`）。ドロワーとスクリムの手前に出て、そのまま閉じるボタンになる | × が三本線へ戻る |
    | ドロワー | 右から滑り込む。スクリムが薄れて出る。ナビの行とテーマの切り替えの**文字**が、上から 45ms ずつ遅れて、**透かさずに**（途中の薄い文字を出さない）順番が来た瞬間に現れ、右から 28px を、終わりに少し行き過ぎて戻りながら寄る（380ms。行の面は動かさない。行の隙間の罫が透けるため。2026-11-06 オーナー指示「ふわんと現れるより、パリッとした印象が欲しい」「早すぎて目で追えない。動きももう少し」）。畳んだ「検索」の中の行が開いて見えているときは、それも同じ並びで順に出す | 短く右へ抜ける。スクリムが薄れて消える。行は動かさない |
    | 「検索」の折り畳み（ドロワーの中） | 高さが 0 から伸びる。∨ が半回転する（`--motion-pop`）。配下の行が、ドロワーの行と同じ動きで上から順に出る（2026-11-06 オーナー指示「検索のプルダウンでも同じアニメーションを走らせると、統一感が出る」） | 高さが縮む |
    | 「検索」のプルダウン（広い幅） | 罫から札が吊り下がる: 上辺から下へ現れながら 8px 降りる。配下の行が、ドロワーの行と同じ動きで上から順に出る | 短く上へ畳む |
    | ホームの探し方のパネル（768px 以上） | 罫から札が吊り下がる（行は順に出さない。選択肢を「/」で流しているので、文字を寄せると並びが動く） | 短く上へ畳む |
    | ホームの探し方のシート（767px 以下） | 画面の下からせり上がり、スクリムが薄れて出る | 下へ抜ける（下へのスワイプでも閉じる。§5.2） |
    | ヘッダーの出入り（§5.1） | 上端から降りる | 上へ畳む |

    行の出る動きの値は `tokens.css` の `--motion-row`・`--motion-row-step`・`--motion-row-shift`。順番は、ドロワーでは `nav-drawer` が見えている行に振る番号（`--row`）、「検索」のプルダウンでは行の並び（`--item`）で、
    どちらも開いた直後の間だけ付く `.is-entering` の下で走る（「検索」を自分で開閉したときにドロワーの行が動き直さないよう、開いた直後に限る）。
    `hidden` 属性の `display` の切り替えを遅らせる（`transition-behavior: allow-discrete` と `@starting-style`）ので、JS は開閉の動きを持たない。非対応のブラウザでは切り替わるだけ。
    管理画面は、行の寄りと × の行き過ぎを止める（`--motion-pop` を短い ease にして、行のアニメーションを外す。開閉の滑り・スクリム・プルダウンは作業の道具なので残す）。
- **遊びの動き**（`motion.css`。2026-11-04。SANKOU! にならった。§0）: マウスで触れたものだけが、短く・小さく・1 度だけ動く。
  型は次の 6 つで、**足すときも、まずこのどれかに当てる**（型を増やすほど、どこを触っても何かが動く疲れる画面に近づく）。

  | 型 | 置き場所 | 動き |
  |---|---|---|
  | 下線を引く | 一覧の行（単語一覧、単語詳細の関連語・しりとり）・ランキング・ホームの 2 つのリストの見出し語、今日の一語、ホームの数字の升の名前、パンくず、分類のリンク、ホームの探し方の選択肢（768px 以上）、フッターのリンク | 墨の 1px の下線が左から引かれ（300ms）、離すと右へ抜ける。折れた見出し語は 1 行目から最終行へ続けて 1 本に引く。行の上に載る分類やタグに触れたときは、そちらに引く |
  | 矢印が進む | 矢印（→・←）を添えたボタンとリンク | 向いている方へ 3px 進む（200ms） |
  | サイト名が伸びる | ヘッダーのサイト名 | 触れている間「長」のあとに伸ばし棒（ー）が伸び続け、上限の 3 字ぶん（「長ーーーい」）へ近づくほど鈍って止まる（伸びきるまで 3 秒）。離すとゴムのようにパツンと戻り、縮みすぎた勢いで縦に膨らみながら 2〜3 回揺れて止まる（0.9 秒。揺れの幅は離したときの長さに比例する）。**遊びの動きでこれだけが、触れている間ずっと動く**（2026-11-05 オーナー指示。それまでは SANKOU! のロゴと同じく 3px 沈んでいた） |
  | シャッフルの印がめくれる | 単語一覧のシャッフル、単語詳細の「別の言葉へ」 | 印が 1 度だけ裏返って戻る（400ms） |
  | 円環をなぞり直す | 今日の一語・単語詳細のレールの円環（ホームの印は除く。§5.9） | 始点から読みを 1 度なぞり直す。速さは一定で、描き終えるまで 図の幅 ÷ 200 × 1.6 秒（200px で 1.6 秒、レールの 104px で約 0.8 秒） |
  | 済んだ印が出る | 単語詳細のリンクのコピー | チェックの印が小さく膨らんで出る（250ms）。押したあとの手応えなので、タッチの端末でも動かす |

  - hover で動くものは、hover できる端末（`hover: hover`）だけで動かす。タッチでは押した印が残り、選択の印に見える。
  - `prefers-reduced-motion: reduce` では動かさない。下線は伸ばさずにそのまま出す（線と色の変化は残す）。
  - 動かすのは `transform`・背景の大きさ・破線のずれだけにして、まわりの組みを揺らさない。
    距離と時間はトークン（`--nudge` 3px・`--motion` 200ms・`--motion-line` 300ms）。
  - SANKOU! のサムネイルが影を落として浮き上がる動きは採らない（影で押し出す“カード風”。§12）。
  - 管理画面では動かさない（admin.css が距離と時間を 0 にし、ボタンも反転させない。§10）。
- **リンクは色を変えない**。`base.css` の `a` は `color: inherit` ＋ **文字と同じ色（`currentColor`）の 1px の下線**（offset 5px）で、hover で下線を消す（SANKOU! と同じ）。
  ナビ・一覧の行・カードなど「下線を出したくない」リンクは各コンポーネントで `text-decoration: none` にし、**hover は面か文字色の濃さ**、
  または遊びの動きの下線（上の表）で示す。
- **ボタンは hover で墨に反転する**（`.btn`・ページ送り・ホームの検索ボタン。2026-11-04。SANKOU! にならった）。
  墨のベタの主要ボタン（`.btn--primary`）は、逆に白い面に墨の文字へ返す。反転はマウスの端末だけ。
  **選択の切り替え（`aria-pressed` を持つボタン。ランキングの板の切り替え）は、hover で面（`--bg-soft`）を敷くだけ**にする
  （墨のベタは選んでいるものの印なので、触れただけで墨になると、どれを選んでいるのか分からなくなる）。
- **選択状態は墨のベタ**（チップ・50音セル・タブ・主要ボタン = `--text` のベタ ＋ `--bg` の文字）。
  ホームの探し方の、選択肢を開いているボタンも同じ反転で示す（§5.2）。

  配下のページにいるときは、閉じている間は「検索」を、開くと配下の行を墨のベタで塗る（ベタは常に 1 つだけ。開いている「検索」には面を敷かない）。
- **900px 以下はハンバーガー → 右からのドロワー**（2026-11-04 に 767px から広げた。767px で切り替えていたころは、768px 幅でナビが 2 段目に落ちていた。
  サイト名 約 220px と、ナビ・トグル約 490px は、余白を含めて 780px ほどないと 1 行に並ばない。WebKit で実測）。
  - ハンバーガーの三本線は墨。押せる大きさのまま、内側の余白（12px）のぶんだけ右の余白へはみ出させ、三本線の右端を余白の端に揃える。
    **開くと × に変わり**（§4 の開閉の動き）、ドロワーとスクリムの手前（`z-index: 21`）に出て、そのまま閉じるボタンになる。
    × の腕は線を 0.86 に詰めて、Phosphor の × と同じ 11px 四方に収める。
  - 767px 以下では左右の余白を本文の帯と同じ 16px に詰め、サイト名の左端とハンバーガーの三本線の右端を本文の端に揃える（2026-11-03。
    円環と英字を添えたブランドが 290px あった当時は、左右 24px のままだと 390px 幅でも 6px 足りず、ハンバーガーが 2 行目に落ちていた）。
    サイト名とハンバーガーは、320px でも 1 行に収まる（実測）。
  - **ドロワーは札の組み**（2026-11-04。それまでは地 `--bg` の面に影を落とし、14px・`--text-muted` の文字を罫なしで並べていた）。
    札と同じ白い面（`--surface`）に**左端の墨の罫 1 本**で輪郭を持たせ、影は落とさない（下のページはスクリム `--scrim` で沈める）。
    幅は `min(280px, 82vw)`、高さは見えている画面の高さ（`100dvh`。`100vh` だと iOS のツールバーの裏に下の行が潜る）。
  - **頭はヘッダーと同じ高さ**（罫を含めて 61px。管理画面は 12px の余白で 61px のまま。どちらもヘッダーと同じ余白の変数で組む）に組み、下に墨の罫を引く。
    開いた画面では、スクリムの下のヘッダーの罫と同じ高さで横につながる。左に「メニュー」（サイト名と同じ 20px・800・字間 0.04em）だけを置き、
    右端には、手前に重なる × のハンバーガーが来る。**閉じるボタンは別に持たない**（2026-11-06 まではドロワーの頭に × のボタンを置き、ハンバーガーの真上に重ねていた。
    同じ位置に 2 つ重ねず、同じ 1 つが形を変える）。ヘッダーを降ろしたまま（§5.1 のヘッダーの出入り）にするので、× は開いている間いつもドロワーの頭と同じ高さに並ぶ。
  - **ナビは行を 1px の隙間で仕切って積む**（§3）。15px・`--text`・左右 16px・高さ 48px で、並びの終わりにも `--border` の罫を 1 本引いて閉じる。
    **現在地の行は墨のベタ**（ヘッダーの項目と同じ規則。§4）。
    「検索」は折り畳みのまま（開閉の印は 1em）で、配下（ジャンル〜詳細検索）は 40px に字下げしてアイコンを添え、14px で組む。
    配下のページにいるときは、畳んでいる間は「検索」の行を、開くと配下の行を塗る（ベタは常に 1 行だけ）。
    hover の面もヘッダーの項目と同じで、マウスの端末だけ（開閉するだけの「検索」の行に、タップした面が残って選択の印に見えていた）。
  - **テーマの切り替えは、ナビの行から 24px 空けた 1 行**（上下に `--border` の罫）に、名前（「ダークモード」）を見せて置く（§9.3）。
    画面の最下部には貼り付けない（iOS の下端のジェスチャと取り違える。§10.1.2）。
  - フォーカスは、開いてもハンバーガー（× になったそれ）に残す。閉じるときは、ドロワーの中にあったフォーカスだけをハンバーガーへ戻す。
    閉じたドロワーは `visibility: hidden` でも隠し（滑り終わってから。visible と hidden のあいだの補間は途中がずっと visible なので、遅らせる指定は要らない）、Tab で入らない。
    Turbo のキャッシュの直前に閉じる（開いたまま残すと、戻ったときに開いて見えていた）。
  - 「検索」の折り畳みは、**ドロワーの中のほかの行（テーマの切り替えなど）を押しても畳まない**（外側のクリックで畳むのは、吊り下げ・シートのときだけ。
    畳むのは「検索」の再押下・Escape・Turbo のキャッシュの直前。2026-11-06 オーナー指摘「検索を開いたままダークモードを切り替えると、畳まれて高さが変わる」）。
    パネルを grid の 1 行にして `0fr` ↔ `1fr` で伸び縮みさせ、はみ出した分をパネルが切る（行数が決まっていない高さは補間できない）。
    **WebKit（2026-11 時点の Safari 18 相当）は、`0 < fr < 1` の行をパネルの高さの fr 倍のさらに fr 倍に縮める**ため、行の包みを行に合わせて縮めず（`align-self: start`）、
    パネルの `overflow: hidden` で切る形にしてある（行に合わせて縮める形だと、途中でパネルとの差が灰色の帯に見えた。実測）。
- フッター（奥付）: 帯は持たず、上に墨の罫 1px を引いて（ヘッダーの下の罫と対）、**1.6fr ＋ 1fr × 3 の 4 列**に割る。1 列目に**ブランド名 → 一行の説明 →「このサイトについて →」**、右の 3 列は**さがす / データを見る / サイト情報**の導線。最下段は細罫で切って `EST. 2026 / JAPAN` ＋ コピーライトだけ。
  - **ワードマークは持たない**（2026-09-05 にヘッダーのブランド名の右へ移し、2026-11-04 にヘッダーからも外した。上記）。奥付はブランド名から始める。
  幅は**ヘッダーと同じ 1040px**（左右の余白も同値。ただし 560px 以下ではフッターの左右の余白だけ `--space-4` に詰まり、
  左端が 8px ずれる。揃えるかは未決）にして、ヘッダーのサイト名と 1 列目の左端を揃える。1040px はトークン `--frame-width`
  （tokens.css）で、ヘッダー・管理ナビ・フッター（2 か所）の 4 か所がこれを使う。900px 以下で 2 列（1 列目は全幅）、560px 以下で 1 列に畳む。
  （中央揃えで列に割らない案も試したが、**導線が横一列に潰れて奥付として引けなくなる**ためオーナー判断で 4 列に戻した。2026-09-04）

### 5.2 ホーム（看板と札の棚）
**ホームは上から 印 → 看板 → 札の棚 の 3 段で組む**（2026-11-03 オーナー判断。SANKOU! のトップにならい、看板の検索バー・ボタンと同じ墨の枠の札を棚に積んだ）。
それまでは「1 枚の紙」として、画面端まで届く帯（`.band` / `.sheet`）を罫の格子で割り、左の袖に英字の標識を置いていた
（2026-09-03〜11-03。組みと経緯は [`history/design.md`](history/design.md)）。

- `main` に `container--flush`（本文の幅と左右の余白を外す）を差し込み、印と看板は `.band > .band__inner` が、札の棚（`.home-shelf`）は棚自身が、
  **どれも本文と同じ幅（`--content-width` = 800px。左右の余白 24px を含む）**で中央に寄せる。
  札の幅は 752px（800 − 24 × 2）で、看板の列（640px）から左右に 56px ずつはみ出すだけになる（1280px で札の左端 264px。実測）。
- **棚は 1 列に積む**（今日の一語 → 最近追加 → 読みが長い）。最初はヘッダーと同じ幅（`--frame-width` = 1040px）に広げて 2 つのリストを横に並べたが、
  看板の列との幅の差が大きすぎて看板が負けた（2026-11-03 オーナー指摘「横幅が違い過ぎて少しびっくりします」）。
  幅を詰めて 2 列のまま組む案（800px・880px）も実寸で比べたが、リストが細って長い語が 3〜4 行に折れ、左右の高さも倍ほど違ったので、1 列を採った（同日オーナー判断）。
  2 つのリストを縦に積むぶん、ページは 180px ほど長くなる。

置くものは 5 つだけ。

1. **印（`.band--mark`）**: ページの一番上に、**サイト名の読み「ナガイコトバノデータベース」を五十音の円環で一筆書きにした線画**（`.ring-art--mark`、172px、**中央**）を 1 つだけ置く。手本（しずかなインターネット）が最上部にロゴの図を置くのと同じ役割。円の外側を標識「NAGAI KOTOBA DATABASE」が回るので、**キャプションは付けない**（§5.9）。
2. **看板（`.band--hero` + `.masthead`）**: 面も枠も持たず、地の上に直接置く。**手本と同じく 1 列の中央揃え**で、上から順に積むだけ（2026-09-04 オーナー指示。それ以前は縦罫で左右に割る 2 カラムだった）。
   - **見出し「長い言葉を探す。」→ 説明 → 検索バー（高さ 52px・墨の 1px・角 8px）→ 探し方の入口（`.search-ways`）**
     標識はここには置かない（`NAGAI KOTOBA DATABASE` は印の外周へ、`EST. 2026 / JAPAN` はフッターだけに残した）。
   - **列の幅は `--masthead-width`（640px）**。説明・検索バー・探し方の入口はこれを超えない。
     2026-09-04 に 1 列へ組み直したときは説明 `30em`・検索バー 560px だったが、数字に根拠は無く（記録は「列の幅を決める」だけ）、
     説明が 3 行・ボタンが 2 段に分かれていたので広げた（2026-11-03 オーナー指示）。
     640px は、ボタン 5 つが 1 段に収まる幅（1280px で 602px）から決めた（ボタンを 9 つに増やしてからは 2 段になる）。
   - **検索バーの案内（プレースホルダー）は「単語を検索」だけ**（`layouts.search_placeholder`）。以前は「（例：不完全性定理、
     メンブレンキーボード）」と例文を添えていたが、スマホでは途中で切れていたのでやめた（2026-11-03 オーナー指示）。
   - **説明は文ごとに行を分け、文の中は文節の切れ目でだけ折る**（`phrased_sentences`。§2）。PC では 1 文が 1 行に収まる。
     幅だけで折ると「ジャ / ンル」のように語の途中で割れる。以前は 767px 以下で文をつなげて流していたが、スマホで「データベ／ース」と割れた（2026-11-04）。
     文言は meta description の既定と同じ 1 本（文節の配列をつないで使う）。
   - **探し方の入口**は、**ボタン（`.btn`）を 9 つ**並べる（2026-11-03 オーナー指示「ここが充実してると選択肢の多い豊かなサイトになる気がします」。
     SANKOU! のトップの、カテゴリのボタンと、押すとその場で開く選択肢にならった）。ボタンには語と印（∨ か →）だけを置く。
     - **開くボタン（語 ＋ ∨）**: ジャンル / エンティティ / 言語学的特徴 / 読みの長さ / 語種 / 品詞。押すとその場で選択肢が開く。
       選択肢はどれも**単語一覧の既存の絞り込み**（`genre_id`・`reading_length` など）へのリンクで、新しい URL は作らない。
       中身は `SearchWayMenus` が決める。公開語義の無い選択肢は出さず（選んでも空の一覧になる）、選択肢が 1 つも無い探し方はボタンごと出さない。
       ジャンルは大分類、エンティティは語の多い順に 20 まで（全部は `/entity_types`）、言語学的特徴は用語解説の順、
       読みの長さは 10〜19 文字を 1 文字ずつと 20 文字以上（2026-11-03 オーナー指示。最初は 15〜19 文字もまとめていた）、
       語種は語の多い順、品詞は登録順に並べる。
       探すページを持つ探し方（ジャンル・エンティティ・言語学的特徴）だけ、選択肢の末尾にそのページへのリンク（「ジャンルの一覧へ →」）を添える。
     - PC では、**看板の列の幅の墨の枠（`.search-ways__panel`）をボタンの段の下に重ねて**開き、選択肢を「/」で区切って流す（SANKOU! と同じ）。
       767px 以下では**画面の下からシート**を出す（ボタンが 4 段あり、段の下に開くと画面の外にはみ出すため）。
       シートは選択肢を 1 行 1 つで `gap: 1px` の罫に並べ、頭に探し方の名前と ×（44px）を置き、後ろを幕（`--scrim`）で覆う。
       **下へのスワイプでも閉じる**（`swipe-dismiss`。2026-11-06 オーナー指示「下からスライドインしてきたものは、スワイプで元に戻れるようにしたい」。
       ドロワーは左右のスワイプでは閉じない）: シートのどこをなぞっても指に付いて下がり、96px 以上下げるか、速く払ったら閉じる（足りなければ元の位置へ戻る）。
       中身が上へスクロールされているときは、ふつうのスクロールを優先する（いちばん上にいて、下へなぞったときだけ引き下げる）。
     - 開いているボタンは**墨の面に地の文字で反転**し、∨ が上を向く（§4 の選択状態）。開くのは常に 1 つで、
       別のボタン・外側のクリック・Escape・×・幕で閉じる（開閉はヘッダーの「検索」と同じ `nav-menu`）。
       JS が無いと開かない（選択肢はサーバが描くが `hidden` のまま）。そのときも同じ探し方は、ヘッダーのメニューと単語一覧の絞り込みに残る。
     - **進むボタン（語 ＋ →）**: 索引 / ランダム / 詳細検索。ランダムは `rel="nofollow"`（押すたびに行き先が変わる。フッター・単語詳細と同じ）。
     - 語と行き先はヘッダーの「検索」メニュー（`ApplicationHelper#search_ways`。こちらは 5 つのまま）と 1 か所で持ち、
       ホームの並びは `HomeHelper#home_search_ways` が組む。
     - **ホームの描画を重くしない**（2026-11-03 オーナー指示「中途半端にデータを引っ張ってくるので、そこで速度低下のボトルネックになってはいけない」）。
       選択肢は `SearchWayMenus` が組んで 1 時間キャッシュし（組み直すとマスタを引く SQL が 5 本走る）、描いた結果も、
       選択肢が変わるまでフラグメントキャッシュで使い回す（`HomeHelper#home_search_ways_cache_key`。90 ほどのリンクを毎回描くと、
       それだけで開発環境で 5.8ms かかった）。ホームの SQL は 21 本から 16 本に減り、どれも語が増えても本数が変わらない（N+1 は無い。実測）。
     - **列は検索バーの幅を超えない**（2026-11-03 オーナー指摘「PC 表示で、検索窓より広く取るのが気になる」）。
       **ボタンは中身の幅のまま**並べ、収まらなければ折り返して中央に寄せる（1280〜768px で 5＋4 段、600px で 4＋5 段、390px・360px で 2＋2＋3＋2 段。実測）。
       ボタンを伸ばして検索バーの端に揃える案は試したうえで退けた（オーナー「無理に揃えなくてよくて、二段になるなら二段で ok」「無理にボタン幅を広げるのも無し」）。
       一言の説明やアイコンを添えた案、罫で組んだ目次の案も試作したが、**「ユーザーはそんなに文字を読まない」「一画面に入る内容の種類が増える」**として、語と印だけの形を採った。
       もとは検索バーの下に「詳細検索はこちら →」の 1 行だけを置いていた（入口の 1 つに畳んだ）。
   - **看板に数は置かない**（2026-11-03 オーナー判断「そこに統計情報っているの？」「登録数も要らない」）。
     それまでは列の最後に、収録語数の巨大な数字（§5.9）と、語義数・ジャンル数・最長の読み・今月の新収録数を置いていた（`.masthead__figures`）。
   - 縦のリズム（1280px 実測）: 印 → 24 → h1 → 16 → 説明 → 40 → 検索 → 24 → 探し方 → 64 → 札の棚（棚の上端 691px）。
3. **今日の一語（`.home-featured`）**: 棚の最初の札。左に語（32px・800）・読み・意味、右に**その語の読みを五十音の円環で一筆書きにした線画**（200px。§5.9）。
   - 意味の下に**その語の関連データ**を置く（2026-09-04 オーナー指示「情報が少ないので賑やかしが欲しい」）。
     **ジャンルのパンくず**（`shared/_genre_path`）と、**タグの行**（エンティティ / 品詞 / 語種 / 読みの文字数 / モーラ数 / 先頭文字 / 末尾文字）で、
     **どれも単語一覧の絞り込みへの実リンク**にする（§5.5）。数を並べるためではなく「ここから辿れる」ことを見せるための区画。
     先頭・末尾文字のタグは**「先頭 バ」のようにラベルを添える**（文字だけ置くと何の値か読めない）。
     マスタは `HomeController#featured_word` で先読みする（1 語ぶんとはいえ個別に引かない）。
   - **円環に説明（キャプション）は添えない**（2026-11-03 オーナー判断「円環の説明は要らない」）。
     以前は標識 `KANA RING` と、2 行目に弦の交差回数（`9 CROSSINGS`）を添えていた。
   - 700px 以下では 1 列にして、円環を語の下へ回す（168px）。
4. **2 つのリスト（最近追加 / 読みが長い）**: 今日の一語の下に、1 枚ずつ積む。
   行は `gap: 1px` の隙間で仕切り（§3）、hover で面（`--bg-soft`）が敷かれ、語に墨の下線が引かれる（遊びの動き。§4）。
   - 最近追加は 語・読み・公開日。**NEW の印は付けない**（見出しが新着だと言い、公開日も出ている）。
   - 読みが長いは、順位を墨の 1px で囲んだ 28px の角（`.home-column__rank`。角丸 4px・数字は 800）に入れ、
     右端に**文字数を大きな数（18px・800）＋単位**で立てる（この欄の主題）。
5. **数字で見る長い言葉（`.home-figures`）**: 読みが長い言葉の下に置く、統計ページへの入口（2026-11-03 オーナー指示「統計ページの動線が欲しい」）。
   試作は 3 案（数字 4 つ／読みの長さの分布／ワードクラウドの墨版）を比べ、数字の案を採って数を増やした。
   - 統計ページの数字の壁から、**天井無しに増えていく数だけ**を 6 つ選ぶ: 収録語 / 語義 / 別表記 / 同音異義の組 / のべ読み文字 / 公開開始から（日）。
     平均・割合・上限まで埋まっていく数（頭文字の種類「44／46 字」・使用ジャンル・言語学的特徴の種類など）は置かない
     （2026-11-03 オーナー指示「天井無しで増えていく数値を対象にしてほしい」）。選んだ数と行き先は `HomeHelper::HOME_STATS_FIGURES`。
   - 升は 3 列（767px 以下は 2 列）で、罫は `gap: 1px`。数は読みが長い言葉の文字数と同じ墨の 800（28px。767px 以下は 24px）で、
     語と単位は数字の壁と同じもの（`StatsHelper#stats_number_wall`）を出す。
   - **升ごとに統計ページの章へ送る**（収録語・公開開始から → 収録の推移 `#timeline`、ほか → 数字の壁 `#number-wall`）。札の頭には「統計へ →」を置く。
   - 右下に集計の時点（`stats.index.computed_at`）を添える。数は統計ページと同じ 1 日ごとの集計で、ホームは数字の壁だけの写し
     （`SiteStatistics.wall`）を読む（集計一式は 40KB あり、キャッシュから戻すだけで 1 リクエストに 1.3ms かかるため）。

- **札（`.panel`）**: 白（`--surface`）の面を**墨（`--text`）の 1px・角丸 8px（`--radius`）**で囲む。看板の検索バー・探し方のボタンと同じ枠で、
  ページの上から下までを同じ線で組む（2026-11-03 オーナー指示「しっかりしつつキャッチー」「検索窓周辺との雰囲気は統一して」）。
  札どうしの間は 24px（`--space-5`）。ホームで始めた札が、そのままサイト全体の区画の単位になった（§3）。
  - 札の頭（`.panel__head`）には**日本語の見出し（18px）と、右端の「もっと見る →」ボタン（`.btn--sm`）だけ**を置き、墨の罫 1px で中身と分ける。
  - **英字の標識（アイブロウ。`WORD OF THE DAY` など）は置かない**（2026-11-03 オーナー判断「英語で書かれたアイブロウヘッドラインは要らない」）。
- 組み方は 3 案を実寸で試作して比べ、墨の枠の札を棚に並べる案を採った（2026-11-03）。ほかの 2 案は、1 列（800px）のまま中身だけを墨の枠に収めて
  見出しを枠の外に出す「額」と、枠を持たずに見出しの下と区画の終わりを墨の罫で挟む「罫の表」（読みが長い言葉は文字数を先頭の列に立てる）。
  いまの棚は「額」と同じ 1 列・800px に落ち着いたが、見出しを札の頭に入れて「もっと見る →」を添える点が違う。
- **札を積むか 1 枚にするかは、中身が 1 本の並びかどうかで決める。** 単語一覧は札を 1 枚だけ使い、件数と並び順を札の頭に、行の並びを中身に収める
  （2026-11-03 オーナー指示「一覧ページにこのトップページのデザインを反映させて」。§5.3）。1 本の並びを札で割ると、どこから読むのかが定まらなくなる。
  収録リクエストも札は 1 枚（入力の表）で、送るボタンと送信前のお願いは札の外に置く（2026-11-04。§5.12）。
  積むのは、別々の区画が並ぶページ（ホーム・単語詳細・統計・索引・恒久ページ。§5.4・§5.6.1・§5.11・§5.13）。
  ランキングは板ごとの札を、切替のボタンで 1 枚ずつ見せる（§5.5.1）。
  単語詳細は語義を 1 つずつ札に収め、その下に関連語・しりとりの札を積む（2026-11-04 オーナー指示「トップページと一覧ページのデザインを引き継いで」。§5.4）。
  関連語・しりとりは次の語への入口で、トップの棚と同じ性格の区画になる。

  .entry-list { display: grid; gap: 1px; background: var(--border); }
  .entry-row  { background: var(--surface); }

  - **600px 以下では 2 列をやめて縦に積む**（見出し語 → 読み → 分類 → 文字数）。2 列に割る幅が無く、同じ潰れが起きるため。
  - 文字数は、数をトップの数字と同じ墨の 800 で立て、単位「字」を小さく添える。
  - 同じ読みの語義が複数ある語は、読みを 1 回だけ出す（2026-11-04 オーナー判断。語義ごとの読みは詳細で見る）。
- ページ頭のレール（`.page-header__rail`）には、**件数だけを大きく立てる**（`.page-header--count`。2026-11-05 オーナー指示
  「一覧とかで見たときに代表的な円環はなくてもいい。その代わり、登録語数とかヒットした語数をきちんと主張させてあげた方がいい」）。

    大きさは 56px（線画と並ぶ単語詳細の 40px より大きい）。**列の幅は数の幅に合わせ、単位を数から離さない**
    （幅 160px の列に 40px で組んでいた頃は、4 桁の件数で単位「語」だけが次の行へ落ちた）。
  - **その面でいちばん長い読みの円環は置かない**（2026-11-05 まで件数の下に置いていた。§12）。
    **英字の標識（`WORD INDEX`・頁の位置）も置かない**（2026-11-03。トップと同じく見出しは日本語だけ。§5.8）。
- 行は角丸を持たず（上記）、hover で `--bg-soft` に沈み、見出し語に墨の下線が引かれる（遊びの動き。§4。分類やタグに触れたときはそちらに引く）。
  **矢印などの装飾は置かない**。
- **検索条件に当たった箇所は、見出し語と読みの上で黄の面（`--highlight`）で囲む**（`mark.search-hit`。2026-11-10 オーナー指示。§1 の例外）。
  はじめは単語詳細の注釈の対象（§5.4）と同じ `--bg-tint` で組んだが、検索のハイライトは黄の方が見慣れているとして替えた。
  字は太らせず、色も変えず、余白も付けない（語の途中を囲むので、字の間が開くと語が割れて見える）。行に新しい要素は足さない。
  - 囲むのは文字列の一部に当たる条件だけ: キーワード・正規表現・言語学的特徴（該当部分）と、読みの上だけのヘボン式ローマ字・母音・音の成分（数えた字）。

  - **2 つ以上の条件が重なって当たった字は、一段濃い黄（`--highlight-deep`）にする**（蛍光ペンの重ね塗り。濃さは 2 段だけ。2026-11-10 オーナー判断）。
    特徴は該当部分ごとに数えるので、特徴の範囲どうしが重なった字も濃くなる。接するだけの範囲は 1 つに続けて囲む。

- 一覧の頭のツールバー（`.entry-toolbar`）は**札の頭**に置き、件数（3 桁で区切る。レールと揃える）の右に `.entry-range`（等幅 11px）で **`001–100`** を出す。「いま何件目を見ているか」を数えられるようにするための目盛りで、手本「ただ、そこ」の `001–022 / 022` に当たる。
  - 右にシャッフル（`.btn--sm`）と並び順のセレクタ（墨の枠）を置き、狭い幅では件数の下へ回す。**並び順の名前は縮めず、幅が足りないときはセレクタを縮める**（名前が縮むと「並び／順」や 1 字ずつ縦に折れた）。
  - **シャッフル中だけ、選べない「シャッフル中」をセレクタの先頭に出して選択済みにする**（2026-11-04 オーナー判断）。出さないと先頭の既定の並びが選ばれて見え、それを選び直しても変更にならず、既定の並びへ戻れない。
- **絞り込みの条件（`.active-facet`）**: 左の列に漏斗、右の列に条件の札（`.condition-chip`。墨の枠）と「条件を変更」「絞り込みを解除」（`.btn--sm`）を置く。
  札が何行に折れても、漏斗は 1 行目の高さに留まる。
  - 札の名前は縮めない。**名前と値が 1 行に収まらないときは、値を名前の下の行へ回す**（2026-11-04 オーナー判断。名前の横で折ると、1 語のキーワードが「みつからないな／がいことば」と語の途中で折れた）。
  - 複数の値は「・」でつなぎ、**折り返すのは「・」の後ろだけ**（`ApplicationHelper#phrased_name`。§2）。語の途中（「スポー／ツ」）や最後の 1 字（「出版／物」）では折らない。
- **0 件のとき（`.empty-panel`）**: 結果があるときと同じ札に、溶けた顔（§5.0）・案内・収録リクエストへの導線を中央に積む
  （2026-11-03 オーナー指示「🫠 の『見つかんねぇ〜』みたいなグラフィック」）。
  - 案内は文ごとに行を分け、文の中は文節の切れ目でだけ折る（中央寄せでは「見つかりませんで／した」のような語の途中の折れが目立つ）。
    文言は文ごとの文節の配列で `ja.yml`（`words.index.empty_filtered`）に持ち、`ApplicationHelper#phrased_sentences` が文節を `<wbr>` でつなぐ
    （`.phrase-sentence`。説明文に共通の組み。§2）。
  - 導線の文言は、キーワードをフォームへ引き継ぐときだけ「この言葉の〜」と言う。条件だけの 0 件には指す語が無いので「収録してほしい言葉をリクエストする」。
- **ページ送り**は、前へ・状態・次へをどれも途中で折らず 1 行に収める（560px 以下で間と左右の余白を詰める）。
  **1 ページしかないときも「1 / 1 ページ」を出す**（2026-11-04 オーナー判断。1 ページで完結していることが明示的になる。出さないと、描画の失敗や読み込み中と取られうる）。
- 絞り込んだ面の見出し（`facet_heading`）は、スマホで「バトル・アドベンチャーの長／い言葉」と語の途中で折れても、折る位置を指定しない
  （2026-11-04 オーナー判断。絞り込みの内容なので、読まずとも分かり、折り返しにそこまでストレスを感じない）。
- ジャンルのパンくずは**常に「中 › 小」に畳む**（カラムが狭いため。大分類への導線はジャンル一覧と単語詳細が担う）。

### 5.4 単語詳細
**トップと単語一覧の組みを引き継ぐ**（2026-11-04 オーナー指示「トップページと一覧ページのデザインを引き継いで」）。
見出しまわりは単語一覧と同じく、英字の標識を置かず、数は墨の 800 で立て、円環に説明を添えない。語義・関連語・しりとりは、トップと同じ墨の枠の札（`.panel`）に収める。

1. パンくず → **2 カラムのヘッダー（`.page-header--rail`）**。
   - 左: **h1 見出し語** → メタ行（`No. {id}` と文字種。どちらも等幅）→ 説明（定義文。単語一覧のリードと同じ `.page-lead` で、面を敷かない）→ 操作の行（`.word-actions`）
   - 操作の行は、左にシェア（X・URL コピー）、右端に「別の言葉へ」（ランダム。`rel="nofollow"`）。どれもトップ・一覧と同じ小さいボタン（`.btn--sm`）。
     見出しのすぐ下に置くので、下まで降りずに次の語へめくれる。
   - **「別の言葉へ」はシェアと同じ並べ方にせず、行の右端へ離す**（2026-11-04 オーナー指示「前者は共有、後者はシャッフルなので、スペースを設けるか、別の場所に置きたい」）。
     題の上の帯（`No. {id}` の右肩）へ移す案も試作して比べ、離す案を採った（同日オーナー判断）。
   - **狭い幅でも 2 段に折らない**。519px 以下では、シェアの 2 つを名前を隠したアイコンだけの四角（32px）にして 1 行に収める（名前は読み上げに残す）。
     折ると、右端へ離した「別の言葉へ」が下の段の中途半端な位置に取り残される（2026-11-04 オーナー指摘「モバイル時に中途半端にズレるのが気になる」）。
     URL のコピーが済んだあいだは、リンクの印をチェックの印に替える（名前を隠した幅でも済んだことが見える。`data-copied` は `clipboard_controller` が付け外しする）。
   - 右のレール（縦罫で仕切る・160px）: 上に**読みの文字数**を単語一覧の件数と同じ墨の 800 で立て（線画と並ぶので 40px）、単位「字」を小さく添える。
     下に**読みを五十音の円環で一筆書きにした線画**（§5.9）。円環に説明は添えない。
     レールは左の見出しより背が高くなりやすく、余ったぶんがそのままヘッダー下の空白になるので、**数字と線画の間隔（`--space-5`）と線画の大きさ（104px）は詰めてある**。
   - **英字の標識（`HEADWORD`・`CHARACTERS`・`READING PATH / 50-ON RING`）は置かない**（2026-11-04。トップ・単語一覧と同じく見出しは日本語だけ。§5.8）。
     説明も、以前は `--bg-soft` の面に「説明」のラベルを添えて置いていた。
   - **縦罫はヘッダーの全高に通す**（`align-items: stretch`）。宙で途切れると「切り株」に見える
   - 罫は**この縦罫だけ**。下端に線は引かない
   - 本文が痩せるので **1024px 未満ではレールを下へ回し、数字と線画を横並び**にする
2. 1 カラム。右サイドの基本情報パネルは作らない。
3. **語義ごとに札を 1 枚**（`.panel.sense-card`）。札の頭に `語義 1`（ゼロ埋めしない）。中身:
   - グループ ruby。ただし**見出しと別表記の読みはルビ配置では組まず、表記の上に別行として積む**
     （WebKit は語まるごとのルビの途中で改行できず、読みが長い語で画面外へはみ出すため。
     **マークアップは `<ruby>`/`<rt>` のまま**、CSS の `flex` + `column-reverse` で見せ方だけ変える＝疑似ルビにしない）
   - 意味（15px・行間 2.0）
   - **該当部分つき特徴**: 注釈対象は `--bg-tint` の淡いハイライト、特徴名はチップ（`.chip`。§5.5）
   - 関連データ: ラベル列＋値列。**札の幅いっぱいに敷き、行は 1px `--border` の隙間**で仕切る（語義の札は高さ 800px 級の面になるので、余白だけでは平坦に流れて読めない）。
     上の本文とは 1px `--border` の罫で分ける。「円環交差数」は**数値だけ**を置く（図はレールに出したので折り畳みは持たない）
   - 本文と行の左右の余白は、札の頭の見出しと揃える（24px。767px 以下は 16px）。
   - 以前は 1px `--border` の大きな角丸（20px）で囲み、頭に `語義 1` を小さく置いていた（2026-11-04 まで）。
4. **関連語・しりとりは、トップの「最近追加」と同じ札**（`.panel.entry-panel`）に、一覧と同じ行（`words/_entry_row`）を収める。
   語義の札の下に 64px 空けて、札どうしは 24px の間で積む。
   - 札の頭に日本語の見出し（「同じジャンルの言葉」「同じ文字数の言葉」「しりとり 〜次の一手〜」）と、単語一覧の絞り込みへの「もっと見る →」（`.btn--sm`）を置く。
     「関連する言葉」の総見出しとアイコンは置かない（札の見出しが、何の並びかを言う）。
   - しりとりは、札の頭の下に「末尾の「ウ」から始まる言葉」を 1 行添える。繋ぎ目の文字だけ色を濃くする。
     次の一手が無いとき（「ン」で終わる・まだ収録が無い）は一文だけを置き、「もっと見る →」も出さない。
5. 一覧へ戻るリンクは、一覧のページ送りと同じ墨の枠のボタン（`.btn`）。
6. 個人情報・いいね等は置かない。

### 5.5 関連データ（必ず検索への導線にする）
- **ジャンル階層**: パンくず。区切り `›` は `--text-subtle`、末端は `--text`。共通 partial `shared/_genre_path`。
- **品詞・エンティティ・語種・文字数など**: タグ（`.tag`）。白（`--surface`）に墨の 1px・角 4px、13px の `--text-muted`。
  hover で枠ごと `--bg-tint` の面に替わり、文字が `--text` になる。

- 値には必ずラベルを添える。関連データを雑に並べない。

### 5.5.1 ランキング（2026-11-04）
**トップ・単語一覧・単語詳細の組みを引き継ぐ**（2026-11-04 オーナー指示「次にランキングをデザインしてください」）。
英字の標識（`RANKINGS` と板の数）は置かず（§5.8）、ページの頭はレールの無い `.page-header`（h1 とリード。下に章の罫）。
リードは文ごとに行を分け、文節の切れ目でだけ折る（`phrased_sentences`。1 段で流すと PC で「辿れます。」だけが次の行に、
スマホで「各」だけが行末に残った。2026-11-04 オーナー指摘）。
- **切替は目次を兼ねた小さなボタンの列**（`.rank-tab` = `.btn--sm`）にし、選んでいる板だけ墨のベタ（`.btn--primary` と同じ）。
  以前は上下 1px の罫で挟んだ帯に枠の無い文字のタブを並べていた（ページ見出しの章の罫と帯の 2 本が続いて、罫が 3 本重なっていた）。
  - **767px 以下では折り返さずに 1 段に並べ、横に送って選ぶ**。折り返すと 390px で 7 段・272px（320px で 9 段・352px）が札の上に積まれ、
    1 行目が画面の下端まで押し出される（1 段なら 40px。390px で 1 行目の上端が約 720 → 456px。2026-11-04 実測）。
    段は本文の左右の余白（`main.container`）まで広げ、端で切れたボタンが続きのあることを示す。スクロールバーは出さない。
- **1 枠 = 墨の枠の札（`.panel.rank-panel`）**。頭に板ごとのアイコンと見出し（音の成分は成分ごとに別のアイコン。§5.6）、中に順位表、
  **足の右端に「もっと見る →」（`.btn--sm`。同じ並びの単語一覧へ）**。頭に置くと、見出しの長い板（「拍（モーラ）が多い言葉」など）は
  見出しとボタンが 1 行に収まらず、390px で 10 枚のうち 6 枚、320px では全部でボタンが 2 行目に落ちた（2026-11-04 実測）。
- **行はトップの「読みが長い言葉」の札と同じ組み**: 順位は墨の枠の 28px の角（`.home-column__rank` と同じ）、語の下に読み、
  右端に指標値（`--font-display` の 800・18px の数＋単位）。長い語は何行にも折れるので、順位と値は 1 行目の高さに揃えて上に置く。
  行は `gap: 1px` の隙間で仕切る（§3。`.rank-list`）。
- **同じ値の語は 1 行にまとめる**（2026-11-04 オーナー指示「同じ数値のものは一番長い単語を代表として、折りたたみコンテンツにしたい」）。
  円環の交差が少ない言葉では、上位 10 件のうち 9 件が「0 回」で埋まり、同じ値の行が続くだけで順位表として読めなかった。
  - 行は「同じ値の組」1 つで、**読みがいちばん長い語を代表**に立て、残りは読みの下の「› ほかN語」（`details.rank-fold`）に畳む。
    畳んだ語は読みを付けず、見出し語のリンクだけを折り返して並べる（数十語になっても縦に伸びすぎない）。
  - 載せるのは**値の違う上位 10 組**で、**順位は組ごとに 1〜10 の通し番号**（同じ値の語数で次の順位を飛ばさない。2026-11-04 オーナー指示
    「きちんと1~10位までナンバー出しましょう」）。飛ばす数え方（「1 位（8 語）」の次が「9 位」）を一度試したが、同じ値の語が増えるほど
    10 位以内に入る組が減り、いずれ 1 位の組しか無い順位表になるのでやめた。
  - 下の順位の組は数百語になりうる（2026-11-04 の開発 DB で「長音符 1 本」は 381 語）ので、畳む語は 50 語までにし（`WordRanking::FOLD_LIMIT`）、
    残りは「残りN語は一覧で →」で同じ並びの単語一覧の、その組が始まるページへ渡す（`RankingsHelper#rank_fold_rest_path`）。
  - 比率（一字が重い言葉）は、表示する小数 2 桁が同じなら 1 組にする。
  - 「› ほかN語」は行全体を覆う詳細へのリンクより上に重ね、開閉と各語のリンクを押せるようにする。
- **順位は塗り分けない**（トップの札と同じく、どの順位も墨の枠だけ）。組にまとめる前は同率の語が同じ順位で並び、
  1 位だけを塗るとベタが続いて誤読を招いた（上位 3 位の順位の文字を濃くして段を作るのもやめた）。
- 板の 1 位の値を、見出しの右に線だけの数字（`MAX 字`）で立てていたが、外した（1 行目の値と同じ数が並ぶ。§5.9）。
- ゼロ埋めしない。

### 5.6 フォーム / ボタン / テーブル / ページネーション
- **入力は細枠の角丸ボックス**（1px `--border-strong` ＋ 角 8px ＋ 白（`--surface`）・14px）。focus は枠が `--text-muted` に変わり、共通の `:focus-visible` のアウトラインも出る（§4）。
  ホームの検索バーと探し方のページの絞り込みの欄だけは、押せる部品と同じ墨の枠にする（§5.2・§5.11）。
  モバイル（767px 以下）ではフォーム部品を 16px 以上にする（iOS の自動ズーム対策）。
- **ボタンは墨の枠**（白（`--surface`）＋ 墨の 1px ＋ 角 8px・高さ 40px・14px。`.btn--sm` 32px・13px、`.btn--icon` 30px）。hover は墨に反転する（選択の切り替えは面だけ。§4）。
  塗りは主要 CTA（`.btn--primary` = `--text` のベタ + `--bg` の文字）だけ。
- **検索フォームは、フォームそのものをトップ・一覧と同じ墨の枠の札にする**（`.panel.search-form`。2026-11-04 オーナー指示「次は検索周りのデザインをお願いします」。§5.11）。
  札の頭に見出し「検索の条件」（`funnel`）と区画どうしの組み合わせのスイッチ、足に送信の行を置き、そのあいだの条件の区画（数は書かない。出どころは `searches/index.html.erb`）を
  `1px var(--border)` の細罫で上下に仕切る。欄・区画の見出し・中身・送信の行の左右の余白は札の頭の見出しと揃える（24px。767px 以下は 16px）。
  札の中でも面は変えない（淡い面を全高の 7 割に敷くと、条件が平坦に流れて「どこを見ればいいか」が消える。面を足すのではなく**外す**のが正解だった）。
  英字の標識（`SEARCH`）は置かない（§5.8）。区画の見出しは、ほかの札の行と同じく hover で `--bg-soft` に沈む。
  - **キーワードの欄だけを常に出し、ほかの条件は区画ごとに見出し（`summary`）だけへ畳む**（`searches/_section`。2026-10-24 オーナー判断）。
    以前は「項目の多さそのものが見どころ」として全部並べていた（区画を畳む案は 2026-07-15 に PR #86 で一度差し戻した）。しかしジャンルや
    エンティティが増えるにつれてフォームが 3,915px（ページ全高 5,237px）まで伸び、キーワードだけで探したいときも最下部までスクロールしないと
    送信できなくなったので改めた。畳むとフォームは 877px（数字はどれも 390×844・ヘッドレス Chromium、2026-10-24 実測）。
    - 見出しはジャンルの折り畳み（`.genre-fold`）と同じ示し方で、既定の三角マーカーの代わりにキャレット（閉じると右向き）を置く。
      区画どうしは従来どおり 1px `--border` の細罫で仕切る。
    - **どの区画も、見出しの名前の頭（キャレットの右）にアイコンを添える**（2026-10-27 オーナー指示。10-24 に畳んだときは、キャレットが左端を引き継いでアイコンを外していた）。
      **同じ概念には、単語詳細の関連データと統計で使っているアイコンをそのまま使う**（読みの文字数の `ruler` など。区画ごとの割り当ての正は `searches/index.html.erb`）。
      サイトに無かった概念には、正規表現に `regex`（自作の `.*`）、音の成分に `waveform`（濁点・小書き・長音符を束ねる「音」の印。ランキングは成分ごとに別のアイコン）、
      ヘボン式ローマ字に `romaji`（自作の ka）を当てた。文字種には語種で使っていた `translate`（文 と A）を回し、語種は `globe_hemisphere_east`（言葉の出どころの地域）に移した。
      品詞は `article`（文書の印）から `part_of_speech`（自作の 品）に替えた。語種と品詞は、単語詳細と統計の同じ行も一緒に替えている（いずれも 2026-10-27 オーナー判断）。
    - **見出しは 16px・`--text`**（中身の欄やチップの 13〜14px・`--text-muted` より一段大きく濃く。太さは本文と同じ 400。
      2026-10-24 オーナー指摘「もう少し目立つように」）。常に出すキーワードの欄の名前（`.field-legend`）も同じ大きさ・濃さに揃える。
    - **条件が入っている区画は開いて描く**（単語一覧の「条件を変える」から来たとき・正規表現の誤りで差し戻したとき。`SearchesHelper#search_section_open?`）。
    - チェックボックスで選ぶ区画（50 音表・ジャンル・チップ）は、畳んだままでも選択が分かるよう**見出しの右端に選択数**を出す
      （`.genre-fold__count` と同じ形。選び直すと `fold_count_controller.js` が付け直す）。
    - 中の欄の名前（legend / label）は見出しと同じ文言なので、見た目からは隠して読み上げ用に残す（`.visually-hidden`）。
    - **欄に添える畳んだヘルプ（`.field-help`、`searches/_field_help`。正規表現の書き方・言語学的特徴の用語解説）は、開くと中身を
      見出しのキャレットの真下から 1px `--border-strong` の左罫で吊り、中身にだけ `--bg-soft` の面を敷く**（左罫に接する側は角を立てる。
      罫の色はジャンルの中分類を束ねる `.genre-hub__medium` と同じ）。2026-10-29 オーナー指摘「展開後の領域が折り畳みコンテンツ感が無い」への対応。
      それまでは 12px の小さな見出しの下に面だけを置いていたので、見出しと切り離れた別の箱が浮いて見えた。
      同日に試して退けた案: 見出しごと面に包む（「主張を抑えて。折り畳みのタイトルの背景色は要らない」）、面を持たず左罫だけで吊る（左罫に面を足すよう指示された）。
      見出しは文字（13px。閉じて `--text-subtle`・開いて `--text-muted`・hover で `--text`）だけで、文字の頭は入力欄の文字の頭（左右の余白 14px）に揃える。
      **用語解説の項目どうしは `gap: 1px` の罫（`--border-strong`）で分ける**（§3。管理画面の注釈フォームは一覧そのものに余白と面を持たせているので、余白で分けたまま）。
      開くときだけ中身の高さを 0 から伸ばす（§4）。
  - **送信の行（`.search-actions`）は画面の下端に貼り付ける**（`position: sticky; bottom: 0`。2026-10-24）。区画を開けばフォームはまた長くなるので、
    どこまで読み進めても押せるようにする。フォームの終わりまで来たら札の足に収まる。面は札と同じ `--surface` で下を流れる条件を隠し、
    縁は札の頭と同じ墨の罫が兼ねるので**影は付けない**。貼り付けるのはこの行だけで、ヘッダーは追従させない（§3）。
    札の既定の `overflow: hidden` はスクロールの入れ物を作り、貼り付きが画面ではなく札に対して効いてしまうので、この札だけ `overflow: clip`
    （入れ物を作らずに角丸で中身を切る）にする。
    Tab で移った先が行の下に隠れないよう、このページだけ `scroll-padding-bottom` を取る。
  - テキスト欄はどれも Enter で送信でき、モバイルのキーボードの確定キーも `enterkeyhint="search"` で「検索」にしてある。
  - **札の頭の右端に、区画どうしの組み合わせを切り替えるスイッチ（`.match-switch`）を置く**（2026-10-24 にページ見出しの行に置き、2026-11-04 に札の頭へ移した）。
    スイッチは文字なので、札の頭の右の余白を中身の欄と揃える（ボタンを置く札の頭より広い 24px。767px 以下は 16px）。
    左が AND（既定。すべてを満たす）、右が OR（どれか 1 つでも満たす。`match=any`）。区画の中の組み合わせ（文字数の下限と上限・
    音の成分の 3 つは AND、複数選択は OR）はどちらでも変わらない（`WordSenseSearch::MATCH_ANY`）。
    - 形はテーマの切り替えと同じ寸法のトラックを AND・OR の文字（等幅 12px）で挟む。どちらも「オン」ではないのでトラックは塗らず、
      つまみの位置と、効いている側の文字の濃さ（`--text`。効いていない側は `--text-subtle`）で示す。
    - チェックボックスを CSS だけでスイッチに見せる（JS は持たない）。フォームの中にあるので `form` 属性は要らない（ページ見出しの行に置いていたときは、フォームの外から `form` 属性で結んでいた）。
  - **選択肢に公開語義数を添え、索引と同じ見せ方にする**（2026-10-24 オーナー指示。数は `PublishedSenseCounts`。索引と共有する 1 時間のキャッシュ）。
    - 先頭文字・末尾文字の 50 音表は **`/browse` と同じヒート**（`.kana-cell--heat`。件数の濃淡、0 件のセルは `.kana-cell--muted`）。実数は title。
    - ジャンルは **`/genres` と同じ組み**: 大分類の折り畳みの見出しに横棒と件数（`.genre-hub__bar`・`.genre-hub__count`）、開くと中分類ごとに
      左罫で束ね（`.genre-hub__medium`）、中分類のチップを束の見出しにして小分類のチップを並べる。チップの名前の右に件数を等幅で添える。
      大分類は `/genres` と同じく行に積んで 1px の隙間で仕切り（2026-11-04。それまでは大分類ごとに淡い角丸の枠で囲んで間を空けていた）、
      区画の中なので入力欄と同じ淡い罫（`--border`）の外枠で束ねる（札の墨の枠と重ねない）。名前は「・」の後ろでだけ折る（§5.11）。
      **公開語義の無い分類は出さない**（`/genres` と同じ。選んでも必ず 0 件になる）。中分類の入れ子の折り畳み（`.genre-fold--medium`）はやめた。
    - 読みの文字数のスライダーは、**トラックの上に目盛りごとの公開語義数の棒グラフを敷き、選んだ範囲の棒だけを `--chart` で塗る**
      （範囲の外は `--border` で分布の形だけを見せる。不動産サイトの家賃の範囲指定の形）。上端の棒は「以上」なので、上端より長い語義もまとめて数える。
      棒の中心はつまみの中心（値の位置）に合わせる。スライダーを両端に置いたままなら、下限・上限とも送らない（端は「絞っていない」）。
- エラーは `--danger` の文字＋細枠（背景は塗らない）。
- テーブル = ヘッダ下と行に `1px var(--border)`。ページネーションはボタンと同じ墨の枠（角 8px）。

### 5.6.1 恒久ページ（About・プライバシー）の本文（`.prose`）
- **章は 1 つずつ墨の枠の札に収め、札の棚（`.panel-shelf`）に積む**（2026-11-04。統計の章と同じ組み）。札の頭にアイコンと章の見出しを置き
  （`pages/_chapter`）、中身は本文の区画（`.panel__body.prose`）か、1px の隙間で仕切った行で組む。
  札に収める前は、章の見出し（h2）の下に 1px `--border` の細罫を引いて章を分けていた。
  - 章の見出しはスマホで 2 行に折れることがあるので、文節の塊で組み（§2 の名前）、アイコンは 2 行の間に下ろさず 1 行目に置く（`.panel__title--wrap`）。
  - アイコンは章ごとに別の形にする。同じ形が 2 つの章に付くと、章の見分けに使えない（About の「データの精査」と「プライバシー」が同じ形だった）。
- **本文は札の幅いっぱいに組む**（15px で 1 行 43 字ほど）。札に収める前の `--reading-width`（640px）の読み物の幅は取りやめた。
- **英字の標識（`ABOUT` / `PRIVACY` / `1,496 ENTRIES`）は置かない**（§5.8）。About の収録語数は、単語一覧のレールの件数と同じ組み
  （数だけのレール `.page-header--count`。墨の 800 の 56px・単位は「語」）でページの頭に立てる。プライバシーは立てる数を持たないので、レールの無いページ頭にする（下に章の罫。§3）。
- **よくある質問は問答の行（`.faq-list`）に積み**、行どうしを 1px の隙間で仕切る（§3）。問いと答えの差は大きさ・太さ・文字の濃さで作る。
  **問い（h3）＝ 16px・800 の `--text` / 答え（p）＝ 15px・400 の `--text-muted`**。
- **外部送信の公表事項（送信先事業者・送信される情報・利用目的）は名前と値の行（`.fact-list`）に組む**。名前は 13px の `--text-subtle`、値は 15px。
  行どうしは 1px の隙間で、前後の本文の区画とは上下の細罫で分ける。560px 以下では名前を値の上に積む（単語詳細の関連データと同じ）。
- **ページ内もくじ（`.page-toc`）は試したうえで不採用**（2026-09-09 オーナー判断）。`--bg-soft` の面に章題を 2 列で並べる形で作ったが、
  本文の頭に「もう一つの見出しの束」が挟まって、ページの入口が重くなる。**章が多くても、もくじは置かない。**
- **図・イラストも置かない**（§5.7）。恒久ページは**文章と余白と罫だけ**で組む（札の枠と行の仕切りは区画の罫で、図ではない）。

### 5.7 図版（写真は置かない / About には図を置かない）
- 手本（TOFT / mud / ただ、そこ）はいずれも**図版が雰囲気の大きな部分を占める**。ただし手本の図版は**すべて撮影ではなく作図**なので、
  こちらも**図版が要るなら線画で用意する**（§5.9）。線画なら素材待ちにならず、実データから描けば嘘もつかない。
- **写真プレースホルダ（`.image-slot`）は全廃した**（2026-09-09）。「○○の画像を挿入」の破線枠を置いておく方式は、
  ホームの写真 4 枚の帯（`.image-strip`）→ 撤去、About のリード直下の 1 枠 → **撤去**、で置き場所がゼロになったため、
  partial `shared/_image_slot` と `.image-slot` の CSS ごと削除した。
  - **再導入しない。** 永久に埋まらない破線枠はページの入口を占領するだけで、実素材が入る当てのないまま「未完成の枠」を見せ続けることになる。
  - どうしても写真でなければならない場所が出てきたら、枠ではなく `<img loading="lazy">` を直接入れる（先に枠だけ置かない）。
- **About（このサイトについて）に図・イラストは置かない**（2026-09-09 オーナー判断。**再提案しない**）。
  「サイトの成り立ちを表す線画」として**5 案を実データで試作し、すべて不採用**になった（案と理由の表は [`history/design.md`](history/design.md)）。
  - **恒久ページは文章と余白と罫だけで組む**（§5.6.1）。図を足すのではなく、章の札と問答の行で読ませる。

### 5.8 標識（`.label-en`）
- 区画の頭に置く**等幅・大文字・12px の英字ラベル**（`--text-subtle` の塗り、字送り 0.04em）。「ただ、そこ」の `INDEPENDENT VISUAL ARCHIVE` と同じ役割。
  §2 の「補足・ラベルは 11px 未満にしない」を満たす最小。**置く場所によらず同じ組み**（横組み）。
  線だけの数字に添える単位（`.figure-caption`。同じ 12px の塗り）と、図に添えるキャプション（`.ring-art__caption`。一段小さい 10px）も
  この組みを兼ねていたが、ジャンル一覧のレールの数と放射図から外して、どちらも無くなった（2026-11-04。§5.9・§5.11）。

- **標識を白抜き（アウトライン）にする案は試したうえで不採用**（2026-09-05 オーナー判断。§12）。白抜きに見える線幅は級数ごとに狭い範囲にしかなく、
  大きくすると組みが崩れた（実測は [`history/design.md`](history/design.md)）。
  - **測り方の教訓**（白抜きを再検討するときは必ずこれで測ること）:
    - **白抜きは「線の画素そのもの」を測る**。背景から十分離れた画素だけを抜き出して平均する。細い線はアンチエイリアスで薄く溶けるので、
      指定した色（`--text` = 14.51:1）はまったく当てにならない。「暗い側 N%」で測ると**字面の大きさに結果が引きずられ**、級数を変えたときに比較できない。
    - **塗りは指定色で評価する**（WCAG の標準どおり）。塗りの文字を画素平均で測るとアンチエイリアスの縁を拾って不当に低く出る。
  - 白抜きはいまサイトのどこにも無い（標識の白抜きを取りやめたあとも残っていた線だけの数字 `.figure-number` を、2026-11-04 に外した。§5.9）。
- **必ず日本語の見出しと対にする**。標識だけで意味を伝えない。
  **ホームの札・単語一覧・単語詳細・収録リクエスト・ランキング・統計・探し方のページ（ジャンル・エンティティ・言語学的特徴・索引・詳細検索）・
  恒久ページ（About・プライバシー）には置かない**（2026-11-03 オーナー判断。ほかはそれを引き継いだ。§5.2〜§5.4・§5.5.1・§5.6.1・§5.11〜§5.13）。
- 文言は `config/locales/ja.yml` の `labels.en.*` に集約。**翻訳ではなく「図」**なので日本語ロケールでも英字のまま。
- 使う場所: **ホーム最上部の印の外周**（§5.9）、フッター最下段の `EST. 2026 / JAPAN`。
  共有カードの本体下段（`NAGAI-KOTOBA-DATABASE.JP` / `READING / N CHARACTERS`）にも置いていたが、2026-11-06 に外した（§5.1）。
  恒久ページの見出しの上（`ABOUT` / `PRIVACY`）にも置いていたが、2026-11-04 に外した（§5.6.1）。
  ヘッダーのブランド名の右にも、標識ではないワードマークとして 3 行の `NAGAI` / `KOTOBA` / `DATABASE`（`.site-brand__roman`）を置いていたが、
  2026-11-04 に外した（§5.1）。
- **標識の規則（日本語の見出しと対にする・2 行目に値を持たせる）の例外**は、フッター最下段の `EST. 2026 / JAPAN` だけ
  （奥付の印で、2 行目の値も日本語の対も持たない）。

  図のキャプション（`.ring-art__caption`）も例外だったが、どの図にも添えなくなった（五十音円環には、今日の一語が交差数を、単語詳細が `READING PATH / 50-ON RING` を、
  ジャンル一覧の放射図が `SENSES BY CATEGORY` を添えていたが、2026-11-03・11-04 に外した。§5.2・§5.4・§5.11）。
- **これ以上増やさない。** 見出しのたびに英字を足すと、標識が背景化して効かなくなる。

### 5.9 図としての数字・線画
- **線だけの巨大な数字（`.figure-number`。`-webkit-text-stroke: 1px var(--text-muted)` ＋ `color: transparent`）は、もう使わない**（2026-11-04 に、
  最後の置き場所だったジャンル一覧の分類数を、単語一覧の件数と同じ墨の 800 に替えて外した。§5.11）。
  「その面の性格を一言で表す数」を 1 つだけ置く部品で、ホームの看板の収録語数（2026-11-03。§5.2）とランキングの板の 1 位の値（2026-11-04。1 行目の値と同じ数が並ぶ。§5.5.1）にも置いていたが、外した。
  単語一覧の総件数（2026-11-03。§5.3）と単語詳細の読みの文字数（2026-11-04。§5.4）は、トップの数字と同じ墨の 800 に替えた。
  面の性格を表す数は、いまはどれもその墨の 800 で立てる（レールの `.page-header__count`）。
- **線画は五十音円環（`.ring-art` / `shared/_kana_ring_art`、`KanaRing`）の 1 種類だけ**。1 語の読みを、円（viewBox 200・中心 100・外周半径 82）の上に一筆書きにした図で、
  新しい図形を足さない（単語一覧の 0 件の札の溶けた顔はアイコンで、図には数えない。§5.0）。
  - ホーム最上部の印・今日の一語・単語詳細のレール・共有カードで使う（単語一覧のレールにも置いていたが、2026-11-05 に外した。§5.3）。
    どの置き場所にも説明（キャプション）を添えない（2026-11-03 オーナー判断「円環の説明は要らない」。単語詳細のレールもそれを引き継いだ。§5.2〜§5.4）。
  - 並んだ数値を同じ円の上の一筆書きにした**放射図**をジャンル一覧のレールに置いていたが、2026-11-05 に外した（§5.11・§12）。
  **実データから生まれる図**なので、装飾でありながら嘘がない。塗りを持たず、折れ線は `--text-subtle` の 1.2px、円は `--border-strong` の 1px で描く
  （ページの扉に置くホームの印は墨で描く。下の印の項）。
- **比べられる棒（`.genre-hub__bar`）**: 並んだ数値（ジャンルごとの公開語義数など）が比較できないときだけ、
  **72×2px の細い横棒**を数値の左に添える。トラックは `--border-strong`、塗りは `--text-subtle`。
  519px 以下は 48px に縮め、名前の幅に回す（比べるのは棒どうしの長さの比なので、縮めても読み方は変わらない。72px のままだと 320px 幅で大分類の名前が 1 行 5 字ほどに痩せた）。
- **ページ最上部の印（`.ring-art--mark`）**: ホームの一番上に、**サイト名の読み「ナガイコトバノデータベース」の円環**を 172px で 1 つだけ置く。
  手本（しずかなインターネット）が最上部に 81×101px のロゴの図を置くのと同じ役割（実測）。**キャプションは付けない**。
  - 描いているのは**サイト名そのもの**なので、ロゴでありながら他の円環（語の読み）とまったく同じ規則で生成される。**別途ロゴ画像を持たない**。
  - **中央に置く**（帯の左端に合わせない）。印だけは看板ではなく扉なので、ページの入口に据わって見えるほうを採る。
  - **線は墨（`--text`）で強める**: 折れ線は墨の 1.5px、円は図の灰（`--chart`）の 1px、始点は墨、外周の英字は `--text-muted`
    （2026-11-03 オーナー判断）。見出しと押せる部品の枠が墨の 800・1px になったぶん、ほかの円環と同じ淡い 1.2px の線では
    看板に飲まれて主張が弱くなった。墨の 2px（円も 1.25px に太らせる）は実装してみると重すぎ、216px への拡大も採らなかった。
    大きさと配置は変えない。今日の一語・単語詳細の円環は元の線のまま。
  - **印に描く読みは「ナガイコトバノデータベース」から変えない**（2026-09-04 オーナー判断。§12）。
    交差が 9 本と少なく密度が物足りない件は、4 つの案を実寸で試作したうえで**すべて見送った**（記録は [`history/design.md`](history/design.md)）。
  - **「ナ」から「ス」へ一筆書きで描かれる**。現在の実装値は
    **円が浮かぶ 1.0s（遅延 0.17s）→ 始点が点く 0.58s（遅延 0.75s）→ 線を 4.65s で引く（遅延 0.92s）**で、
    アニメーションが終わるのは開始から**約 5.6s**（線が端まで届くのは約 4.9s。下記）。1 度だけで止まり、繰り返さない。
    読みを 1 字ずつ辿る線なので**速度は変えず一定（`linear`）で引く**。ペンの動きに合わせるためで、`ease` を掛けると図形の演出になってしまう。
    **この速さが確定値**（2026-09-16 オーナー判断。`issues.md` 確定事項 27。速める指示が適用されていなかった経緯は [`history/design.md`](history/design.md)）。
    - 実装は `stroke-dasharray` / `stroke-dashoffset` の CSS アニメーションだけ。**線の全長はサーバ側で出す**（`KanaRing.stroke_length` → `--ring-length`）ので、
      長さを測るためだけの JS（`getTotalLength()`）を持たない。Chromium と WebKit の双方で実測して確認した。
    - 線の太さを保つ指定（`vector-effect: non-scaling-stroke`）があると、viewBox の単位で渡した破線が画面の上の長さで数えられる。
      そのため 172px の印では、線は 4.65s の 172/200（**約 4.0s**）で端まで届き、残りの約 0.65s は見た目が変わらない
      （2026-11-04 に Chromium と WebKit で実測）。確定しているのはいまの見え方なので、値は変えない。**印の大きさを変えると、引く速さも変わる**。
    - **`prefers-reduced-motion: reduce` では完成形をそのまま出す**（アニメーション定義ごと `no-preference` の中に置く）。
    - **ほかの円環（今日の一語・単語詳細のレール）は、読み込みでは動かさない**。読み込みで動くのはページに 1 つだけ。
      触れたときにだけ、始点から読みを 1 度なぞり直す（遊びの動き。§4。印と同じく `--ring-length` の破線をずらす）。
  - **外周を英字が回る（`.ring-art__arc` / `.ring-art__orbit`）**: 標識「NAGAI KOTOBA DATABASE」を、円の外側の弧（ベースライン半径 90）に沿わせて
    **80 秒で 1 周**させ続ける。`<textPath>` を「下から時計回りに 1 周するパス」の 50%（＝真上）に中央揃えで載せる。
    - **回転の中心は円環の中心**（`--ring-center` = `KanaRing::CENTER`）。`transform-box: fill-box` にすると、文字が弧の上側にあるぶん
      外形の重心が上へずれて回転が振れる（実測で 5 単位ずれた）。`transform-box: view-box` ＋ 中心指定にすること。
    - この標識は**看板から移したもの**で、`.masthead` 側には置かない（同じ英字を 2 箇所に出さない）。`EST. 2026 / JAPAN` は看板からは外し、フッター最下段だけに残す。
    - **弧のラベルは 1 ページに 1 つだけ**（`<textPath>` が参照する id を固定で持つため）。
- **線画は 1 ページに 1 枚 …… ただしホームの印だけは別枠**（ページの看板であって区画の図ではないため、「今日の一語」の円環と併存してよい）。
  図をこれ以上増やすと「実データから生まれた図」（`.ring-art` / `.genre-hub__bar`）の説得力まで飾りに見える。
- 線画に共通の作法: 実装は `viewBox` だけを持つ SVG。**色は `currentColor` か既定のクラスのみで、直書きしない**（ライト／ダークの反転が自動で付く）。
  濃さは置き場所で決める。**区画の中に置く図は `--text-subtle`〜`--text-muted`**（`--text` まで濃くすると本文より濃い線になり、絵だけが主張する）。
  **ページの扉に置くホームの印は墨（`--text`）の 1.5px**（見出しが 800 の墨で組まれた看板の上では、淡い線のほうが飲まれる。上の印の項）。
  **正規化は最小値〜最大値を 20〜100% に写す**（`BarWidth`。最大値で割ると 143〜196 が 73〜97% に潰れて差が読めず、
  「情報を運ばない印」を足しただけになる。2026-09-03 の実測で判明）。**数値は必ず併記**し、長さだけで情報を伝えない。
- いずれも**色を持たせない**。図で目を引くのは形と余白だけにする。

### 5.10 統計 §1 のワードクラウド（サイト唯一の多色）

- **サイトで多色を使うのはここだけ**（2026-09-10 オーナー指示）。ほかの図（ヒートマップ・
  ツリーマップ・遷移グラフ）は従来どおり無彩色 ＋ `--chart` で描く。**この例外を広げない。**
- 色相は 8 つ（`--cloud-1`〜`8`）。割り当ては**語そのもの**から決まる（`MorphemeCloud#palette_for` = CRC32。
  `String#hash` はプロセスごとに変わるので使わない）。収録が増えても同じ語は同じ色のまま。
- **彩度はライト 30% / ダーク 34%**、**明度は「地に対して 4.6:1 以上」** まで落としてある（実測値。§1 に値を列挙）。
- 級数は 18〜64px で、頻度の位置は**対数**で採る（線形だと大多数が下限に貼り付いて差が読めない）。
- **最頻の 1 語を `--chart` で印す方式はやめた**（全部に色が付いたので意味を成さない。
  いちばん大きい字が最頻であることは級数で分かる）。
- 詰め方・件数・配置の決まりは [`stats.md`](stats.md) の統計ページ §1 の章が正。

### 5.11 詳細検索から切り出した探し方のページ（2026-10-28）

- 詳細検索の区画のうち、**探す動機がはっきりしていて、詳細検索では手数と読む量がかさむもの**だけを 1 ページずつ切り出す。
  いまは **ジャンル（`/genres`）・エンティティ（`/entity_types`）・言語学的特徴（`/linguistic_features`）・索引（`/browse`）** の 4 つで、
  ヘッダーの「検索」プルダウンとフッターの「さがす」にこの順で並べ、プルダウンの最後に詳細検索を置く（何についての言葉か → 読みの形 → 全条件）。
  - 切り出さなかった区画は詳細検索に残す: 品詞・語種（探す動機が弱い）、正規表現・ローマ字・文字種（書ける人向け）、母音（入力欄 1 つで済む。
    末尾一致の韻は Issue 59 で退けている）、音の成分（ランキングで足りる）。**区画ごとにページを増やさない。**
  - どのページも、選んだら条件付きの `/words` へ進むだけで、ページ自身は結果を出さない。件数は `PublishedSenseCounts`（1 時間のキャッシュ）で、
    **公開語義の無い選択肢は出さない**（選んでも空の一覧になる。`/genres` と同じ）。
  - ページの頭はどれもレールの無い `.page-header`（h1 とリード。下に章の罫）。線画の置き場所（§5.9）は増やさない。
    ジャンルだけはレールに分類の総数と放射図を立てていたが、2026-11-05 に外してほかの探し方のページとそろえた
    （オーナー判断「他の検索項目との整合性を取ってあげる方が綺麗な収まり」。分類の総数はページに出さない。統計で見られる。§12）。
- **どのページも、トップ・一覧と同じ墨の枠の札（`.panel`）に収める**（2026-11-04 オーナー指示「次は検索周りのデザインをお願いします」）。
  英字の標識（`GENRES`・`ENTITY TYPES`・`LINGUISTIC FEATURES`・`KANA INDEX`・`SEARCH` と、2 行目の数）は置かない（§5.8）。
  - 札の頭はアイコンと日本語の見出し（ランキングの板・統計の章と同じ組み。`.panel__title`）。アイコンはヘッダーの「検索」の一覧と同じ
    （ジャンル `tag`・エンティティ `cube`・言語学的特徴 `pen_nib`。索引は区画ごとに `grid_nine`・`ruler`、詳細検索は `funnel`）。
  - ジャンル: 頭は「大分類」と名前で絞り込む欄。中身は大分類の折り畳みの行で、札の幅いっぱいに積んで 1px の隙間で仕切る（`.genre-hub`。§3）。
    それまでは大分類ごとに淡い角丸の枠で囲み、間を空けて並べていた。行の左右の余白は札の頭の見出しと揃え、hover で `--bg-soft` に沈む。
    大分類の公開語義数は、単語一覧の文字数と同じ墨の 800 で立てる（中・小分類の数は名前に添える小さな等幅のまま）。
    大分類の名前は「・」の後ろでだけ折る（`ApplicationHelper#phrased_name`。§2。320px 幅で「演劇・スポー／ツ」と語の途中で折れた）。
    開いた中の「◯◯ 全体を見る」は、札の頭の「一覧へ →」と同じ小さいボタン（`.btn--sm`）にする。
  - エンティティ: 頭は「エンティティ」と名前で絞り込む欄。中身（`.panel__body`）に件数つきのタグを折り返して並べる。
  - 言語学的特徴: 頭は「言語学的特徴」。中身は特徴の行で、札の幅いっぱいに積んで 1px の隙間で仕切る（`.feature-hub`）。
  - 索引: 50 音と読みの長さを 1 枚ずつ札にして、統計と同じ札の棚（`.panel-shelf`）に積む。切り替えのボタンは統計の読みの長さの章と同じく札の中身の頭に置く。
  - 詳細検索: フォームそのものを札にする（§5.6）。
- **名前で絞り込む欄（`.list-filter`、`list_filter_controller.js`）**: ジャンルとエンティティの札の頭の右端に置く（`.hub-panel__head`）。入力の文法（細枠の角丸ボックス）に、
  ホームの検索バーと同じく先頭のアイコン（`funnel`）を入れる。`type="search"` の既定の外観（Chromium の青い消去ボタン・iOS の角丸）は外す（色はトークンだけ）。
  - 高さは札の頭のボタン（`.btn--sm`）と同じ 32px、幅は 240〜320px。767px 以下は入力の文字が 16px に上がる（iOS の自動ズーム対策）ので、
    いつも見出しの下の行に幅いっぱいで置く（見出しの横に残った幅に収めると、414px 幅で入力 204px に対して例文が 287px あり、途中で切れた。2026-11-04 実測）。
  - 例文は「絞り込む（例: アニメ、鉄道）」「絞り込む（例: 駅名、曲名）」。何の名前かは札の見出しが言うので、例文から「ジャンルを名前で」を外した
    （入力の幅 244px 以上、つまり 360px 幅以上で切れずに収まる。320px 幅では末尾が切れる。2026-11-04 実測）。読み上げ用の欄の名前（aria-label）は「ジャンルを名前で絞り込む」のまま。
  - 何も残らなかったときの一言（`shared/_list_filter_empty`）は札の中身の下に置く。
  - 欄は JS がつながってから出す（JS が無いときは欄が無いだけで、一覧はそのまま辿れる）。ひらがなはカタカナに、全角英数は半角に寄せて照らす。
  - ジャンルは**小分類と中分類の名前**に照らす（「漫画」で 漫画・コミック の小分類がまとめて残る）。**大分類の名前には照らさない**
    （「芸術・音楽・演劇・スポーツ・娯楽」のように広く、当てると配下の数百件が残るだけになる）。当たった小分類を含む大分類だけを開き、
    欄を空にしたら、絞り込みで開いたものだけを閉じ直す（人が開いたものは閉じない）。
- **索引**: 50 音（先頭の文字 / 末尾の文字）と読みの長さ（文字数 / モーラ数）を、統計 §3 と同じセグメントボタン（`.segmented`）で切り替える。

  50 音表のヒートは統計 §2 と共有の部品（`shared/_kana_heat_grid`）。モーラ数には数え方の注を添える（統計 §3 と同じ）。
- **エンティティ**: 語の多い順に、件数つきのタグ（`.entity-hub__tag`。ジャンルの小分類のタグと同じ組み）を折り返して並べる。
  エンティティは DB のマスタで増えていくので、まとまりには分けない（分け方をコードに持つと、足したものが漏れる）。
- **言語学的特徴**: 1 つの特徴 = 名前（一覧へのリンク）と件数 → **定義の 1 文** → 例（頭から `LinguisticFeaturesController::EXAMPLE_LIMIT` 件）。
  行は `gap: 1px` の隙間で仕切る（`.feature-hub`）。**用語解説の全文は載せない**: 起こらない場合やこのデータベースで付ける範囲の但し書きまで並べると、
  1280px 幅でページが 4,672px になり（定義の 1 文と例 3 件なら 3,859px。2026-10-28 実測）、探すページとして読む量が重い。全文は詳細検索の畳んだヘルプにある。

## 6. アクセシビリティ & パフォーマンス

- **コントラストは WCAG AA 以上**（最も弱い文字 `--text-subtle` でも、地・札の白・沈めた面・選択の面のどの上でも 4.5:1 以上。§1）。`:focus-visible` を消さない。アイコンのみ操作要素に `aria-label`。
- **ダブルタップでのズームは禁止、2 本指のズームは残す**（`base.css` の `html { touch-action: manipulation }`。アプリ全体。2026-11-06 オーナー指示。
  ドロワーの折り畳みのように続けて押す部品で、指が 2 度当たるたびに画面が拡大していた）。viewport の `user-scalable=no` は使わない（2 本指のズームも奪い、iOS は無視する）。
- **タップ領域**: 公開側の主な部品の高さは `.btn` 40px（`.btn--sm` 32px）、タグ・チップ約 29px、フッターのリンク約 25px で、

  （44px は AAA の値。部品を 44px に揃えるかは未決で、揃えると余白と密度が変わる）。

| `--scrim` | `rgba(47,39,37,.35)` | `rgba(0,0,0,.6)` |

- **色はトークン以外で直書きしない**。影・幕のような非色の視覚効果も、ダークで意味が変わるならトークンにする。
- **ダークでは札の面と地が同じ色になる**（`--surface` = `--bg` = `#262120`）。札の輪郭はライトでも墨の枠が持つ（地との差 ΔRGB 5。§3）ので、
  ダークでは明るい墨（`#F2EEEC`）の枠だけで札を見せる。沈めた面（`--bg-soft`）は地より暗く（差 ΔRGB 20）、選択の面（`--bg-tint`）は地より明るい側に置く。
- **`--bg-tint`（選択中）はダークでは `--surface` より明るい側に置く**。暗い側に寄せると面の上で沈み、選択状態がほぼ見えなくなる（Issue 93）。
  いまは `#3C3533` で、`--surface` との差 ΔRGB 22・`--text-subtle` を載せて 5.0:1（下限の 19 と 4.5:1 は `test/assets/design_tokens_test.rb` が測る）。
  2026-11-03 より前の青みの値で詰めた経緯は [`history/design.md`](history/design.md)。
- トークンを 1 つ足したら、`@media (prefers-color-scheme: dark)` 側と `:root[data-theme="dark"]` 側の**両ブロックに参照を追記する**。
- **`color-mix(..., transparent)` の塗りは両テーマで意味が変わる**（下に透ける地が反転するため）。濃さの上限を 45% に抑え、上に載る文字を `--text` にしておけば両方で読める。

### 9.2 切り替え

- **既定は OS 設定に追従**。ヘッダーのトグルを押したときだけ `html[data-theme="light"|"dark"]` が上書きし、`localStorage.theme` に残る。
- 初回描画のちらつきを防ぐため、**復元だけは `head` 内のインラインスクリプト**で行う。`theme-color` も CSS のトークンから読む。同期は `theme_controller.js`。
- **「自動に戻す」UI は置かない**（2 状態のトグルのみ）。JS 無効時は `noscript` でトグルを隠す。
- `color-scheme` を併せて切り替え、フォームコントロール・スクロールバーもブラウザ側で追従させる。
- **CSS だけで追従できない描画**（統計ページの Plotly など）は `theme:change` イベントを購読して色を差し替える。**その色も `getComputedStyle` で CSS トークンから読む**。

### 9.3 トグルの UI

- `role="switch"` ＋ `aria-checked` を同期し、`aria-label` は「ダークモード」。

### 10.1.3 共通ナビとダッシュボード（2026-09-26 オーナー指示。2026-11-05 に公開側の部品で作り直した）

「左端の『管理』がクリックできそう」「上下中央揃えに」「『公開サイトへ →』は不要（サイトタイトルで飛べる）」
「並び順を 単語の登録 → アノテーション → 登録予定単語 → 単語の管理 → タグ管理 → リクエスト に」

- **作業の並びは `AdminHelper#admin_sections` だけで持つ**。共通ナビ（ダッシュボードに続けて並べる）とダッシュボードのカードが、

## 11. CSS のクラス名の付け方

既存の節番号を変えないよう、末尾に足した節（2026-10-03）。

- **ブロックの根は、CSS が無くても DOM の目印として付けてよい**（例: `.word-cloud`・`.vowel-graph-panel`）。
- **要素・修飾子は、CSS かフック（JS・テスト）の用途があるときだけ付ける**。用途の無い要素名は、書きかけと
  区別できないので残さない。
- **補間で組み立てる修飾子**（`cand-status--<%= status %>` など）のうち、既定の見た目に任せる値（CSS を持たない値。
  `--keep`・`--normal` など）は、そのブロックの CSS に一行で列挙する（書き忘れと見分けるため）。
- **見た目用のクラスを JS・テストも参照している箇所**は、CSS 側に「JS（〜_controller.js）・テストも参照」と注記する。
  改名・削除で黙って壊れるのを防ぐ。新しく JS のフックを足すときは、Stimulus の target か data 属性を使う。
  `js-` 接頭辞のクラスは既存の注釈コンソールにだけ残し、増やさない（`js-` が付いていても JS が使うとは限らない）。
