### [A05-1] §8 のリード文は「実例の下線」と書いているが、実装は下線ではなく淡い面のハイライト

- リスク: 低 ／ 外部振る舞いへの影響: あり（公開ページの説明文が変わる）

### [A05-4] 母音遷移の上限「15 拍」と線の最大幅「3.2」が、それぞれ別の場所に直書きされている
- 観点: B ／ 確度: 確認済み
- 根拠:
  - 層の数: `SiteStatistics::TRANSITION_MAX_POSITIONS = 15`（site_statistics.rb:30）。
  - 検索の上限: `WordSenseSearch::VOWEL_TRANSITION_FORMAT = /\A(\d{1,2})-([aiueo]{2,15})\z/`（word_sense_search.rb:7）。コメント（:6）自身が「上限は統計 §7 のグラフの層数」と書いているのに、定数を参照していない。
  - 線の最大幅 3.2:
    - `StatsHelper::GRAPH_MAX_EDGE = 3.2`（stats_helper.rb:171）
    - 選んだ線の `stroke-width: 3.2`（components.css:4504）
    - JS のコメント「最も太くても 3.2px」（vowel_graph_controller.js:6）
  - 境界値のテストは 16 拍（word_sense_search_test.rb:318）と位置 99（:319）だけ。15 拍と位置 30 が通ること、位置 31 が落ちることは固定されていない。
- 問題:
  - `TRANSITION_MAX_POSITIONS` を 16 以上に上げると、図から出る 16 拍以上の鎖のリンクは条件ごと黙って捨てられる。リンク先は条件なしの /words になる。テストは図とリンクの往復を見ていないので気づけない。JS がこの上限を知らない件は J-06 で既知。ここで挙げるのは Ruby の 2 つの定数の側。
  - 3.2 を片方だけ変えると、「選んだ線が最太の線より細い」状態になる。
- 提案:
  - 正規表現の上限を `SiteStatistics::TRANSITION_MAX_POSITIONS` から組む（`/\A(\d{1,2})-([aiueo]{2,#{…}})\z/`）。値は同じなので、振る舞いは変わらない。
  - CSS の 3.2 は、helper の定数を `--edge-max` としてビューから渡すか、少なくとも両方に「GRAPH_MAX_EDGE と同じ値」と注記する。
