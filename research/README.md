# research/ — Claude Code のオフライン調査の作業ディレクトリ

`/harvest`・`/expand`・`/notation`・`/reading`・`/annotation` の5つのカスタムコマンド（それぞれ
`.claude/skills/word-*-research` スキルを起動する）が、**入力ファイルを読んで出力ファイルを書き出す**
という形で動く。その入出力を置く場所。

6つ目の `/reannotation`（1語の再調査）だけは、**JSON を会話に貼って起動し、結果もチャットに返す**
（スマートフォンから回すため）。ファイルは補助的に `outputs/reannotation.json` へ書くだけ。

`inputs/` と `outputs/` の中身は実行のたびに上書きされる作業ファイルなので、`.gitignore`
で除外している（ディレクトリだけ `.keep` で残す）。ローカルの状態ファイルも同様に除外:
`harvest-seen.txt`（/harvest が過去に提案した語の累積リスト）・`harvest-cron.log`（定期実行のログ）・
`.tmp-*`（途中経過の置き場）。**このディレクトリで git に載せるのは本 README だけ**という前提なので、
新しく作業ファイルを置くときは `.tmp-` で始まる名前にするか、`.gitignore` に足すこと。

## ファイルの対応

| コマンド | 入力 | 出力 |
| --- | --- | --- |
| `/harvest` | （外部サイトを巡回。入力ファイルなし） | `outputs/harvest/<実行日>-<セット>.txt` |
| `/expand` | `inputs/expansion.txt` | `outputs/expansion.txt`（人が読む版）＋ `outputs/expansion.json`（取り込み用） |
| `/notation` | `inputs/notation.txt` | `outputs/notation.txt`（人が読む版）＋ `outputs/notation.json`（取り込み用） |
| `/reading` | `inputs/reading.txt` | `outputs/reading.json` |
| `/annotation` | `inputs/annotation.json` | `outputs/annotation.json` |
| `/reannotation` | （会話に貼る再調査用JSON。無ければ `inputs/reannotation.json`） | チャットに提案JSON（＋`outputs/reannotation.json`） |
| `/features` | `inputs/features.json` | `outputs/features.json` |

いずれも引数で入力パスを渡せば、上の既定パス以外も読める。

## 使う順番（候補収集 → 前処理 → 登録 → アノテーション）

登録前の語が「次に何を待っているか」は、ファイルではなく**管理画面「登録予定単語」（`/admin/candidates`）**の
ステータスで管理する。ファイルは実行のたびに上書きしてよい。スキルに渡すのは各段の画面の「コピー」、
スキルの結果は同じ画面の「結果を取り込む」に貼る（語は書き出し時の ID `#123` で引くので、表記が変わっても崩れない）。

```
仕分け → 拡張（/expand）→ 表記（/notation）→ 登録待ち（/reading → 一括登録）→ 登録済み
（脇に外す: 保留 / 重複 / 不要。不要にした語も消さずに残り、同じ語の再流入を防ぐ）
```

仕分けと表記の確認では、語ごとに処理（拡張 / 採用 / 保留 / 除外）を選んで**一度に確定**する。
処理は最初から選んである（追加した語は拡張、重複の疑いがある語は除外、立項に疑義がある語は保留、それ以外は採用）ので、
選び直すのは例外の語だけでよい。まとめて変えるときは、行を押して選び（Shift+クリック・左端をなぞると範囲、
系統の見出しの「この系統を選ぶ」で系統ごと）、下端のバーで処理を押す。キーボードでは ↑↓ か Enter で行を移り、
`E`（拡張）`A`（採用）`H`（保留）`X`（除外）で選ぶと次の行へ進む（選んでいる行があれば、その行すべてに効く）。
`Space` で行を選び、`Shift+↑↓` で範囲を広げ、`Esc` で選択を外す。`Ctrl+Enter` で確定する。

-1. **収穫（任意・定期実行向け）**: ニュースサイトなど更新頻度の高いサイトを巡回して、
   新しい候補語を外から拾う。`/harvest`（セットを指定するなら `/harvest 朝` `/harvest 夕`、
   系統を絞るなら `/harvest 美術` 等）。
   ソースは**朝セット**（エンタメ / ニュース / IT）と**夕セット**（スポーツ / 科学 / 学術 / 美術 /
   書籍 / ファッション）に分かれ、ジャンルが重ならないようにしてある。
   `outputs/harvest/<実行日>-<セット>.txt` の上部に候補語リストが並ぶので、目視で確認してから仕分けの画面に貼る。
   出力は日付＋セットごとに残る（確認前に次の実行が走っても流れない。取り込み済みの古い日付は適宜消してよい）。
   過去に提案済みの語は `harvest-seen.txt` で自動的に除外されるので、毎朝・毎夕の定期実行に耐える。
   cron で **7:17（朝セット）と 16:45（夕セット）**の1日2回動かしている。
0. **仕分け（ブラウザ）**: 仕分けの画面の「語を追加する」に1行1語で貼る。語ごとに **拡張**（`/expand` で
   同じ系統の語を集める）・**採用**（表記へ進める）・**保留**（あとで決める）・**除外**（入れない）を選んで確定する。
   追加した語には最初から拡張が選んであるので、拡張しない語だけを採用などに選び直す。
   同じ系統の語（例: 泥門デビルバッツと王城ホワイトナイツ）は1つだけ拡張に回すと、調査が重ならず `/expand` の負荷も抑えられる。
   収録済みの語・別表記・ほかの登録予定単語と表層形が粗く一致した語（かなの種類・全角半角・空白・中黒・記号の違いは無視）は、
   最初から除外が選んである。拡張を選んだ語があれば拡張の画面へ、採用だけなら表記の画面へ進む。
1. **拡張（ローカル）**: 拡張の画面で「コピー」した内容を `inputs/expansion.txt` に保存して `/expand`。
   一度に渡す語数を指定できる（既定 30 語）。Claude Code の利用上限に当たらないよう、数十語ずつ
   「コピー → `/expand` → 取り込む」を繰り返す（取り込んだ語は拡張待ちから抜けるので、次に書き出すと続きの語が出る）。
   上位概念（作品・アーティスト等）を突き止め、読み 10 文字以上の語が見込める**収集軸を 1 つ選んで**集める
   （泥門デビルバッツ → アイシールド21 の他のチーム名。軸は種語の軸とは限らない）。軸を指定したいときは引数で渡す（`/expand キャラクター名`）。
   `outputs/expansion.json` を同じ画面に貼ると、元の語と集めた語が**仕分けに系統ごとに並ぶ**（拡張を見送った元の語も戻る）。
   要らない語を除外にして確定する（系統ごと外すなら、見出しの「この系統を選ぶ」→ 下端のバーの「除外」）。採用した語は表記待ちになる。
2. **表記（ローカル）**: 表記の画面で「コピー」した内容を `inputs/notation.txt` に保存して `/notation`。
   `outputs/notation.json` を同じ画面に貼ると表記が置き換わり、下の「確かめる」に並ぶ（立項スコア2以下の語は保留、
   表記をそろえたら収録済みの語などと重なった語は除外を、最初から選んである。分割案があった語は不要になり、
   分割後の語が仕分けに入る）。確かめて確定すると、採用した語が登録待ちになる。
3. **読みと登録（いつもの一括登録）**: 登録待ちの画面で「コピー」した内容を `inputs/reading.txt` に保存して `/reading`。
   「一括登録へ進む」を押すと、登録待ちの語を入れた一括登録の step2（読みの確認）が開くので、`outputs/reading.json` を
   「調査結果（JSON）を反映」欄に貼って MeCab の暫定読みと突き合わせ、step3（重複チェック）を経て登録する。
   登録された語は自動で「登録済み」になる。
4. **注釈**: 管理画面の「調査用データの書き出し」で得た JSON を `inputs/annotation.json` に保存し、
   `/annotation`。`outputs/annotation.json` を「提案 JSON の取り込み」に貼ると DB に下書きとして入り、
   アノテーション・コンソールで人間が承認する。
5. **再注釈（1語ずつ・随時）**: 4 の承認作業中に「この注釈は微妙だ」と思ったら、その語のコンソール
   画面（`/admin/annotations/:id`）の「再調査用JSON →」でコピーし、`/reannotation` の後ろに貼って起動する。
   調べ直す項目（意味・ジャンル・エンティティ・品詞・語種・言語学的特徴・別表記・立項スコア）を
   選択肢で聞かれるので選ぶと、その項目だけを調べ直した提案JSONがチャットに返る。それを
   「提案 JSON の取り込み」に貼ると下書きが上書きされ、コンソールで承認し直せる。
   スマートフォンの Claude アプリからも同じ流れで回せる。
6. **特徴の点検（特徴の新設・基準の見直しのあと）**: 管理画面「調査データ」→「言語学的特徴の点検」で、点検する特徴
   （例: 方言）を選んで公開済みの語を書き出し、`inputs/features.json` に保存して `/features`。足す・外すの変更が
   `outputs/features.json` に返るので、同じ画面の「点検結果の取り込み」に貼り、1 行ずつ確かめて選んだ行だけを適用する。
   提案キューは通らず、意味・ジャンル・注釈状態には触れない。手順の正はスキル（`.claude/skills/word-feature-audit/SKILL.md`）。

## 自動実行（`bin/rails research:auto`。Issue 112）

`inputs/seeds.txt` の種語を、上の 1〜3（拡張 → 表記 → 読み）に人の手を挟まずに通し、一括登録に貼る状態まで進める。
**ローカルで完結し、本番には書き込まない**（本番の「登録予定単語」の画面も通さない）。一括登録・提案の取り込み・承認は人が行う。
規則の正は `ResearchPipeline`（起動・期限・種語）と `ResearchRun`（段とふるい）。

```
seeds.txt ─▶ /expand ─[コード]─▶ /notation ─[コード]─▶ /reading ─[コード]─▶ register.txt ＋ reading.json
                                                                            │ ここから人
                                       一括登録 step1 に register.txt、step2 に reading.json → step3 → 登録
```

- **段の間のふるい（コード）**: 確実なものだけを通し、ほかは却下する。確信度は high だけ、立項スコアは満点だけ、分割案のある語・
  読みが揺れる語・読みが基準に届かない語（`ReadingLengthCheck`。アプリと同じ数え方）は却下。重複は、表層形を畳んだ完全一致と
  読みの Levenshtein（一括登録 step3 と同じしきい値）で、公開語の写し・台帳・同じ run の中と照合する（読みの似た兄弟の語も落ちる）。
- **起動**: cron で動かす。新しい run は前回から 2 日経っていれば始め（日付で比べる）、途中で失敗した run は次の起動で続きから進める。
  同じ段で 3 回失敗したら止める。起動の時刻を逃しても、次に cron が動いたときに追いつく。
- **注釈**: 管理画面「調査用データの書き出し」を `auto/inbox/annotation.json` に保存しておくと、次の起動で `/annotation` に回し、
  `auto/annotation/<日時>/annotation.json` に提案 JSON が出る。それを「提案 JSON の取り込み」に貼る。
- **自動実行の Claude には Bash を渡さない**（文字数と重複はコードが見る）。公開語の写し（百万字を超える）は Read も禁じ、AI には読ませない。

置き場所はすべて `auto/`（git の外）:

| パス | 中身 |
| --- | --- |
| `auto/runs/<日時>/` | run 1 回ぶん。`summary.md`（件数と却下の内訳）・`rejected.tsv`（却下した語と理由）・`register.txt`・`reading.json`・段ごとの入出力 |
| `auto/ledger.tsv` | 台帳。使った種語と、却下した語・登録用に出した語（次の run の照合の相手。消すと同じ語をまた調べる） |
| `auto/corpus/llms-full.txt` | 公開語の写し。新しい run の前に、司令塔が公開側から条件付きで取り直す（更新が無ければ転送しない） |
| `auto/inbox/annotation.json` | 人が置く注釈の書き出し（拾ったら `auto/annotation/<日時>/` へ移す） |
| `auto/auto.log` | cron の出力 |

一括登録に貼り終えた run は、ディレクトリごと消すか残すかを自由に決めてよい（台帳に記録済み）。

crontab（新しい run は午前 3 時に始めたいので 3 時に起動し、逃したときの追いつき用に 12 時と 20 時にも起動する。期限前なら何もせずに終わる）:

```
0 3,12,20 * * * cd <リポジトリ> && PATH=<rbenv の shims>:<claude のあるディレクトリ>:/usr/bin:/bin bin/rails research:auto >> research/auto/auto.log 2>&1
```

判断基準のうち、収録範囲・立項の4原則と立項スコア・表記・読み・知名度・人物語の分類・確信度は
[`docs/annotation-guidelines.md`](../docs/annotation-guidelines.md) が正。語種・ジャンル・エンティティ・
言語学的特徴の付け方と意味の文体は注釈スキル（`.claude/skills/word-annotation-research/SKILL.md`）が正で、
言語学的特徴の定義は用語解説（`config/linguistic_features_glossary.yml`）が正。

## 共通の約束

- **でっち上げ厳禁**。記憶で語や読みを並べず、必ず WebSearch / WebFetch で裏を取り、
  確認できた分だけを出す。確信が持てないものは `confidence` を下げて候補を併記する。
- **アプリの実行時には LLM も外部 API も呼ばない**。調査はすべてこのオフラインの流れに閉じ、
  結果だけを人間が承認して DB に入れる（`annotated_at` を立てるのは人間だけ）。
- **MeCab の読みは `/reading` の入力に含めない**（追認バイアスを避けるため）。突き合わせは
  一括登録 step2 の画面で行う。
